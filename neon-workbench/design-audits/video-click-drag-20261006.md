# 视频画面点击与节点拖动

日期：2026-10-06

## 交互契约

- 点击中央或底部播放按钮开始播放。
- 播放中单击视频画面暂停；该单击不会启动节点拖动。
- 暂停时按住画面拖动节点，拖动结束保持暂停。
- 播放中的画面拖动不改变播放状态；移开后回到原位仍视为拖动。
- 进度、播放、全屏按钮继续使用各自的控件事件，不触发画面单击逻辑。

播放中画面承担暂停操作，拖动节点须先暂停。这让暂停与移动有明确边界，避免拖动误切换播放状态。没有改变 Neon/Flora 的颜色、壳体、图标和控件尺寸。

## 实现与验证

原暂停事件绑在 `.canvas-video-preview`，但该元素在 Flora 视频节点中设置了 pointer-events:none，实际点击命中媒体壳体。现将事件绑定到可见媒体壳体，并用 8px 屏幕移动阈值区分单击和拖动；播放时截断画布拖动事件，暂停时交由原画布引擎拖动。

- 新增回归先失败于“播放中单击视频画面应暂停”，修复后通过。
- `video-node-regression.cjs` 验证播放按钮、单击暂停、暂停拖动、进度条、全屏和选中工具栏，无 pageerror。
- `video-seek-host-regression.cjs` 使用真实宿主画布引擎与实际 MP4，在 390、768、1440、1728 宽度及 0.5、1、1.75 缩放下验证，共 37 组进度/画面交互记录；另有键盘进度及全屏单击暂停断言。
- `npm run build` 通过；经 `deploy.mjs` 备份部署，规范源与运行时文件哈希一致。
- 使用 `AI_OS_TEST_URL=http://127.0.0.1:3188` 完成部署后验收；3199 当前属于另一份项目，不能用作本次运行入口。验收脚本现支持显式指定测试入口。

业务 API 与身份使用隔离模拟，未写入用户真实画布。真实登录下的原视频仍需用户体验确认。Better Design 本轮读取了点击/拖动 UX 原则，未声称取得动态视觉审查通过或最终回执。

刷新应用页面后加载新版本前端脚本；已加载的旧页面不会自动更换事件监听器。
