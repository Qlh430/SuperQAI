# Neon 无限画布与节点 Better Design 审查

日期：2026-10-03  
审查对象：Neon 独立工作台的无限画布、统一节点壳体、节点工具栏、连接端口和节点输入区域。

## 本次审查范围

本次把“所有节点和画布必须符合 Neon”具体化为七个审查面：

1. 画布基础层：背景、网格、缩放、平移、画布工具栏和画布边界。
2. 统一节点系统：标题带、400×400 内容壳体、16px 外圆角、透明内部内容区、8px 内边距和 16px 组间距。
3. 节点类型覆盖：文本、便签、图片生成、视频生成、素材、素材合集、Midjourney，以及同一 Flora 壳体可承载的扩展节点。
4. 统一交互：悬停、选中、聚焦、连接中、运行中、成功、失败、空态和参数面板打开状态。
5. 统一控件：节点工具栏、运行按钮、输入端口、输出端口、删除、模型和参数入口。
6. 响应式和缩放：390、768、1440、1728 宽度，以及画布缩放后的命中区域和不溢出。
7. Neon 可访问性：中文可理解性、键盘焦点、按钮名称、输入标签、图片替代文本和颜色之外的状态提示。

## 已确认的统一结构

在一次真实画布 DOM 采集中，24 个节点覆盖 6 种节点类型，并且每个节点都存在以下统一结构：

- `.flora-node-shell`
- `.flora-node-card`
- `.flora-node-content`
- `.flora-node-toolbar`
- `.flora-node-port-layer`
- `.flora-node-actions`

标题 `.flora-node-label` 是壳体外的同级标题带，符合“标题不计入 400×400 壳体”的约定。旧的 `.canvas-node-bar`、`.canvas-node-footer`、`.canvas-node-actions` 等兼容层仍保留在 DOM 供数据和行为桥接使用，但当前 CSS 将其从可见布局中移除，避免出现第二套标题、底栏或工具栏。

当前可见壳体的计算样式符合已确定的 Neon 基线：外壳 16px 圆角，普通卡片使用 Neon 深色表面和细边框，内部内容层透明，内容组使用 16px 间距，工具栏使用独立的深色浮层和 12px 圆角。

## Better Design 结果

### 间距审查

Better Design `inspect-spacing` 已在 847px 真实渲染状态完成一次测量，结果为 **70/100**，发现 6 个 moderate 级触控尺寸问题：工具栏高度约 43.84px，连接端口层约 42.48px，均略低于 44px 建议值。

随后针对真实交互元素复核，发现两类更严重的问题：

- “运行节点”在画布缩放 11% 的实际渲染尺寸约为 4.46×4.46px。
- “结果输出，拖动连接”的可见按钮约为 2.97×2.97px；端口扩展点击区域约为 22.97×22.97px。

这对应 Better Design 的 `spacing/touch-target` serious finding。原因是画布缩放会把节点内的操作按钮一并缩小，而工具栏之前有逆缩放补偿，底部运行按钮和端口没有完整采用同一策略。

已完成的修复：

- 工具栏图标保持 32px 视觉尺寸，同时通过按钮内部扩展命中层提供 44px 交互范围，避免工具栏高度被撑大。
- 运行按钮改为至少 44px，并使用画布逆缩放补偿，保持缩放时可操作。
- 连接端口保留 Flora 的圆形加号视觉，并使用逆缩放补偿；透明命中层覆盖端口周边，保持拖动连接可用。
- 对未包裹可见 `<label>` 的节点输入文本域补充 `aria-label="节点输入"`，不再依赖会消失的 placeholder 作为名称。

### 文案理解审查

Better Design `check-comprehension` 对画布工具栏的初始动作集合给出 serious 提示：画布同时暴露 Agent、资产库、新建画布、复位、整理、清空 6 个动作，15 秒内没有单一明显的下一步。节点工具栏的“运行节点、打开节点工具、删除节点、连接输入、连接输出”也超过单一下一步的建议。

这不是节点壳体样式问题，而是信息架构问题。建议 Neon 统一系统将动作分成三层：

- P0：新建画布、运行节点、连接端口。
- P1：打开参数、选择模型、资产操作。
- P2：整理、复位、删除、批处理和高级工具。

视觉上仍可保持 Flora 的悬浮工具栏，但默认只显示 P0/P1；P2 放入“更多工具”菜单，避免每个节点同时展开过多等权动作。

## 当前不合格或待补证项

1. **Better Design 的全宽度间距审查还未完成。** 本轮已完成 847px 状态，但工具要求还需要 390、1440、1728 三个宽度的第二次采集。当前不能宣称“全宽度通过”。
2. **最终视觉审查未通过。** Better Design 的规则明确：规则读取、源代码检查和间距分数都不能代替同内容、同状态的渲染对比；目前没有生成一份可复核的 before/after 同状态截图集，也没有公共 HTTPS 视觉审查回执。
3. **画布缩放语义需要单独确认。** 44px 是触控建议；无限画布在极低缩放下允许节点视觉缩小，但必须保证命中区域和键盘操作可用。修复后应在 11%、25%、50%、100% 四档实测，不应只看 100% 的截图。
4. **节点状态矩阵仍需逐项验收。** 当前 DOM 已有 hover、focus-within、selected、connecting、参数面板和运行状态钩子，但还需要对每种节点逐项捕获截图，确认状态环、工具栏、端口和参数面板没有重叠。

## 工程验证

- `npm run build`：通过。
- `node deploy.mjs`：通过，已通过 Neon 独立工作台部署脚本部署。
- `node acceptance.cjs`：通过；`errors=[]`、`overflow=[]`、48 张验收截图。
- `node flora-toolbar-regression.cjs`：通过，200/200；覆盖 390、768、1440、1728，5 种节点，5 档缩放，悬停和选中状态。
- `node design-fixes-regression.cjs`：通过，10 组中文错误、状态、焦点和移动端断言均通过。

## 结论

结构层已经统一到 Flora/Neon 节点系统，旧节点壳体没有继续作为可见第二套组件存在。当前可以确认“统一壳体、统一工具栏、统一端口层、统一内容层”的实现方向正确；本轮修复补齐了缩放下的主要交互命中问题和输入名称问题。

Neon 的最终合格结论需要补齐 390、1440、1728 的 Better Design 间距采集，以及同内容同状态的视觉对比。完成这两项后，才能给出正式的全画布通过结论。
