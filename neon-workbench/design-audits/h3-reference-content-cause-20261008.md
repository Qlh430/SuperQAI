# H3 生成内容偏离参考图：原因调查

用户本次只要求查找原因；本轮未修改或部署生产代码，未重新生成视频。

## 确定证据

- 实际 ComfyUI 任务 946da3d3-2a6f-4d76-a906-17cb274d9a05：H3 390 的 prompt 是“香蕉被人拿起剥开”，文字已正确传递，sampler 392 steps=8；整个实际提交图没有 LoadImage/LoadVideo/LoadAudio，H3 输入没有 ref_images 引用。已连接香蕉图片没有进入最终推理图。
- 后端 minimax-h3-workflow.js 的 normalizeMinimaxH3Request 调用 selectPromptReferences，后者仅保留提示词显式包含 <Picture N>/<Video N>/<Audio N> 的素材。无标记的输入参考数组被静默清空。
- 本地对照同一香蕉图片输入：原句 → images=0、LoadImage=0、H3 参考连接=0；改为“<Picture 1> 中的香蕉被人拿起剥开” → images=1、LoadImage=1、H3 参考连接=1。仅验证规范化与工作流准备，不请求真实推理。
- ffprobe 确认真实 MP4 10.125 秒、1056×608、24fps；ffmpeg 抽帧显示餐盘旁的人拿起类似核桃的物体，剥开后出现香蕉般内芯，与用户提供的单根香蕉参考画面不一致。诊断帧 .design/h3-content-check/contact.jpg。

## 结论与建议

可确定的应用错误是“素材区显示已连接，但最终模型并未收到图片”，发生在后端素材筛选，与上一轮完成视频回写到旧节点的问题分别独立。不能只把偏离内容归因于模型对提示词的理解。

建议已连接/已添加的参考素材默认保留进入模型；必要的 H3 引用标记由应用建立绑定，不能要求用户知道底层标记才能让素材生效。仍需保留显式引用的编号校验与素材上限。修复后的真实内容遵循效果需另行推理验收，不能用工作流构造测试声称已经生成正确动作。

只读检查真实 ComfyUI 历史及本地文件，没有改用户画布/数据库或运行中的 3199 服务。使用 ffmpeg-usage 技能执行元数据与抽帧诊断。
