# 画布节点标签实施计划

> 执行方式：在当前会话按步骤执行，沿用已确认需求。

**目标：** 所有节点支持一个分类标签，同一画布共享可编辑的标签库，保存、恢复、复制和撤销均保留标签。

**架构：** `flora-node-tags.js/css` 负责原生画布适配器的标签按钮、选择弹层与管理对话框；共享规则负责名称、颜色和默认值；宿主脚本通过现有操作队列提交节点引用及画布定义。SQLite 的画布表增加标签定义列，已有数据通过幂等迁移保留。

**技术：** 原生 DOM / Neon 语义令牌 / 现有画布操作、SQLite worker / Playwright。

**约束：** 不使用 localStorage；不覆盖已有未提交改动；参考图只借鉴交互；只通过 deploy.mjs 备份并部署；不停止 3199 服务。

1. 编写保存服务回归，确认旧服务缺少标签保存支持；补齐规则、Schema、worker 与协作事件。
2. 实现节点标签和独立管理弹窗；以宿主操作接线，合并 board.patch 字段，支持 undo/redo、复制、虚拟化及切换画布。
3. 新增浏览器回归，覆盖添加、移除、定义变更、删除确认、空库、错误、键盘和四个宽度的视觉状态。
4. 构建、部署（自动备份）、运行 acceptance.cjs 及相关回归；记录模拟接口和真实登录边界。保存服务在桌面主进程持有 worker，部署后需要完全退出并重开才能加载新 worker；前端检测旧服务并显示中文提示，不能假装保存成功。
