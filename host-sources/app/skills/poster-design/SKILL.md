# 海报设计

## 定位

先像专业设计师一样确认任务，再决定构图和生成。没有确认 brief 前，不创建海报节点，不运行付费生成。

## 第一阶段：策划和确认

1. 结合 `references/creative-brief.md` 和 `references/poster-playbook.md` 策划；春节、新年、元宵等节庆需求还参考 `references/festival-poster.md`。若宿主已在本轮提供原文，不重复读取。
2. 对照用户原话与真正的视觉附件。按附件序号明确列出产品图、不同产品及风格参考；只用本轮素材，不能拿风格图里的对象冒充产品。用户说“以此产品”且已收到产品图时，不再询问图片来源。
3. 信息足够时直接提出专业默认方案：一句话传播目标、受众/渠道、视觉母题、阅读动线、主辅层次、画幅和留白。多个方向要在场景、构图或叙事上有实质差异，只保留推荐方向的执行提示词。确实影响结果的未知项才询问，最多 5 项。
4. 用 `request_design_brief` 提交。workflow 为 poster；source_node_ids 是真实附件节点，known_context 写逐图识别、事实约束和准确文字，summary 写具体推荐方案，image_prompt 写完整可执行主视觉提示词，questions 无待决定事项则为空。等待确认，不创建节点、不提交生成。

## 第二阶段：制作

1. 确认卡使用最新稿与同一原图版本。主视觉存入一个现有图片生成节点并连接确认过的参考图，完整 Brief、主副标题和必须准确的文字另存为可编辑文字节点。
2. 图片提示词包含画幅、主体和摆放、构图与视线、色彩、光线、材质、文字安全区和禁忌。中文长文、价格、日期、二维码或排版 Logo 不交给生图模型编造。
3. 校验已保存的主视觉节点和连线。只有用户明确确认这一次付费生成才运行主视觉节点；结果跟随节点，未出图不能宣称已出图。失败时保留可编辑内容，不自动重复提交。

## 质量规则

- 主视觉只能表达一个核心主题；焦点、视线、层级、留白和品牌安全区必须明确。
- 产品海报必须保留真实产品结构、颜色、材质、配件、数量、组合关系和可见标识；角色不清时不猜。需要基于指定实物却没有可读取产品图时只请求补图；只有用户同意时才做无品牌占位。
- 节庆海报必须先区分“节日祝福”“节日促销”和“借节日氛围做产品传播”，三者构图和信息量不同。
- 春节海报不能只堆灯笼、祥云、金色和红色；视觉母题必须服务于传播目标，避免廉价拼贴和元素过载。
- 不虚构未提供的活动日期、折扣、价格、二维码、认证或合作品牌。
- 执行失败时停止，不自动重复付费任务。
