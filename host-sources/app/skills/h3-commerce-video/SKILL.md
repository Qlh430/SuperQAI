# H3 Commerce Video

从商家商品介绍和受控图片写有购买理由的带货文案、分镜及 MiniMax H3 双段提示词。中文、9:16、轻快自然；画面形式按用户请求采用人物讲解或纯商品旁白，未指定时沿用人物讲解。两种形式共用购买理由与事实取舍规则。工作流承担生成、前置帧引导、裁切与合并；交付提示词与已完成视频分别记录。

## 启动与材料收集

用户说“使用H3带货视频Skill，开始制作”、询问安装后怎么用，或要正式提示词但资料/图片未齐时，先读取[用户引导流程](references/onboarding.md)，按已选画面形式和品类收集当前缺项。纯商品旁白使用商品场景图，无需模特照。收集阶段先给资料摘要、图片要求和当前缺项；资料齐备后一次完成正文、分镜和正式包。用户明确先要文案时进入文案分支。已有内容直接使用；由Agent核验并在齐备后直接输出。用户只需提供商品信息和素材，工作流参数由配套合同确定。

已有完整资料与合格四图时直接进入制作；只要文案或分镜草案时进入下方文案分支，按实际缺口交付。

## 文案与分镜草案

每次依据本次商品资料执行[购买理由与口播写作](references/selling-copy.md)：选择购买理由及成立条件 → 连续正文 → 逐句对照资料 → 对应分镜。原始介绍可以是自然语言，直接归纳；已提供的信息不再索要。图片已提供时，实际查看并按[固定输入协议](references/assets.md)核对外观和SKU；只有文字时将画面素材标待准备。

用户只要台词、分镜或商品适配测试时，交付这个分支的实际结果。这个阶段的任务是完成可用的文案与镜头草案，按有效事实判断计划时长。资料不足就交短稿和具体缺口，图片缺项另列制作待办。来源与待办保留在说明，连续正文面向购物者。

## 正式提示词与视频

用户要求H3提示词或运行视频，并且文案进入完整方案状态后，读取[正式H3包与执行](references/production.md)，完成固定图片槽位、共享身份、六字段格式和真实工作流合同。默认四图：开场场景、商品主图、同款补充证据、关键细节或操作；图1按所选形式使用人物场景或商品场景，各槽位按品类协议验收。两图版沿用原有单独选择条件。

已有足够资料与素材时直接推进；既有授权持续有效。资料齐备后的答复直接交付可复制的两段完整提示词，或实际已保存文件的入口，再附简短说明。Agent先解决尚未完成的取舍、时长与格式问题，再给结果；素材摘要与“校验通过”本身不构成交付。正式包用 `prompt-a.txt`、`prompt-b.txt`、`package.md`、`result.json` 交付，图片冲突或内容仍为短稿时交可支持部分。用户只要文案时，制作步骤留在此分支。

事实与素材验收、文本合同检查、实际画面和声音验收分别报告。格式校验或ASR不能证明销售理由、分镜执行、口型及声音均已合格。
