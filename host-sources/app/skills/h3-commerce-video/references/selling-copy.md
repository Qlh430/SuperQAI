# 商品亮点变成购买理由

目标是写主播面向购物者说的自然销售口播：挑出本款值得考虑的特点，说明它适合怎样的需求，让对应商品镜头提供可见内容。商家介绍是事实库，口播以有依据的商品优势和使用价值组织内容，每句推进一个具体购买理由。

## 1. 选内容

先整理一张简短的内容取舍表，再写口播。按本次SKU核对事实，数量、位置、规格范围和成立条件保持原义。来源未提到某结构时，该结构仍为未知；只有实图或明确资料才能确认存在或不存在。每行包含：原始事实与来源、它回答的购买问题、必要条件、本次处理。处理分为：

- **口播**：本次最值得讲的一两项特点，以及与它直接有关的使用价值或必要条件。
- **画面/详情**：辨认商品的包装、简单使用动作、次要参数、完整操作与注意事项。
- **待补**：本次没有确认的款式、结构、效果或素材，写进制作说明。

口播入选理由必须回答“这个特点为什么让目标购物者考虑本品”。从用户需求推到本品的具体区别和直接用途，选最有依据的一两条，不按品类套固定卖点。只有说明操作步骤而没有新增选择依据的内容归入画面或详情。

取舍表要明确本次不讲什么，并在正文中实际执行。已确认的事实也可以留在详情；同一条事实一旦归入画面/详情，就由对应内容承担，不再返回口播填满时长。需要改变取舍时先重排理由与条件的预算，广告不必覆盖整张资料卡。

先将资料中的条件归入`selling_plan.condition_review`的三栏，各栏用原资料短句组成数组，未提供则为空：

- `selection`：资料中影响选型或适用判断的候选条件，包括尺码/规格体系、适配对象与范围、明确不适用项、需另配或不包含的部件。此栏保留资料供取舍，是否入口播由本次实际介绍的卖点与方案决定。
- `effect`：本次所选效果或功能主张的强度、范围和成立前提，随该主张保留。未选择的主张可连同其条件一起放入详情。
- `operation`：为正确执行操作而需要的准备、顺序和注意事项，交给镜头与使用说明。销售口播介绍能完成什么任务、带来什么有依据的便利；完整步骤只用于用户明确要求的教程。

分类后再筛选：只将省略后会使本次实际主张失真、扩大强度或适用范围的条件放进`purchase_conditions`，`source`原样复制对应资料短句，用最简自然表达随主张说清；也可以连同该主张一起舍去。未介绍的备选方案、可选配件、次要局限和一般注意事项保留在商品说明中。用户明确要求的披露按要求安排。`purchase_conditions`仅记录实际入口播的条件，可为空；资料收集完整不等于广告要逐条念完。

分类依据是“它限定本次所讲价值，还是仅影响其他选型或具体操作”。关键条件无法在时长内说清时，缩减理由范围或改选其他理由。资料没有提供的用量、频次、兼容范围和效果不能从常见用法补出。

## 2. 写完整口播

用具体的商品特点和生活场景直接说话，像主播认真帮观众挑东西。句子短、观点明确；开头与收尾从本次商品内容自然产生，可直接介绍用途、选择或搭配，不必每条都先制造顾虑、再说“就是它”。商品来源、全称、型号和证据条目放在取舍表，口播用易懂的短称呼。商家明确提供的功能按原强度表述功能，带条件的效果保留条件，不能改成自己实测过或效果保证。口播句子的主语与内容围绕商品及购买需求；出处只记录在source，不作为一句广告台词的开头。依据不足的主张移出正文，不能靠念出处绕过事实核验。

所选主张以准确的强度、范围和条件表达：帮助、可能、适用对象、限定环境等均是事实的一部分。百分比或程度词已把主张说清时，沿用这句准确表述，后文继续讲相关使用价值；重复解释同一个边界的反向补句归入说明。把特点连接到用途时只推到资料直接支持的便利，不把成分、结构、演示画面扩大成效果保证或真实试用经历。主观风味和体感保持原资料边界。

简单的拿取、涂抹、开袋、穿戴和按键交给镜头。正文讲这款商品的用途、味型、妆效、搭配或便利；专门的操作讲解留给教程需求。某个动作本身体现核心便利时，讲它减少了什么麻烦或解决什么任务，画面承担具体步骤；完整教程不挤进销售正文。数字按实际念法写，保留影响本次购买判断的关键值。有关联的功能和场景可以连贯讲，事实不足时完成一个短而完整的介绍。

先写连续正文，再分镜。约30秒口播以130–160个汉字为初始预算；英文名称、接口缩写和数字按实际发音另留时间。字数是朗读预算，不是必须填满的下限。每项理由连同必要条件一起占用预算，条件复杂时减少本次主张的数量，而不是把全部参数念快。

草案和正式包都要报告实际全文汉字数、数字/外文的预定读法及估时依据，读取[H3节奏规则](prompts.md#节奏)后再分配每镜头的发声起止与台词。先让台词能在对应时段说完，再选择切点；跨镜头延续的句子明确标出完整发声区间。整条字数合适不能代替逐镜负荷检查，不能把未分配的长句或收尾堆进剩下几秒。

## 3. 审稿后交付

逐句审稿并改完再交付。对每句记录它新增的具体信息，合并只换说法重复同一特点的句子。保留能让购物者多一个选择依据的句子；仅要求观众“结合需求、核对条件”的泛泛建议回到制作说明。结尾接着本次购买理由自然结束。

完成以下检查，写出实际结果：

1. **购买理由**：能指出主打哪一两项商品事实、对谁有什么用。主体内容围绕这些理由推进。
2. **事实与条件**：将实际台词的每项主张逐一对回原资料，检查强度、范围、数字及条件；检查它还新增了哪些来源没有的判断。所选理由涉及的关键购买条件必须能定位到具体台词。将每个体验或效果评价词单独核对，新的体感仍为待补。检查结果引用真实对应内容，而不是只写“通过”。
3. **信息推进与口吻**：第二半段提供与主打理由有关的新依据、具体用途或搭配场景。逐句指出它增加了什么购买价值；只为达到字数而补进的备选方案、注意事项、参数和同义重复移回资料说明，短稿按实际有效内容交付。来源说明、拍摄待办和操作清单归入各自说明；收尾延续本次购买价值。
4. **朗读**：复算全文、分段和逐镜汉字数及数字/外文负荷，报告实际数值。超过预算先删次要内容、压缩长称呼或重分切点，再按能讲完的内容估时；估时未核对完成时保留为待调整草案。

将检查落在实际正文上：`selling_plan.core_reasons`与`selling_plan.purchase_conditions`每项记录`source`和`dialogue_quote`，后者必须逐字摘自最终正文。回看condition_review，区分本次实际主张所需的条件与留在说明的资料；仅为前者逐项定位真实台词，后者在取舍表写明去向。operation项留在操作说明。将最终正文写入`full_script`，实际汉字数写入`script_hanzi_count`；分镜每行给出`dialogue`、`start/end`、`speech_start/speech_end`。这些记录由Agent整理，用户仍只需提供自然语言资料。

具备Python时，草案用`scripts/validate_package.py 草案.json --copy-only`，正式包用提示词指南中的命令，交付前核对脚本打印的实际字数、引文和逐镜负荷。只读或内存环境可将JSON经标准输入传入并以`-`代替文件路径。脚本检验引用是否真的在正文、字数与分镜是否一致，不判断理由是否选对、必要条件是否选全或动作物理正确；这些仍需按原资料审稿。聊天型宿主可以在交付说明列同样的实际引用与核对结果，未核对的项目保持待核对。

交付前将所有资料缺口与制作待办归入`missing_information`，`full_script`只保留实际要播出的购物者台词。分镜的对白按时序拼接后，与最终正文逐字一致；每句按正文顺序出现一次。检查结果决定交付状态：

- `ready_for_storyboard`：正文连贯、理由成立、事实对应，有效正文按轻快口播足以支撑所请求的时长；分镜仍是待准备草案。正文在该语速下只有20–25秒时进入`short_draft`，时间按实际念法估算，标点不计作发音字符。
- `short_draft`：删去重复和次要信息后，只有较短的有效介绍。交付短稿、估计时长和能实际增加选购价值的最少补充项；分镜总时长与短稿估时一致，30秒方案保留待补。补充项根据缺失的购买理由选择，用户已有资料不再索要。
- `needs_facts`：核心功效、口味、用途或SKU信息存在冲突，交付可支持部分和具体问题。

缺图片影响制作状态；有效商品事实决定口播能讲什么。两者分别报告。分镜时为每条主打理由指定具体镜头、素材与出现时段；可见的部位、内容物或功能完成状态要实际进入该镜头。资料支持的非外观主张可由人物讲解配合相关场景承载，并说明画面只作展示。列在共享图片定义中不等于已安排镜头。动作与承接按[提示词的边界规则](prompts.md#边界)检查。

## 品类取舍参考

|品类|购物者关心的方向|适合承载的画面|
|---|---|---|
|服装、鞋包|风格/版型/搭配、使用任务、已支持的穿戴与携带特点|上身或上脚、正侧背面、相关结构与搭配|
|美妆、日化|护理/清洁/妆效偏好、已知配方或质地、适用范围|人物成妆或使用场景、实际质地、对应部位|
|食品、饮料|味型/口感、配料或份量、组合与食用场景|内容物、切面、取食和分享；体验依据来自资料|
|小家电、数码|要完成的任务、功能带来的便利、实际兼容条件|与任务有关的功能动作、完成状态、连接组合|
|家居、器物|使用位置、收纳或摆放价值、已支持的结构与设计|场景中的取放/移动、相关细节与空间关系|

外观本身是用户主打卖点时，可以围绕设计价值写。其余品类根据本次资料选理由，而非套用品类模板。健康、医疗、功效、耐用、舒适、续航等主张保留来源及条件；图片和生成演示不能补出实测结论。

## 交付记录

草案按顺序交付：内容取舍表、连续口播正文、审稿结果与状态、分镜草案、资料/图片缺口。分镜不能把未通过的正文包装成已完成30秒方案。

正式`package.md`保留取舍与事实来源；`result.json`沿用原合同并记录`skill_version`，加入上述正文与引用记录，并提供`selling_plan`：`category`、`audience_or_scenario`、`purchase_question`、`core_reasons`、`condition_review`、`purchase_conditions`（无则为空数组）、`opening`与`closing`。格式检查与文案审稿分别记录，生成后另查实际台词、切镜与声音。
