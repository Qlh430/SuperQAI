# 视频脚本与故事设计

创建、改写或评审品牌片、产品短片、CG动画和其他AI辅助视频脚本时读取。脚本的首要目标不是写满镜头术语，而是让观众在有限时间内看懂：发生了什么、为什么值得看、最后记住什么。

## 写作顺序

不要一开始就拆镜。依次完成：

1. 确定观众、传播场景和期望行为。
2. 用一句话锁定核心表达。
3. 确定主角或行动主体。
4. 建立能推动故事的问题。
5. 写出完整因果链和最大可见变化。
6. 分配画面、对白/旁白、环境/动作音、音乐和文字各自承担的信息。
7. 设计情绪曲线、视觉母题、开头和结尾闭环。
8. 用段落节奏格检查全片强弱、动静和信息密度。
9. 用时间、制作和生成条件检查可执行性。
10. 脚本获批后才拆分 `SEQ/SH`。

## 九项脚本骨架

开始写脚本前，回答：

| 项目 | 必须回答的问题 |
|---|---|
| 传播目标 | 观众看完要记住什么？ |
| 核心表达 | 能否用一句话说清影片观点，而非只介绍题材？ |
| 目标观众 | 给谁看、在哪里看、希望看完做什么？ |
| 主角 | 谁或什么在推动故事发展？ |
| 初始状态 | 故事开始时是什么状态？ |
| 核心问题 | 什么缺失、阻碍、目标或疑问推动行动？ |
| 关键行动 | 主角采取什么行动，为什么此刻采取？ |
| 最大变化 | 全片最重要且可被看见的结果是什么？ |
| 最终落点 | 如何回到产品、品牌或主题？ |

信息不足但可逆时提出少量暂定答案；核心表达、行动主体、核心问题或最终落点存在多种本质不同方向时，先确认再写完整脚本。

## 核心表达

核心表达是观众离开后应记住的观点，不是产品名、题材介绍或卖点清单。它应能指导取舍：一个段落、功能或视觉奇观若不服务核心表达，应删除、压缩或重写。

优先写成“某种价值通过一次变化被证明”的句子。避免宽泛口号；让观点能够被故事和画面验证。

## 观众与传播场景

明确：

- 观众已有的知识、兴趣和疑虑。
- 播放平台、主动观看或被动曝光、声音是否默认开启。
- 期望结果：记住、理解、产生情绪、互动、咨询或购买。
- 时长与观看环境对开场、文字密度和铺垫长度的影响。

不要把“短视频前三秒”当成机械规则；应在平台和观看情境下尽快建立兴趣与核心世界。

## 主角与故事发动机

主角可以是人物、产品、工程、能量、概念或创造过程，但必须明确谁在推动变化。特效、灯光和摄影机运动不能代替行动主体。

核心问题不一定是激烈冲突，可以是缺少、困难、秩序破坏、未完成目标或待揭晓疑问。它必须产生行动压力：若问题不存在，故事不应原样继续。

## 因果链

使用：

`初始状态 → 问题出现 → 主角采取行动 → 过程发生变化 → 获得结果 → 主题落点`

每段都回答：

- 这一段由什么导致？
- 它具体改变了什么？
- 它为什么使下一段必然或更合理地发生？
- 如果删除，后面的事情还能否原样发生？

若删除后没有影响，该段通常只是展示素材。删除、合并，或让它承担因果、信息、情绪或主题任务。

## 可见的变化

视频不能只依赖抽象说明。把“获得灵感、改善生活、更加高效、连接彼此”等概念改写为观众能看到或听到的变化：

- 物体、人物、环境或信息从什么状态变成什么状态。
- 哪个动作触发变化。
- 变化如何被空间、光线、声音、秩序、速度或角色反应证明。

每个重要信息都要回答：“观众具体看到什么变化？”旁白可以补充意义，但不能代替关键视觉证据。

## 情绪曲线与高潮

短片也需要强弱变化：建立或悬念、问题、行动加速、关键变化、反应和收束。高潮是全片最重要的状态改变发生，而不是特效最多、最亮或运镜最快。

为关键结果和角色反应保留时间。持续高强度会削弱真正高潮；稳定镜头、静音或节奏放缓也可以承担叙事力量。

## 视听节拍与节奏格

脚本阶段就确定每段的主信息通道：画面负责证明动作和变化；对白/旁白补充观点或人物语言；环境音建立空间；动作音强调关键接触；音乐组织情绪；字幕只保留需要准确读取的内容。避免画面、旁白和字幕同时重复同一句信息。

在复杂短片进入逐镜拆分前，先制作段落级节奏格。可用5×5节拍格或同等规模的接触表，每格只记录一个关键状态、动作、情绪或声音节点，而不是提前写25个镜头。用它检查：

- 开头多快建立异常、问题或目标。
- 信息、行动、反应和停顿是否交替。
- 中段是否只在展示素材，没有升级因果或压力。
- 高潮前是否有蓄力，高潮后是否有确认结果的空间。
- 色彩、声音或视觉母题是否随故事推进。

节奏格是思考工具，不等于固定镜头数量；多个格可以合并为一镜，一个格也可因制作需求拆成多镜。

## 功能、故事与主题

产品功能应因需要而出现：

`角色需要 → 使用功能 → 状态改变 → 产生后续结果 → 证明产品价值/主题`

不要按功能清单轮流展示。若某项功能不改变行动或结果，评估是否删除、降为背景信息，或重新设计其使用动机。

## 视觉母题

选择一个能贯穿影片的颜色、轨迹、形状、动作、文字、声音或节奏。母题应随剧情从弱到强、混乱到有序、残缺到完整或其他有意义的状态演变，同时统一跨场景画面并承载主题。

若母题只重复出现而不改变，它只能作为装饰，不能代替故事发展。

## 开头与结尾

开头不负责一次性交代全部背景，而应同时制造兴趣并建立核心世界。可根据内容选择异常状态、结果前置、动作切入、尺度反差、问题切入或熟悉事物的陌生化，但不要为形式牺牲理解。

结尾先完成故事闭环，再出现Logo或品牌语。至少完成两项：回答开头问题、展示状态变化、回收视觉母题、证明产品价值、留下明确情绪、落到可记忆的表达。

## 可执行性

在批准脚本前检查：

- 目标时长是否容得下所有因果节点和必要反应。
- 产品、人物、场景和动作是否符合真实形态与制作条件。
- 关键转场是否依赖难以控制且没有备用方案的生成效果。
- 每段是否提供新信息或新状态，而非同义展示。
- 独立概念是否过多；优先讲完整一个核心变化。

可执行性不应把创意变平，而是提前识别需要拆分、简化、替换方法或准备备用方案的部分。

## 默认脚本交付物

脚本阶段默认输出：

1. 已确认输入、暂定假设和待确认项。
2. 九项脚本骨架。
3. 一句话核心表达。
4. 故事发动机与因果链。
5. 带段落时间的脚本表，包含行动、可见变化、声音、功能动机和段落任务。
6. 视听分工和必要时的段落节奏格。
7. 情绪曲线与视觉母题变化。
8. 开头、高潮和结尾闭环说明。
9. 删除测试与可执行性检查。
10. 脚本确认结论：`已批准并锁定`、`有条件批准`、`需要修改`或`暂时阻塞`。

不要在脚本阶段用详细机位、镜头品牌、焦段或特效术语制造完成感。只有脚本结构通过后，才进入内容驱动的镜头拆分。
