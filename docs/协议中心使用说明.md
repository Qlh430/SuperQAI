# 协议中心

入口：超级管理员打开「系统设置 → 协议中心」。

| 项目 | 作用 | 使用位置 |
| --- | --- | --- |
| 平台协议 | 决定连接站点时使用的认证方式、模型目录接口和默认运行方式 | 模型服务中的「平台协议」 |
| 模型协议 | 决定单个模型请求的接口和允许的能力 | 模型服务中每个模型的「模型协议」 |
| 路由检查 | 根据已保存配置，显示本次请求会选中哪个站点、模型和运行协议，以及缺少哪些能力 | 协议中心下方「路由检查」 |

例如，一个 OpenAI 兼容平台可以同时提供聊天和图片模型。站点选择 OpenAI 兼容，图片模型使用 OpenAI Images，聊天模型使用 OpenAI 兼容；APIMart 等已接入的平台会沿用已实现的专用图片路由。

新增 API 时，先填写站点地址、密钥，验证并拉取模型。软件根据站点和模型识别默认协议、能力；已有手动选择在再次同步时保留。通常无需创建自定义协议。

需要复用配置或限制能力时，可新建自定义平台／模型协议，选择一个已接入的运行协议。平台继承其连接方式；模型协议可以限制允许的能力，例如创建「仅聊天」配置并只允许对话。保存后在模型服务的对应下拉框中选择即可。实际调用使用该运行协议，不需要重复配置密钥。

自定义协议保存在主机 SQLite 数据库中，随重启和数据库备份保留。正在使用的协议可以修改名称和说明；要删除或改变运行方式，需要先切换引用它的站点／模型。这样可以避免已有配置突然失效。

「检查路由」复用实际模型选择器和执行映射，不访问上游，也不生成内容。它可以发现模型缺少工具能力、站点未启用、运行适配器不可用等问题。检查通过表示当前配置能匹配请求，不等于密钥、额度及上游服务已经验证成功。需要确认真实调用时，使用模型服务中的「测试」；图片等模型测试可能产生上游费用。

本功能能减少配置错误，统一新 API 的识别与执行，并让故障更容易定位；不能消除上游限流、额度不足或网络故障。自定义协议继承现有运行方式，不会自动实现新的厂商私有协议。通用转发适配器的适用限制会在详情中显示。

参考 DX OS 活动版本 `runtime-0.2.6-7adc49d7-bdc7-4aa8-987e-8c789f1e6ee4` 的平台／模型分层、自定义运行协议继承和本地路由测试。没有移植其未接入的厂商接口或任意 JSON 配置编辑器。

验证：协议中心契约测试、隔离 Chrome 浏览器完整流程、原有 Provider 与 APIMart 回归均通过；浏览器测试使用本地模拟上游，验证自定义协议确实执行 `/v1/chat/completions`，并验证协议编辑、删除保护、重启持久化和路由检查期间改变选择不会显示过期结果。
