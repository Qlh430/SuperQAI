# 画布 Agent 生图可靠性与节点定位设计

日期：2026-08-28

## 目标

解决以下相互关联的问题：

- Agent 找到相似节点后只高亮和居中，但节点仍然太小，用户无法快速辨认。
- 设置中已有可生成的图片模型，手动节点可以生成，Agent 却可能误报“没有可用模型”。
- 图片接口已经生成远程结果，但本地原图保存失败时，系统仍显示“完成”并把不可访问的远程地址写入图集，造成空白卡片或破图。
- 将 `https://api.hyhawang.com` 对应的已启用图片提供方设为默认首选生图接口，同时保留同模型自动故障转移。
- 自动区分适合直连和适合代理的目标主机，避免“代理端口开着但实际线路不可用”，同时保证计费请求不会因换路重复提交。

本设计不改变旧画布的数据结构含义，不移动被定位节点的画布坐标，也不自动重复提交可能计费的生图请求。

## 已确认根因

### Agent 节点定位

`focusAgentCanvasNodesInViewport` 当前只重新计算画布平移量，保持原缩放比例。画布处于 41% 等低缩放级别时，节点虽然被居中和高亮，仍然无法辨认。

### Agent 误报无模型

Agent 和手动节点走了不同的候选判定路径：

- Agent 依赖客户端候选快照，并会把监测为 `offline`、`connection-error` 等状态的已配置模型直接排除。
- 刚保存设置时，Agent 还可能等待较旧的共享刷新任务，短暂得到空快照。
- 手动节点在执行前会重新获取候选，而且即使监测状态暂时异常，仍可能继续尝试当前已配置模型。

因此同一个接口可能被 Agent 判定为“无模型”，但手动节点实际能够生成。

### 生成完成但图集为空

已检查任务 `imgjob_1787886750048_7b23951f77`：上游在 2026-08-28 03:13 返回 `completed`，同时本地保存结果为 `fetch failed`。现有服务仍将远程临时 URL 当作 `local_url` 返回，客户端据此把图片写入图集并显示“完成”。这导致图集计数增加，但图片不可见。

### 代理路径误判

当前配置为 `OUTBOUND_PROXY_URL=auto`。Windows 系统代理实际关闭，但程序只因本机 `127.0.0.1:7890` 端口开放，就把所有公网请求统一交给该代理，并缓存这一选择。它没有验证具体目标主机通过代理是否可用，也没有代理失败后的直连候选。

对同一运行环境的只读对照测试结果：

- `api.hyhawang.com`：直连约 984ms；代理约 6.2s。
- `chatimage2-img3.shyfai.cn` 图片 CDN：直连约 1.8s 成功读取；代理 15s 超时。

因此本次 `fetch failed` 是图片 CDN 被送入不适合该域名的代理路径所致。仅判断代理端口是否开放不能代表代理链路健康。

## 推荐设计

### 1. 自适应节点取景

- 单节点：按可用画布高度的约 55% 计算目标缩放，限制在 65%–125%。
- 多节点：按整体边界加 12% 安全边距进行适配，目标占可用区域约 80%，缩放上限 100%。
- 只改变视图的 `x`、`y`、`scale`，绝不改变节点自身坐标。
- 取景完成后保留选中态，并显示短暂的 Agent 高亮光环。
- 计算使用 Agent 面板打开后的真实可用画布尺寸，避免节点被右侧面板遮挡。

### 2. 权威生图候选与首选接口

- 保存设置后递增候选版本号；任何旧版本的刷新结果都不能满足新版本的生图请求。
- Agent 正式生图前必须等待当前版本的权威 `/api/image-models` 响应，不使用旧空快照下结论。
- 候选分两层：
  - `configured`：已启用、具备 Base URL、密钥和 `generation` 能力。
  - `healthy`：监测状态良好。
- 优先选择健康候选；健康候选为空时，仍允许尝试已配置候选，让真实生图请求决定结果，而不是误报“没有模型”。
- 有参考图时必须要求 `edit` 能力；用户明确指定模型时不静默替换成其他模型。
- 将 Base URL 规范化后等于 `https://api.hyhawang.com` 的提供方设为默认首选；当前对应 `汪汪1 / gpt-image-2`。首选只影响排序，真实失败时仍按同模型候选自动切换。
- Agent 与手动节点共用同一候选解析函数，消除行为分叉。

### 3. 图片任务采用“本地可读后提交”

图片任务状态拆分为：

1. `queued/submitting/running`：等待上游生成。
2. `syncing`：上游已生成，正在把原图保存到本机。
3. `completed`：本地 `/output/...` 文件存在、非空且能识别为图片，才算真正完成。
4. `sync_failed`：上游已生成，但本地同步在重试后仍失败。
5. `failed/unknown`：上游明确失败或提交结果无法确认。

本地同步规则：

- 对远程结果执行有上限的退避重试，只重复下载结果，不重新调用生图接口。
- 图集只能接收已验证的本地 `/output/...` 地址；不得再把失败的远程临时 URL 当成本地地址写入。
- `sync_failed` 必须保留任务编号和远程结果，并显示“图片已生成，但原图尚未同步到本机”。
- 用户点击“恢复原图”时，只恢复同一任务的远程结果，不重新生成、不重复扣费。
- Agent 的成功消息只能在任务进入 `completed` 且图集包含本地可读图片后出现。

### 4. 按主机自适应出站网络路由

路由不能仅按国家、顶级域名或“代理是否开启”判断，而要按目标主机的真实可达性和历史表现选择。API 主机与它返回的图片 CDN 主机必须分别决策。

#### 路由模式

每个 API 提供方支持三种策略：

- `auto`：默认模式，按主机选择近期表现最好的直连或代理线路。
- `direct`：强制直连，用于明确位于国内或代理反而不稳定的接口。
- `proxy`：强制代理，用于直连不可达的海外接口。

`https://api.hyhawang.com` 对应提供方默认使用 `direct`，并作为首选生图接口。其返回的 CDN 主机仍由自动模式独立判断；当前 `shyfai.cn` 系列主机优先直连，但不写死单个完整图片域名。

#### 自动判断

- 为每个 `scheme + hostname + port` 维护独立线路状态，不把 API 主机的结论套用给 CDN。
- 使用轻量、非计费探测比较直连和代理的 TLS 建连、首包延迟和近期错误率。
- 路由结果设置短期 TTL；成功会延长偏好，连续失败会触发熔断并重新探测另一线路。
- 代理自动发现必须验证代理能实际访问目标主机，不能只验证本地端口开放。
- 记录结构化失败阶段：DNS、TCP、代理连接、TLS、首包、下载中断、HTTP 状态。设置页只展示脱敏后的主机、线路、延迟和原因。

#### 请求安全边界

- 非计费 GET/HEAD 和图片下载是幂等请求：首选线路失败后允许自动换路，并取消较慢或失败的线路。
- 图片下载可使用“首选线路先发、短暂延迟后启动备用线路”的竞争策略；只采用第一个通过图片校验的结果。
- 生图、编辑等可能计费的 POST：提交前完成线路选择，实际请求只发送一次。
- 计费 POST 如果在提交后出现不确定网络中断，标记为 `unknown` 并保留任务；不得自动换路重发。
- 明确收到“请求未到达上游”的代理握手或 TLS 建连失败时，才允许在提交前切换线路。

#### 路由持久化与便携部署

- 保存提供方的显式模式和按主机学习到的脱敏线路统计，不保存代理凭据。
- 换到另一台电脑后保留显式 `direct/proxy/auto` 偏好，但清空机器相关的延迟、端口和熔断状态，重新探测当地网络。
- 未检测到可用代理时，`auto` 仍可直连；强制代理模式则明确提示“代理不可用”，不会假装接口本身故障。

### 5. 旧图集自动修复

- 打开旧画布时，识别图集中仍为 HTTP(S) 远程地址、加载失败的条目。
- 通过本地化接口按 URL 幂等恢复到 `/output/...`，成功后原位更新同一个图集条目，不增加计数。
- 恢复期间显示明确的“正在同步原图”占位；失败时显示可重试状态，不显示空白卡片或浏览器破图图标。
- 已经是本地 `/output/...` 的图片不重新处理。

## 数据流

1. Agent 或手动节点发起生成。
2. 统一候选解析器读取当前版本候选并选择 `hyhawang.com` 首选候选。
3. 路由器按 API 主机选择线路；对计费请求只提交一次。
4. 服务端创建唯一图片任务并提交一次上游生成。
5. 上游返回远程图片后，任务转为 `syncing`；路由器按图片 CDN 主机独立选择和切换下载线路。
6. 本地文件验证成功后任务转为 `completed`，客户端再提交节点和图集结果。
7. 下载失败则进入 `sync_failed`，客户端保留任务并提供同任务恢复，不重新生成。

## 错误提示

- 没有任何已配置生图能力：`未配置具备图片生成能力的模型。`
- 有配置但真实调用失败：展示具体接口错误和已尝试的备用接口，不再表述为“没有模型”。
- 上游生成成功、本地同步中：`图片已生成，正在同步原图到本机…`
- 本地同步失败：`图片已由接口生成，但原图尚未保存到本机。可恢复原图，不会重新生成或重复扣费。`
- 强制代理但代理不可用：`代理线路不可用；请求尚未提交到图片接口。`
- 计费请求提交后线路中断：`请求可能已被接口受理，正在核对原任务；不会自动重复提交。`
- 完成：仅在本地文件验证和图集提交均成功后显示 `完成`。

## 测试要求

- 低缩放画布定位单节点后，节点占用比例达到目标范围，节点坐标不变。
- 多节点定位整体可见，不被 Agent 面板遮挡，缩放不超过 100%。
- 设置保存期间制造旧刷新晚到，Agent 仍能选择新加入的 `汪汪1`。
- 所有健康监测暂时异常但配置完整时，Agent 会尝试候选而不是返回 `no_usable_image_model`。
- `hyhawang.com` 在健康条件相同或可尝试时排在首位。
- 模拟上游成功、首次下载失败、后续下载成功：只发生一次生图请求，最终写入本地地址。
- 模拟持续下载失败：不写入远程破图，不显示完成，可通过同一任务恢复。
- 旧画布远程破图恢复成功后原位替换，图集计数不增加。
- 自动代理端口开放但目标主机代理访问超时：国内 API 和 CDN 自动选择直连。
- 直连不可达、代理可达：海外接口自动选择代理并缓存该主机线路。
- API 主机直连、其 CDN 需要代理（以及反向组合）时，两个主机独立选择正确线路。
- 计费 POST 出现提交后超时时只产生一个上游请求；图片 GET 下载失败时可以安全换路重试。
- 携带显式路由偏好迁移到另一台电脑时，不携带旧机器代理端口和线路健康缓存。
- 浏览器回归覆盖 Agent 生图、手动生图、故障转移、页面重载和旧画布打开。

## 非目标

- 不重构所有图片提供方协议。
- 不改变现有画布节点坐标或历史连接。
- 不自动再次提交收费生图请求来修复下载失败。
- 不依赖 `.cn`、`.com` 或静态“国内/海外域名表”作为唯一判断依据。
- 不接管或修改用户代理软件本身的规则和节点选择。
- 不把 API Key 或其他秘密写入画布数据。
