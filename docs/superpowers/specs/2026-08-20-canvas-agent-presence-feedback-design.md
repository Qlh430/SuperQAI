# 画布 Agent 默认入口与等待反馈设计

## 背景

画布 Agent 当前在没有保存偏好时默认展开，首次打开网站便占用 410px 画布空间。用户发送消息后，运行反馈只出现在输入框底部的“Agent 正在处理…”文字中，对话区没有与用户消息对应的回应占位，容易被误判为点击无效。

## 目标

- 首次访问默认收起 Agent，不主动压缩桌面画布。
- 用户手动打开或关闭面板后，继续记住上次选择。
- 每次等待模型返回时，在对话左侧显示无文字的四条竖向动画。
- 正常运行阶段不在输入框底部显示 loading/处理中文字。
- 停止、审批、失败和完成等可操作或终态信息继续清晰可见。
- 动画不进入画布渲染循环，不增加轮询或 JavaScript 定时器。

## 交互设计

### 面板入口

`canvas-agent-panel-open-v1` 不存在时按关闭处理；值为 `"true"` 时恢复打开，值为 `"false"` 时恢复关闭。顶部 Agent 按钮始终可见并继续更新 `aria-expanded`。

### 等待动画

发送用户消息后，消息列表立即追加一个左对齐的 Agent 等待项。等待项只包含四条黄绿色竖条，不显示“Loading”“正在处理”或其他可见文字。竖条使用错峰 `scaleY` 与 `opacity` 动画，形成视频参考中的条形呼吸节奏。

等待项使用 `role="status"`、`aria-label="Agent 正在回应"` 和屏幕阅读器文本提供无障碍状态；屏幕阅读器文本不参与视觉布局。`prefers-reduced-motion: reduce` 时停止循环并显示静态高低错落状态。

等待项按以下生命周期工作：

1. 用户提交后立即出现。
2. 服务端返回一个完整 Agent turn 前保持显示；普通 status 阶段变化不改写底部文案。
3. 收到 turn、发生失败、用户停止或重置任务时移除。
4. 工具执行完成后发起下一轮模型请求时重新出现，工具执行期间由现有工具步骤承担反馈。

每个等待项绑定当前 `run_id`。旧任务在停止后即使仍有异步工具完成，也不能移除新任务的等待项、继续提交旧工具结果或覆盖新回复。服务端一旦发出终态 `turn` 事件，客户端立即取消当前流读取并清理动画，不等待连接自然关闭。

### 输入区状态

运行中保持停止按钮可用、发送按钮禁用，但 `#canvasAgentStatus` 的正常进度文字清空。审批等待、停止、失败、完成以及配置警告仍可使用现有状态区；错误同时继续写入对话区。

## 性能与边界

- 动画完全使用 CSS，不调用 `setInterval`、`setTimeout` 或 `requestAnimationFrame`。
- 只变换 4 个小元素的 `transform` 与 `opacity`，不读取布局，不触发画布连线重绘。
- 创建等待项的函数必须幂等，连续 status 事件不得产生多个动画。
- 清理函数必须覆盖成功、工具调用、审批、停止、异常和新任务重置路径。
- 面板收起时 Agent 状态仍可完成，但动画不可影响画布宽度或交互。
- 面板收起时同步设置 `inert` 与 `aria-hidden="true"`，并禁用指针交互，避免屏幕外控件仍可聚焦。

## 验收标准

- 清空面板偏好后刷新，Agent 面板保持收起，顶部按钮 `aria-expanded="false"`。
- 手动打开后刷新，面板恢复打开；手动关闭后刷新，面板恢复关闭。
- 点击发送后，在用户消息对面立即出现四条竖向动画，且页面没有可见 loading 文案。
- 收到 Agent 回复后动画消失且回复正常显示。
- 多轮工具调用时等待项不重复，工具执行期间仍显示原有步骤反馈。
- 点击停止、接口失败或新建任务后没有残留动画。
- 停止旧任务后立即发起新任务时，旧工具完成不会串入新任务；新任务始终只有一个等待项。
- 动画样式包含 `prefers-reduced-motion` 降级。
- 完整静态检查和浏览器关键路径验收通过。
