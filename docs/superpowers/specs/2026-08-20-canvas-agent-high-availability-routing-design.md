# 画布 Agent 高可用与快速响应路由设计

## 背景与问题

当前画布 Agent 的服务端调用固定读取 `CANVAS_AGENT_API_URL` 或 `AI_API_URL`，默认只请求一个 `/v1/responses` 端点。一次请求最长可能等待约 180 秒，失败后没有备用线路。设置页的“在线”状态主要通过 `/v1/models` 获取速度判断；该接口返回快，只能证明模型列表可读取，不能证明真实推理、视觉输入或工具调用可用。

本次实测中，当前 Agent 请求约 180 秒后返回 504；设置页中的局域网线路访问模型列表仅需数毫秒，但真实 `/v1/responses` 与 `/v1/chat/completions` 推理均在 90 秒内没有返回。因此需要把“模型列表在线”和“Agent 实际可用”分开，并为 Agent 增加独立的自适应路由与故障转移。

## 目标

- 优先使用真实响应速度最快、近期稳定的 Agent 线路。
- 同一模型的线路全部失败时，自动降级到其他支持所需能力的模型。
- 单个接口超时、限流或临时故障时，Agent 仍能切换到其他可用模型继续工作。
- 前端不显示模型、提供商、接口地址或切换顺序，只显示任务状态。
- 不阻塞画布渲染、拖拽、缩放、选中、框选和节点连线等高频交互。
- 保持现有“自动 Agent + 可选 Skill”、画布上下文和付费执行确认机制。
- 避免故障转移造成重复扣费、重复生成或重复写入画布。

## 非目标与能力边界

- 不承诺在所有外部模型服务同时故障、断网或所有密钥失效时仍能生成 LLM 内容。此时必须立即给出本地状态反馈、保存任务并允许恢复重试，不能无限转圈。
- 不在普通用户界面暴露内部模型或提供商名称。详细诊断仅保留在设置页的管理视图和服务端日志中。
- 不采用默认双请求竞速。并发向两个模型发送同一任务可能产生双份推理费用，并使有副作用的工具调用更难保证只执行一次。

## 方案比较

### 固定主备顺序

实现简单，但不能根据近期真实速度自动调整；首选线路变慢时，每次请求都会先经历同样的等待。仅适合作为初始配置，不作为最终路由策略。

### 自适应顺序故障转移（采用）

根据真实推理的成功率、首个事件耗时、完整响应耗时和近期故障动态排序。先请求最优线路，达到短超时阈值后中止并切换下一线路。该方案兼顾速度、成本和工具执行安全。

### 并发竞速

首字速度理论上最快，但可能重复计费；取消请求也不保证上游不计费。对于会触发画布工具的 Agent，还存在重复工具计划风险。因此不作为默认策略，首版不实现。

## 总体架构

在现有 Agent 处理器和外部模型接口之间增加服务端路由层：

1. **候选池构建器**：从设置中的已启用提供商和模型生成候选线路，不再把 Agent 固定绑定到 `.env` 中的单一地址。
2. **能力验证器**：通过最小真实推理验证文本、视觉和工具调用能力，区分“模型列表可读取”和“Agent 可执行”。
3. **健康评分器**：根据最近请求的真实数据计算候选顺序，并维护熔断状态。
4. **协议适配器**：优先支持 Responses API，同时把兼容的 Chat Completions 工具调用规范化为统一的 Agent 事件。
5. **运行协调器**：负责顺序尝试、超时、取消、跨线路恢复、幂等和流式输出。

浏览器只连接本项目服务端，不直接读取 API Key，也不参与提供商选择。

## 候选模型与能力分层

每条候选记录至少包含：提供商 ID、模型 ID、端点协议、是否支持文本、视觉、工具调用、启用状态和能力验证时间。模型能力不能只由名称推断；管理端获取模型后需要执行一次极小的真实验证，并缓存结果。

候选池按当前任务过滤：

- 普通聊天需要文本能力。
- 带图片上下文的任务需要视觉能力。
- 自动 Agent 和 Skill 执行需要工具调用能力。
- 含图片且需要画布工具时，必须同时通过视觉和工具调用验证。

路由优先级为：同模型的健康线路、其他同等级兼容模型、剩余通过能力验证的兼容模型。模型名称只用于服务端匹配和日志，前端不显示。

现有 `.env` Agent 地址作为兼容候选保留，避免设置尚未迁移时 Agent 完全不可用；设置中通过验证的候选优先参与动态排序。

## 真实健康评分与熔断

`/v1/models` 只用于发现模型，不再作为 Agent 可用性的依据。评分使用 Agent 的真实调用数据：

- 最近成功率与连续失败次数。
- 首个有效流事件耗时。
- 完整响应耗时。
- 429、5xx、网络错误、协议错误和超时类型。
- 最近一次成功与最近一次能力验证时间。

速度采用指数移动平均，避免一次偶然快请求让不稳定线路长期排在第一。没有历史数据的新线路进入有限试用状态，不直接长期占据首位。

熔断规则：

- 网络错误、超时、429 或 5xx 连续出现两次后短时熔断。
- 401、403、余额或权限类错误进入较长熔断，直到配置变化或管理端重新验证。
- 熔断期满后只允许一次半开探测；成功才恢复正常流量。
- 成功请求立即降低失败权重，但不一次性清除全部历史。

运行历史保存在现有提供商运行历史结构的扩展字段中。写盘采用异步批量刷新，不在请求热路径同步写文件。

## 请求、超时与流式响应

Agent 请求改为服务端流式输出。路由层区分连接、首个有效事件和单轮总耗时：

- 连接阶段目标阈值约 4 秒。
- 默认低推理强度下，首个有效事件目标阈值约 10 秒。
- 单条线路的完整响应仍有较长上限，复杂 Skill 可使用更宽松的单轮阈值。
- 整次运行保留统一总预算，不能因为连续切换无限延长。

阈值作为服务端配置，不散落在前端代码中。发生切换时，未产生有效响应的请求立即通过 `AbortController` 取消。已经向用户输出不可撤销文本或已经执行工具后，不盲目重跑整轮，而是进入恢复流程。

普通问候、意图确认和简单问答默认使用低推理强度；需要规划多步工具或执行 Skill 时再提升推理强度，避免所有请求都以中等推理启动。

## 跨线路连续性

Responses API 的 `previous_response_id` 可能只在原提供商内有效，不能直接带到另一线路。因此运行协调器保存与提供商无关的规范化记录：用户输入、图片引用、助手文本、工具调用、工具输出和确认状态。

- 一次工具循环开始后优先固定在当前获胜线路，减少协议差异和上下文重放。
- 当前线路在工具调用前失败时，下一线路使用完整规范化记录重新生成。
- 当前线路在工具执行后失败时，下一线路接收已经完成的工具输出，不得再次执行同一个调用。
- 每个运行、每个工具调用和每个画布写操作都有稳定幂等 ID；浏览器与服务端都拒绝重复提交。
- `run_canvas_node` 的付费确认状态绑定运行 ID，线路切换后不重复询问，也不绕过首次确认。

## 前端交互

Agent 标题区只显示“画布 Agent”，移除当前的模型名称。普通用户只看到以下状态：

- 正在理解
- 正在规划
- 正在执行画布操作
- 当前响应较慢，正在恢复
- 已恢复，继续执行

不显示“线路 1/2”、模型名称或提供商名称。只有真正需要用户处理配置时，才显示可行动的错误，例如“所有可用服务暂时不可用，任务已保存，请稍后重试”。

线路切换不创建额外聊天气泡；状态在同一运行状态条中更新，成功后自动收起。用户点击停止时，浏览器中止流，服务端取消当前线路并禁止继续自动切换。

## 画布流畅度硬约束

高可用能力不得进入画布高频交互热路径：

- 不修改画布的 `pointermove`、拖拽、缩放和渲染循环。
- 不使用前端定时轮询健康状态；健康评分、熔断和探测全部在服务端完成。
- 画布选择变化只维护轻量节点 ID，不读取图片、不编码 Base64、不序列化整张画布。
- 仅在用户发送消息时异步构建 Agent 上下文；图片沿用 URL/引用并继续限制视觉素材数量，不复制大对象。
- 流式事件只更新 Agent 面板局部 DOM，不触发布局范围覆盖画布容器。
- 状态更新做合并节流；高频 token 不逐个导致完整消息重排。
- 提供商历史计算保持有界窗口，健康探测并发数为 1，且不得占用画布请求队列。
- 服务端文件日志异步批量写入；路由评分为内存操作，不能同步读取整个历史文件。
- Agent 面板关闭或运行停止后，清理流、计时器和事件监听，避免后台泄漏。

性能验收以 Agent 开关前后的画布操作对比为准：Agent 空闲时不产生网络轮询；拖拽和缩放不增加同步图片处理或整画布遍历；线路故障与切换期间画布仍可正常编辑。

## 全部上游不可用时

当所有候选均熔断或本轮尝试全部失败时：

1. 立即结束“处理中”动画并返回本地可理解状态，不能等待到浏览器请求总超时。
2. 保存用户输入、画布引用、Skill 模式和未完成运行状态。
3. 提供“重新尝试”操作；配置恢复后从安全检查点继续。
4. 不自动重复执行已经成功的画布工具。
5. 服务端可以在熔断半开阶段恢复候选，但不在前端持续轮询或无限自动重发用户任务。

这保证界面始终有反馈并可恢复，但不会把本地错误文案伪装成模型回复。

## 设置页与可观测性

设置页的模型操作区增加“验证 Agent”能力，结果分别展示文本、视觉、工具调用和真实推理延迟。模型列表接口耗时仍可展示，但标注为“模型发现”，不能显示为 Agent 已可用。

管理诊断记录：实际提供商、实际模型、尝试顺序、首事件耗时、完成耗时、失败分类、熔断变化和最终结果。普通 Agent 前端收到的事件不包含这些名称。API Key 继续只存在服务端配置中，日志不得写入完整 Key、图片 Base64 或用户敏感正文。

## 错误分类

- **可快速切换**：连接失败、DNS/TLS 错误、首事件超时、请求超时、429、502、503、504、空响应和可识别的协议损坏。
- **配置型故障**：401、403、无余额、模型无权限和模型不存在；线路进入长熔断并提示管理端检查。
- **任务型错误**：用户素材缺失、参数无效或工具输入不满足约束；不得换模型反复尝试，应由 Agent 向用户说明。
- **工具执行错误**：画布函数失败时保留错误输出交给当前 Agent 修正；只有模型线路本身失败才切换。
- **用户取消**：立即停止，不计为线路故障，不触发自动降级。

## 测试设计

### 单元测试

- 候选能力过滤和同模型优先排序。
- 真实延迟、成功率与失败惩罚的评分更新。
- 连续失败、熔断、半开和恢复状态转换。
- Responses 与 Chat Completions 工具事件规范化。
- 跨线路重放时保留工具输出和确认状态。
- 幂等 ID 阻止重复画布写操作。

### 集成测试

- 首选线路快速成功时不访问备用线路。
- 首选线路连接超时、首事件超时、429、5xx 或返回畸形数据时切换备用线路。
- 同模型线路全部失败后切换到兼容模型。
- 工具执行前后分别发生线路故障时，任务可恢复且工具最多执行一次。
- 所有线路不可用时及时结束并保存任务。
- 用户停止后不再切换或继续输出。

### 画布性能回归

- Agent 空闲 60 秒内没有前端健康轮询。
- 打开 Agent、故障转移和流式输出期间，拖拽、缩放、框选和节点连接保持可用。
- 选择图片时不进行 Base64 编码；仅发送时处理受限数量的视觉引用。
- 流式长回复不会对整个画布容器触发重复布局或重绘。
- 多次打开关闭 Agent 后，无重复监听、残留流或计时器。

## 验收标准

- 前端不再显示 `gpt-5.6-terra` 或任何实际模型、提供商名称。
- 真实推理正常的最快健康线路会被优先选择，而不是按 `/v1/models` 延迟选择。
- 首选线路达到短超时阈值后能自动切换，不再单点等待约 180 秒。
- 同模型不可用时可以降级到通过当前任务能力验证的其他模型。
- 线路切换后对话、Skill、画布上下文和付费确认保持连续。
- 任意工具和画布写操作在一次运行中最多执行一次。
- 所有上游不可用时及时反馈、保存任务并可安全重试。
- Agent 空闲不轮询，运行和故障切换均不影响画布核心交互。
- 设置页能够区分“模型列表可读取”和“Agent 实际可用”。
- 自动化测试、现有 `npm run check` 和浏览器关键路径验收均通过。
