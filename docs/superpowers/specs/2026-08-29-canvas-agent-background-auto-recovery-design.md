# Canvas Agent 后台自动恢复设计

## 目标

Canvas Agent 遇到临时网络超时、Agent 线路不可用或可恢复的协议中断时，默认在后台继续任务，不在第一次失败后要求用户点击“继续任务”。恢复过程必须保留当前画布和已完成步骤，并防止重复付费、重复创建节点或把旧任务写入新画布。

## 根因

当前 `canvas-agent-ui.js` 的 `handleCanvasAgentFailure()` 会把所有可恢复错误立即转为 `recoverable` 终态，写入恢复提示并渲染 `data-agent-continue` 按钮。前端没有自动恢复调度器，因此服务端即使已经尝试备用线路，最终一次临时失败仍会把剩余工作交给用户手动恢复。

## 已确认方案

采用有边界的自适应后台恢复：

- 可恢复错误发生后自动恢复最多 3 次；
- 延迟依次为约 1 秒、3 秒、8 秒；
- 恢复期间显示“网络波动，正在自动恢复 1/3”等状态，但不新增伪装成用户输入的可见消息；
- 第一次临时失败不显示“继续任务”按钮；
- 3 次均失败后才结束自动恢复，并显示一次手动“重新尝试”入口；
- 用户点击停止、切换画布、开始新任务或重置 Agent 时立即取消定时恢复；
- 不进行无限重试，不让后台任务脱离当前画布长期运行。

## 恢复方式

每次自动恢复使用新的 Agent 运行上下文，并提交内部恢复指令：继续完成中断任务、先读取当前画布和对话中的真实工具结果、不得重复已完成步骤。内部恢复指令不写成用户消息。

不直接重放失败的 HTTP 请求。特别是带 `previous_response_id` 和工具输出的续接请求，原服务端是否已经接收可能不确定；直接重放可能造成协议冲突或重复操作。新运行通过当前画布、持久化对话和工具结果重建上下文，沿用现有手动“继续任务”的安全语义，但由系统自动触发。

## 状态与生命周期

前端维护单一自动恢复上下文：

- 原始用户目标；
- 当前画布 ID；
- 手动或自动 Skill；
- 已执行恢复次数与最大次数；
- 下一次恢复定时器；
- 未消费的直接生图授权；
- 本轮是否已经尝试过付费工具。

只有画布 ID 仍一致、没有新用户任务、没有停止信号且恢复上下文仍为最新版本时才允许启动下一次尝试。任何新任务都会使旧恢复上下文失效。

## 付费与幂等安全

- 已经调用过付费工具的运行，不把该付费授权带入新的自动恢复运行；生成结果未知时只检查画布和任务状态，不重复提交付费请求。
- 尚未调用付费工具时，可以继承尚未消费的一次直接生图授权，保证“明确直接生成”不会因 Agent 网络抖动重新要求确认。
- 已完成工具结果继续写入画布对话记录；恢复指令要求先检查这些结果。
- 原有同一运行内的 `call_id` 与付费尝试防重仍保留，自动恢复不放宽任何危险或付费操作授权。

## 用户界面

- 自动恢复期间保留运行态和停止按钮，状态栏显示当前次数；
- 不追加多条重复错误卡，不显示“继续任务”；
- 恢复成功后正常显示最终 Agent 结果和“任务完成”；
- 自动恢复耗尽后显示简洁说明：“网络仍不可用，任务和画布已保留”，并提供“重新尝试”；
- 鉴权失败、余额不足、参数错误、用户拒绝、需要选择节点或等待付费确认不属于自动恢复，不自动重试。

## Skill 一致性

同步修改 `skills/canvas-agent-core/SKILL.md` 中遗留的旧三选项描述：已有节点仅允许“修改后生成”和“新建并生成”，不再出现“直接再生成”或“三选一”。

## 测试与验收

自动化测试覆盖：

1. 第一次可恢复 Agent 失败不会出现手动按钮，并自动发起恢复；
2. 自动恢复成功后只保留一条原始用户消息，不显示内部恢复指令；
3. 部分安全工具已完成后发生断线，恢复不会重复创建该节点；
4. 已经尝试付费工具后发生状态不明，不会重复提交付费请求；
5. 尚未消费的一次直接生图授权可以安全继承；
6. 三次失败后停止自动恢复并显示一次手动重试入口；
7. 停止、切换画布、新任务和重置都会取消旧定时器；
8. 鉴权、余额和不可恢复参数错误不会自动重试；
9. 核心 Skill 不再包含旧三选项文字；
10. 现有 Canvas Agent、图片故障切换、画布隔离与便携版静态检查继续通过。

## 非目标

- 不修改图片供应商的代理与网络路由；
- 不改变图片后台任务自身的同步恢复机制；
- 不增加无限后台守护或跨画布任务；
- 不修改手动画布生成按钮、参数控件和其他画布功能。
