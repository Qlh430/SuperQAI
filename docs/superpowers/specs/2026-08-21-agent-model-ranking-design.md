# Agent 模型页与可靠性候选排名设计

> 状态：已实施。验证：`npm run check`、`node tools/check-canvas-agent-browser.js`、`node tools/check-portable-package.js .` 均通过。

## 目标

把 Agent 模型管理从“API 接入”中拆成独立设置页。用户只需选择主模型，其余可用候选由系统按可靠性自动排序并在失败时依次接管，尽量避免可恢复的模型或接口故障直接中断画布任务。

## 用户界面

设置侧栏新增“Agent 模型”，API 接入页恢复为只管理地址、Key、启用状态和模型声明。

Agent 模型页按以下结构展示：

1. 顶部“当前主模型”卡片，显示模型名称、API 接入名称、接口地址和健康状态。用户可以恢复“自动选择”，也可以把任意已验证候选设为主模型。
2. “备用顺序”列表按系统实际执行顺序编号。用户不需要选择速度、均衡或稳定策略，也不需要维护备用顺序。
3. “待验证”区域收纳从已启用 API 的 `/models` 发现、但尚未证明工具调用能力的候选，避免它们混入正式排名。
4. 每个候选的身份由 API 接入、接口地址、Key 指纹、模型和协议共同确定；同一模型出现在多个 API 时必须分行展示、分别实测、分别统计。

候选行默认只展示模型、API 接入、接口地址、状态和主要结论。延迟、成功率、连续失败等诊断数据保留为次级信息，避免设置页显得复杂。

## Agent 能力验证

从 `/models` 获取模型名称只代表“可能是文本模型”，不能证明具备 Agent 能力。正式候选必须满足：

- 文本推理成功；
- 能以结构化格式调用无副作用测试工具 `report_agent_probe`；
- 工具参数能正确返回本次随机验证码；
- 当前任务包含画布图片时，视觉能力也必须有通过记录。

测试不执行任何画布 MCP 工具，不创建、修改或删除节点。环境变量保底模型不再拥有特殊信任，必须通过相同验证，或已经在真实 Agent 任务中成功完成过工具调用，才能进入正式候选池。

点击“验证”后，按钮必须立即进入运行状态，并依次反馈“连接接口”“验证文本与工具调用”“验证通过”或可理解的失败原因。按钮事件必须先于通用 API 选择事件处理，防止点击被服务商切换逻辑截获。重复点击同一候选时复用正在执行的验证，不并发产生多笔测试请求。

## 自动排名

正式候选只使用一套可靠性排名，不向用户暴露策略选项。排序优先级为：

1. 用户指定且当前健康的主模型；
2. 工具调用成功率；
3. 连续失败次数和当前熔断状态；
4. 最近成功时间与样本可信度；
5. 首字响应时间，仅在可靠性接近时作为次要排序因素。

新验证通过但样本不足的候选可以作为末位备用，不能因为单次速度快直接排在长期稳定候选前面。鉴权、余额和明确不兼容错误进入长熔断；超时、限流和临时服务器错误进入短熔断。

## 主模型与故障切换

用户设置主模型时实际固定的是一条“模型 + API 接入”候选，而不是只保存模型名称。主候选健康时始终优先；主候选不可用时自动切换到备用排名第一的候选。

一次 Agent 任务正常情况下固定使用同一候选。发生可恢复的模型或接口失败时，运行时保存当前画布、对话、Skill 步骤和 MCP 工具执行结果，换用下一候选继续当前回合，而不是要求用户重新发送。已经成功执行的 MCP 工具调用不得重复执行；使用 `run_id + call_id` 保证幂等。

只有所有已验证候选都失败，或错误属于画布工具自身且不能通过换模型恢复时，才向用户显示最终错误。界面应说明已尝试的接口数量和可操作建议，不暴露 API Key 或内部堆栈。

## 数据与兼容

设置持久化主候选的稳定标识和已验证候选的固定备用顺序。备用顺序在保存后不会因为重启、后台健康数据变化或模型重新发现而漂移；运行时仅临时跳过熔断中的候选，不改写用户保存的顺序。新验证通过的候选追加到备用队尾，只有用户重新选择主模型、API 接入被删除/修改或再次保存配置时才生成新的有效路线快照。

旧版 `speed`、`balanced`、`stability` 和只保存模型名的 `preferred` 设置在读取时迁移：能唯一匹配时转换为对应候选，否则恢复自动选择。旧版只有 `primaryCandidateId` 的配置继续可用，并在下一次保存时补齐备用顺序。

候选身份只绑定“API 接入 + 规范化地址 + Key 指纹 + 模型”，不绑定电脑、安装目录或画布。迁移到另一台电脑后，如果原 API/Key 没有一并配置，旧候选显示为需要重新设置而不能被执行；用户重新填写接口、验证并保存后，新候选替换失效快照。Agent 路由配置不额外复制或暴露 API Key。

健康记录按候选身份保存，包括成功、失败、首字时间、连续失败、熔断截止时间和最后验证时间。更换 LLM 不影响 MCP 工具协议、画布能力注册或 Skill 流程。

## 隔离与性能

- 所有运行、候选和工具结果继续绑定当前 `board_id`；旧画布延迟响应不能影响新画布。
- `/models` 扫描和 Agent 验证在服务端异步执行，不占用画布渲染主线程。
- 仅打开 Agent 模型页、主动刷新、保存 API 设置或候选过期时更新发现结果。
- 候选列表限制为当前 Agent 模型、用户配置的文本模型和已有验证记录，避免渲染数千个无关模型。
- 健康统计批量落盘，不在拖动画布、缩放或节点交互过程中同步写文件。

## 验收标准

- 设置侧栏有独立“Agent 模型”页面，API 接入页不再显示 Agent 路由卡片。
- 页面没有速度、均衡、稳定策略；用户可以设置一个主候选或恢复自动选择。
- 点击验证立即有状态反馈，并确实发送一次对应候选的验证请求。
- 同一模型的不同 API 接口分别出现、分别验证、分别排名。
- 正式候选均通过文本与工具调用验证，不再无条件信任环境变量保底。
- 主候选发生可恢复故障时自动尝试下一候选，并保持当前任务上下文和工具幂等。
- 保存后重启网站，主模型和备用顺序保持不变；熔断只临时跳过故障项，不改写保存顺序。
- 迁移到没有原接口凭据的新电脑时可以重新配置，失效候选不得阻塞新候选验证和保存。
- 设置、扫描和健康记录不造成画布拖动、缩放或节点操作卡顿。
- 静态、路由、验证、故障切换、浏览器交互、性能和便携版检查全部通过。
