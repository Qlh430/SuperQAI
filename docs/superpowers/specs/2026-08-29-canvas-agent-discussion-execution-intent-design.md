# Canvas Agent 讨论与执行意图设计

## 目标

让 Canvas Agent 在不增加常规生图步骤的前提下，准确区分“立即出图”和“只讨论提示词、参数”。同时精简复用已有生图节点时的选择卡，避免含义重复的操作。

## 已确认的交互规则

### 明确执行

当用户使用“想要一张”“要一张”“直接生成”“生成”“出图”“画一张”“做一张”或同义表达时，Agent 将其视为明确的生图请求：

- 不先展示提示词和参数确认方案；
- 允许按现有付费授权规则直接执行一次生成；
- 参数不兼容时沿用现有行为：提示自动调整结果，并继续生成，不增加二次确认；
- 如果当前画布没有需要复用决策的相关生成节点，直接创建节点、执行生成并加入图集；
- 如果找到相关生成节点，只询问是修改当前节点还是保留当前节点另建一个，不再额外询问提示词是否确认。

### 明确讨论

当用户使用“先讨论”“先聊”“先给我提示词”“先看参数”“先优化提示词”“不要生成”“先别出图”“等我确认”或同义表达时，Agent 进入本轮只讨论状态：

- 不调用任何付费图片生成工具；
- 不创建“生成中”节点或图集结果；
- 可以用文字给出建议提示词、模型、画幅、分辨率和兼容性说明；
- 用户可继续用自然语言修改方案；
- 用户随后明确说“按这个生成”“开始生成”“直接出图”时，使用当前对话中已确认的方案执行。

否定或暂缓表达优先于执行词。例如“先讨论怎么生成，不要出图”必须判定为只讨论，而不是因为包含“生成”而执行。

### 问答与歧义

“为什么”“怎么设计”“适合什么”“可以吗”以及以问号结束的咨询默认只回答，不自动生成。只有出现明确执行表达且没有讨论/否定表达时才授权直接生成。

## 已有节点选择卡

选择卡只保留两个操作：

1. **修改后生成**：用本次需求更新当前节点的提示词和已明确参数，然后执行该节点。
2. **新建并生成**：保留当前节点不变，用本次需求新建节点并执行生成。

删除“直接再生成”。原样重跑不再作为本次新需求的默认分支；用户如果确实需要原样重跑，可以直接说“保持这个节点的提示词和参数，再生成一次”，Agent 按明确执行请求处理。

## 实现边界

本次只修改 Canvas Agent：

- 直接生图授权和讨论否决规则；
- Agent 工具调用防线；
- 已有节点选择卡及对应操作；
- Agent 能力说明和测试。

不修改：

- 手动画布节点的生成按钮与参数控件；
- 画布缩放、虚拟化、连线、存储与图片加载；
- 图片模型路由、代理策略和供应商返回尺寸判断；
- 已完成的分辨率兼容自动调整行为。

## 数据流与防线

1. 用户消息先由本地意图规则分类为“明确执行”“明确讨论”或“普通问答”。
2. 明确执行时，创建一次直接生图授权；明确讨论和普通问答不创建付费授权。
3. Agent 模型仍负责组织自然语言回复和选择工具。
4. 工具执行层再次检查本轮意图；讨论状态下即使模型误发付费生图工具，也必须拒绝执行并返回可继续对话的结果。
5. 用户从讨论切换为“按这个生成”时，新的一轮按明确执行重新分类并正常授权。

这形成“提示模型正确选择 + 执行层不可越过”的双层保护，不依赖单次模型判断。

## 用户提示

讨论状态不增加弹窗或模式开关。Agent 用普通对话说明当前仅在整理方案，例如：

> 我先不生成。建议使用 9:16、2K，并采用以下提示词……

明确执行时不展示额外确认；如果命中已有节点，只有两项节点处理选择。

## 测试与验收

自动化测试必须覆盖：

- “我想要一张桃子图片”获得一次直接生图授权；
- “直接生成一张桃子图片”获得一次直接生图授权；
- “先讨论怎么生成桃子图片，不要出图”没有付费授权；
- 讨论状态下模型误发付费生图工具时，执行层不产生图片请求；
- 讨论后新一轮“按这个生成”可获得直接生图授权；
- 已有节点选择卡恰好只有“修改后生成”和“新建并生成”；
- “修改后生成”更新当前节点并只执行一次；
- “新建并生成”保留当前节点、新建节点并只执行一次；
- 选择过程不会多发付费请求，也不会出现第二次参数确认；
- 现有 Agent 生图分辨率、故障切换和完整项目检查继续通过。

真实浏览器回归至少验证选择卡按钮数量、按钮文案、节点保留/复用结果以及图片请求次数。
