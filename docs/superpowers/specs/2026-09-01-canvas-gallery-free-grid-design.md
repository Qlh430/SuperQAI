# 画布图集自由网格设计

## 目标

让画布图集由容器尺寸而不是图片数量驱动布局：用户可自由横向、竖向或同时调整图集大小，所有图片按稳定顺序自动重排、等比缩放且完整显示。

## 已确认的交互规则

- 图片顺序是唯一的内容顺序；图集不再把“1 列自动排序”“3 列自动排序”作为固定布局偏好。
- 横向拖宽时，根据可用宽度和最小缩略图尺寸增加列数；图片按顺序从左到右、从上到下重新填充。
- 竖向拖高时，增加可容纳行数；新增图片继续使用当前列数填满当前行，再从下一行开始。
- 追加图片没有空间时，只向下扩展图集以增加一行，不因为追加图片自动向右扩展。
- 容器缩小时，缩略图可缩小到最小尺寸；达到最小尺寸后，容器不能再缩小，确保全部图片始终可见，不引入内部滚动或裁切。
- 图集支持单行与单列。横竖同时拖动时，按当前宽高重新计算行列并保持图片顺序。
- 图片保持原始宽高比，以 `object-fit: contain` 完整显示；图格、图片与图片之间保留清晰但克制的间隙。
- 已连接成员的黄色输出点仍以图片实际边缘为锚点；连接线继续使用实际 DOM 几何位置，因此在图集重排或缩放后保持正确连接。

## 布局模型

图集持久化保存节点宽度、高度和成员数组顺序，不再持久化派生的 `columns`。

渲染时：

1. 从节点外框尺寸扣除标题栏、页脚与内边距，得到成员可用宽高。
2. 以最小缩略图宽度、最小缩略图高度和固定间隙计算可用列数与可用行数，均至少为 1。
3. 按成员数量与可用列数计算需要的行数。若当前高度不足以容纳所需行数，向下扩展节点至刚好容纳完整最后一行的最小高度。
4. 以可用列数进行稳定的行优先布局：成员索引 `0..n` 依次放入每一行的左至右单元格。
5. 单元格在不低于最小缩略图限制下跟随容器尺寸变化；图片在单元格内等比完整显示，不裁切。

横向拖动改变列数并触发稳定重排；竖向拖动优先改变可用行数和单元格高度。若某次横向缩小导致所需行数增加，节点自动向下扩容而不是丢失、遮挡或裁切图片。

## 数据与迁移

- 现有 `galleryContainer.columns` 被视为旧布局提示，不再写入新的节点状态。
- 已保存的旧图集加载后立即以当前节点尺寸与成员顺序计算新网格；图片内容、成员 ID、连接端点和连接数据保持不变。
- 任何自动扩容都同步更新节点高度，并和用户手动调整尺寸一样参与保存与撤销记录。

## 调整尺寸行为

- 图集使用现有右下角调整手柄，但处理逻辑改为同时接受宽和高变化。
- 拖动中实时重排；若拖动方向导致最小缩略图约束触发，则把对应尺寸钳制到所需最小值。
- 松开后将最终宽高保存为一次可撤销的节点尺寸操作。
- 重排和尺寸变化后请求连接线重新渲染；成员输出点通过其真实屏幕位置参与连线计算。

## 验收标准

1. 只有一张图时，用户可把图集调整为横向、纵向或近方形，图片始终完整显示。
2. 多张图横向拉宽会增加列数，且成员顺序不变。
3. 追加图片按行优先规则填充当前行，满行后图集只向下增加一行。
4. 图集可以成为单列或单行；缩小时不出现内部滚动、裁切或空白图片边框。
5. 小于最小缩略图可承载尺寸的拖动会被限制。
6. 已连接成员在重排、缩放和悬浮时，黄色端点与虚线始终贴合。
7. 图集尺寸变化、自动扩容和连接渲染不会破坏成员连线、删除连线或撤销操作。

## 测试策略

- 为尺寸到网格的计算编写纯函数测试：单图、单行、单列、横向增列、纵向增行、最小尺寸钳制及追加后向下扩容。
- 为成员顺序编写测试，确保重排不改变成员数组顺序或现有成员连接端点。
- 为节点尺寸处理编写交互测试，验证横、竖、双向拖动都会更新尺寸并触发连接重绘。
- 运行现有图集容器操作测试和全量 `npm run check`，防止影响收纳、拖出、连线及持久化。
