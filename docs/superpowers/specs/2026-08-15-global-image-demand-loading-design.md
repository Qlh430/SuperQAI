# 全站图片按需加载与画布流畅度优化设计

日期：2026-08-15

## 背景

网站目前在创建画布节点和渲染历史列表时，会立即把原图地址赋给大量 `<img>`。项目输出目录中存在单张 30–60MB 的图片；高分辨率图片解码后的内存占用还会远高于文件体积。画布打开、历史面板渲染、缩放和平移时，多张原图同时下载、解码和参与合成，导致明显卡顿。

画布滚轮事件还会同步更新 DOM 变换，并通过通用保存入口反复序列化整个画布和记录撤销快照。图片越多、画布数据越大，这部分重复工作越明显。

## 目标

- 未进入视口、未打开的面板和未主动查看的图片不得提前加载原图。
- 画布图片先显示缩略图，只有在画布缩放达到 160% 且停止操作 300ms 后才为可见图片加载原图。
- 图片缩小或离开画布视口后恢复缩略图，降低持续解码和合成压力。
- 在线生图历史、统一历史、画布历史、图集历史、引用缩略图和聊天图片等列表默认只使用缩略图。
- 点击历史缩略图后，原图只加载到用户主动打开的主查看区或编辑区。
- 取消无限画布内图片节点、图集封面和图集历史项的单独全屏预览入口；在线生图及网站其他主查看区的预览能力保留。
- 缩放、平移和图片质量切换不阻塞节点拖动、连线、表单输入、下载、遮罩、裁剪和生成流程。
- 新旧画布及历史数据都能兼容，不要求一次性迁移全部图片。

## 非目标

- 不把现有 DOM 画布重写为 Canvas、WebGL 或其他渲染器。
- 不改变原图文件、下载地址、生成接口输入或画布连接的数据语义。
- 不在启动时批量扫描或批量生成全部旧图片的缩略图。
- 不删除或压缩用户的原图。
- 不取消在线生图、高清放大、扩图、换鞋等主工作区的主动预览功能。

## 总体架构

### 1. 图片资源描述

保留现有 `src`、`savedUrl`、`imageSrc` 等字段作为原图唯一来源，不把缩略图误用于下载、编辑或 API 请求。

运行时通过统一图片资源描述器补充：

```js
{
  originalUrl: "/output/example.png",
  thumbnailUrl: "/output/thumbnails/<stable-key>.webp",
  width: 4096,
  height: 4096,
  state: "idle | thumbnail | original | error"
}
```

缩略图映射由独立注册表按原图地址去重。相同原图在画布、历史记录、引用图和聊天中出现时只生成一份缩略图，不要求在每份历史 JSON 中复制地址。已有数据无需结构迁移；缺少映射时按需补生成。

### 2. 缩略图规格与存储

- 缩略图最长边为 768px，输出为 WebP，质量约 0.76。
- 原图尺寸不超过 1600px 且文件体积不超过约 1MB 时可直接标记为轻量资源，不额外生成缩略图。
- 缩略图统一保存在 `output/thumbnails/`，文件名由规范化原图地址生成稳定键，避免重复。
- 注册表保存在 `data/image-thumbnails.json`，仅记录原图地址、缩略图地址、宽高和更新时间。
- 新图片在导入或生成完成后进入后台单并发队列；浏览器空闲时生成，不阻塞结果展示。
- 旧图片只在对应节点或历史卡片接近可见区域时入队，不在打开网站或画布时集中处理。
- 删除原图时允许同步移除注册表项和对应缩略图；无法确认原图已删除时保留缩略图，避免影响其他引用。

缩略图在浏览器侧使用 `createImageBitmap` 的目标尺寸解码和 `OffscreenCanvas` 生成，优先在 Worker 中执行；不支持 Worker/OffscreenCanvas 时，在 `requestIdleCallback` 或定时回退中一次处理一张。生成后的 WebP Blob 通过专用接口保存。该实现避免引入体积较大的原生图像处理依赖，并保持便携版可用。

### 3. 统一延迟图片控制器

新增统一延迟图片控制器，负责普通页面列表和画布两类场景：

- 普通页面使用 `IntersectionObserver`，只给视口附近约 300px 范围内的图片设置缩略图地址。
- 离开视口一段短暂缓冲时间后清空 `src`，避免快速往返滚动造成请求抖动，同时释放长期解码压力。
- 图片元素只保存 `data-original-src` 和资源状态，初始不设置原图 `src`。
- 历史面板未打开或 DOM 已移除时，取消尚未开始的缩略图任务。
- 主查看区、编辑器、下载和生成请求通过明确的“需要原图”接口取得原图地址，不依赖缩略图元素当前显示的 `src`。

### 4. 画布图片质量控制器

画布不逐项读取 `getBoundingClientRect()` 来判断可见性，而是根据画布的 `x`、`y`、`scale` 和节点保存的坐标、尺寸计算可见画布矩形。所有可见性更新通过单个 `requestAnimationFrame` 合并。

质量状态规则：

1. 节点在视口外：显示轻量占位并清空图片 `src`。
2. 节点进入带缓冲的视口：解析或生成缩略图，显示缩略图。
3. 画布缩放达到 `1.6`：启动 300ms 细节模式计时。
4. 计时期间继续缩放或平移：重新计时，不加载原图。
5. 计时结束时节点仍可见：按“选中或指针附近优先、其余可见节点随后”的顺序加载原图，并限制原图并发数。
6. 缩放低于阈值或节点离开视口：切回缩略图；若缩略图仍未生成则显示占位。

节点的几何尺寸和宽高比不随图片质量切换，避免加载时布局跳动。缩略图和原图使用相同 `object-fit` 规则。

### 5. 画布缩放与保存性能

- 滚轮和触控板事件只更新待处理的变换状态，由下一动画帧统一写入 DOM。
- 画布视口变化使用独立的轻量保存调度器；缩放期间不反复序列化所有节点，也不为每个滚轮事件生成撤销快照。
- 滚轮停止约 250–300ms 后保存一次最终视口状态。
- 平移在指针抬起后保存一次；视口变换不进入内容编辑的撤销栈。
- 图片质量切换属于运行时显示状态，不写入画布撤销历史，也不触发画布保存。
- 连线位于同一变换平面时不因每个滚轮事件重复重算；节点尺寸真正变化或图片比例首次确定时才安排连线更新。

## 各页面加载行为

### 无限画布

- 普通图片节点、生成结果、图集当前封面、图集历史、引用缩略图和画布历史封面全部接入统一资源控制器。
- 点击普通图片节点只执行选择、拖动和现有右键操作，不打开 lightbox。
- 图集封面点击保留选择/拖动语义，不打开 lightbox。
- 图集历史项点击只切换活动图片；移除独立“放大预览”按钮。
- 双击上传节点继续替换图片；右键下载、裁剪和遮罩继续使用原图。

### 在线生图历史

- 历史栏只创建轻量卡片，卡片图片在接近滚动视口时显示缩略图。
- 点击卡片后恢复提示词并在主结果区加载该记录的原图；卡片自身仍保持缩略图。
- 管理、勾选和删除模式不会触发原图加载。

### 统一历史与画布历史

- 统一历史记录和画布封面最多加载其当前可见的缩略图。
- 点击画布记录只恢复画布；恢复后由画布可见性规则决定加载哪些缩略图或原图。
- 点击高清放大、扩图、换鞋等记录时，只有被打开的主工作区加载原图。

### 聊天与引用图片

- 历史聊天中的消息图片使用缩略图；点击后主动打开原图预览。
- 画布连接引用、LLM 图片小卡、H3 参考图等仅显示缩略图，但其数据输出继续传递原图 URL。
- 用户刚刚选择的输入预览和正在编辑的图片属于明确使用状态，可以加载原图。

### 主查看区和编辑器

- 新生成结果、用户点击打开的历史结果、lightbox、裁剪、遮罩和扩图编辑器属于明确查看或编辑状态，允许加载原图。
- 关闭主查看区或 lightbox 时清理原图元素的 `src` 和临时 Object URL。
- 下载操作直接下载原图，不要求先把原图解码到 `<img>`。

## 数据流

### 新图片

1. 上传或生成流程获得原图 URL。
2. 原图立即用于当前明确打开的结果区或编辑流程。
3. 后台单并发队列在浏览器空闲时生成 768px WebP。
4. 专用接口将缩略图保存到 `output/thumbnails/` 并更新注册表。
5. 所有已观察该原图的缩略图元素收到资源更新并切换到新缩略图。

### 旧图片

1. 节点或历史卡片进入视口附近。
2. 控制器查询内存缓存和缩略图注册表。
3. 有缩略图时直接显示；没有时显示占位并进入低优先级单并发生成队列。旧图片首次生成缩略图需要读取一次原图数据，但只会在卡片或节点已经接近可见区域后发生，并且不会把原图挂到页面图片元素中。
4. 生成完成后更新注册表和当前仍可见的消费者。
5. 用户在生成完成前主动点击查看时，主查看区可直接加载原图；缩略图任务继续或根据生命周期取消。

### 画布细节模式

1. 画布变化通过动画帧更新变换和可见节点集合。
2. `scale < 1.6` 时只请求缩略图。
3. `scale >= 1.6` 且 300ms 无变化时，将可见图片加入原图优先队列。
4. 原图加载完成后仅替换显示资源，不改节点数据。
5. 缩小或移出视口后恢复缩略图或占位。

## 错误和边界处理

- 缩略图生成失败时记录失败时间并退避重试，防止每次滚动重复失败。
- 跨域原图无法由浏览器安全转换时，历史卡片使用占位；用户主动打开时仍使用原图 URL。
- 原图加载失败时保留缩略图并显示轻量错误标记，不让节点尺寸塌陷。
- 缩略图文件缺失但注册表仍存在时清除失效映射并允许重新生成。
- 快速滚动、快速缩放或切换工具时，未开始的任务取消；正在执行的单任务完成后若已无消费者，只更新缓存而不修改已销毁的 DOM。
- 多处同时请求同一原图缩略图时合并为一个 Promise，避免重复生成。
- Data URL 和 Blob URL 资源不永久写入注册表；可持久化的本地输出 URL 优先生成持久缩略图。
- 页面隐藏或切到其他工具时停止细节模式计时，不继续加载画布原图。
- 不用缩略图 URL执行下载、裁剪、遮罩、生成请求或连接输出。

## 测试设计

### 纯规则测试

- 画布可见矩形和节点相交判断。
- `scale` 阈值、300ms 稳定计时和质量状态转换。
- 原图、缩略图和占位之间的回退规则。
- 相同原图缩略图请求去重、失败退避和单并发队列。
- 小图跳过缩略图生成的判定。

### 静态回归检查

- 画布图片渲染函数不再直接把原图赋给默认 `<img src>`。
- 历史列表和画布历史不再输出原图 `<img src="...">`。
- 画布图片和图集预览事件已移除，其他页面的 `openPreview` 保留。
- 滚轮处理不再为每个事件调用通用 `scheduleCanvasSave()`。
- 原图 URL仍用于下载、编辑、API 请求和序列化。

### 服务端测试

- 缩略图保存接口只接受受限大小的 WebP/JPEG Blob。
- 输出路径限制在 `output/thumbnails/`，拒绝路径穿越。
- 注册表损坏时安全回退为空注册表。
- 相同原图地址得到稳定键，重复保存覆盖或复用同一缩略图。
- 静态服务正确返回缩略图 MIME 和长期缓存头。

### 浏览器行为验证

- 打开已有缩略图的大量图片画布，初始网络记录中没有原图请求，只有可见缩略图请求。
- 缺少缩略图的旧资源只在节点或卡片接近可见区域后读取一次原图数据生成缩略图，生成队列保持单并发；视口外旧资源不产生请求。
- 画布缩放到 159% 不加载原图；达到 160% 后持续操作不加载；停止 300ms 后只加载可见原图。
- 缩小或移出视口后节点恢复缩略图，拖动、选择和连线保持正常。
- 打开图片历史时只有可见卡片加载或生成缩略图；滚动后按需处理后续缩略图；已有缩略图的记录在点击前不请求原图。
- 点击一条历史记录后只加载对应主查看区原图。
- 画布图片、图集封面和图集历史项不再打开单独预览；在线生图预览仍可用。
- 快速滚动和缩放过程中没有持续堆积的图片任务或明显长任务。

## 验收标准

1. 未打开、未进入视口或未主动查看的图片不请求原图。
2. 大量图片画布恢复后可立即平移和缩放，不等待全部原图解码。
3. 画布 160%/300ms 细节规则准确，缩小或离开视口后恢复缩略图。
4. 所有历史列表先加载缩略图，点击后才在主查看区加载原图。
5. 同一原图只生成一份缩略图，后台生成单并发且不阻塞交互。
6. 画布图片节点不再触发单独预览，其他工作区主动预览不受影响。
7. 下载、裁剪、遮罩、连接、生成和保存始终使用原图地址。
8. 旧画布和旧历史无需批量迁移即可逐步获得缩略图。
9. 自动检查、语法检查和浏览器关键路径验证全部通过。
