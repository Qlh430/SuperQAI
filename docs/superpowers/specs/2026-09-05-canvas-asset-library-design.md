# 无限画布资产库与共享精选设计

## 目标

在无限画布内部增加 DX OS 风格的资产库，让用户能够浏览、搜索、预览并把图片、视频和音频拖入画布；同时提供“共享精选”和“与我共享”，供局域网账号发现和复用他人主动共享的优质素材。

资产库不是第二套文件系统。AI OS 的文件/资源层仍然是唯一事实来源，资产库只提供面向画布的媒体索引、筛选、项目引用、共享、点赞和收藏视图。

## DX OS 参考结论

对 `F:\DXOS-Portable-0.2.0-win-x64` 当前运行时的 `PhotosApp-DyfWQUz5.js`、文件应用与媒体应用进行检查后，确认其稳定性的核心不是额外复制素材，而是复用项目文件：

- 相册应用递归扫描桌面和项目位置中的文件节点，只把图片、视频整理成媒体记录。
- “图库、最近项目、图片、视频、我的相簿”是同一批文件的不同筛选视图；相簿由文件夹派生。
- 素材卡片拖动时传递文件 ID、名称、MIME 和原始文件 URL，而不是重新上传二进制内容。
- 图片编辑、网格切片和视频工作流的结果重新保存到项目文件夹，然后自动进入资产索引。
- 其他应用消费同一个服务端资产；服务器资产和仅浏览器本地素材有明确区分。

AI OS 将采用这套“一个文件、多个视图、按 ID 引用”的逻辑，但沿用现有账号、项目、画布、资源共享和 `/output` 媒体存储。

## 已确认的产品边界

### 资产库与桌面文件的区别

- 桌面文件/共享文件应用负责通用文件管理：归属、重命名、共享、删除和打开。
- 画布资产库只展示可插入画布的图片、视频和音频，并提供项目、媒体类型、最近使用、共享和收藏筛选。
- 两个入口读取同一条 `resources` 记录和同一个实际文件，不维护两份二进制文件。
- 在资产库导入文件时，文件进入 AI OS 文件/资源层；资产库只立即显示该资源。
- 从资产库拖入画布只新增画布节点和项目引用，不复制原文件。

### 第一版范围

资产库包含以下主入口：

1. **我的资产**：当前账号拥有的全部图片、视频和音频。
2. **当前项目**：被当前项目任意画布引用的资产。
3. **共享精选**：所有者主动发布为局域网所有账号可见的媒体资源。
4. **与我共享**：其他用户通过“指定人”共享给当前账号的媒体资源。
5. **我的收藏**：当前账号收藏且仍有访问权限的媒体资源。

每个入口支持搜索，以及“全部、图片、视频、音频”类型筛选。共享精选支持点赞数、点赞和收藏；第一版不根据点赞自动公开素材，也不实现自动排行榜。

### 不在本轮范围内

- 建立与桌面文件并行的第二套文件夹树或重复文件仓库。
- AI 自动评选或自动发布共享精选。
- 跨主机、互联网公开链接、匿名访问和素材市场。
- 复杂标签体系、AI 语义检索、素材版本树和批量编辑器。
- 把已有 `/output` 目录中的孤立文件全部自动归属给某个用户；只索引已有资源记录和后续经认证产生的媒体。
- 本轮不重写现有 `/output` 静态媒体传输机制；资产目录和操作权限由服务端账号校验，媒体内容路由的全面鉴权属于系统文件层的独立加固工作。

## 交互设计

### 入口与布局

无限画布顶部工具栏新增“资产库”按钮。点击后在画布右侧打开可收起的资产面板；面板属于画布窗口，跟随 AI OS 的浅色/深色主题和 75%—175% 系统缩放。

面板结构：

- 顶部：标题、当前项目名称、关闭按钮。
- 搜索区：名称搜索、导入素材按钮。
- 范围导航：我的资产、当前项目、共享精选、与我共享、我的收藏，并显示数量。
- 类型筛选：全部、图片、视频、音频。
- 内容区：响应式缩略图网格、加载状态、空状态、错误重试和分页加载。

资产卡片展示缩略图/媒体占位、名称、所有者、媒体类型、更新时间；共享精选额外展示点赞数和当前用户的点赞/收藏状态。

### 插入画布

- 双击资产卡片：在当前视口中心插入。
- 拖动资产卡片到画布：在释放位置插入。
- 拖动数据使用 AI OS 自有 MIME `application/x-ai-os-asset`，载荷只包含 `assetId`。
- 画布根据服务端返回的 `kind` 创建现有图片、视频或音频节点。
- 节点保存 `assetId` 与资源记录中的稳定媒体 URL；不得把二进制内容写进画布数据库。
- 插入成功后，为资源与当前项目、当前画布写入使用关联，并更新最近使用时间。

### 导入、共享、点赞与收藏

- 导入按钮复用现有认证媒体上传，支持图片、视频和音频；成功响应必须返回规范化资产摘要。
- 自有资产菜单提供“仅自己、共享给所有人、共享给指定人”。“共享给所有人”即发布到共享精选。
- 共享给指定人复用现有用户目录与 `shares/share_members` 权限模型。
- 只有所有者和超级管理员可以下架共享精选；普通用户不能修改或删除他人的资源。
- 点赞只影响共享精选的社会化排序信息，不改变访问权限。
- 收藏是当前用户的私人书签，不复制资源；资源失去访问权限后不再出现在收藏列表。

## 数据模型

### 复用 `resources` 与 `shares`

媒体资产继续使用现有 `resources` 表作为规范记录：

```text
type          image | video | audio
owner_user_id 文件所有者
workspace_id  首次产生时所在项目，可为空
title         展示名称
storage_path  受管文件路径，可为空
ref_type      output_media
ref_id        稳定媒体 URL（现有数据继续使用 /output/...）
metadata_json { url, filename, mimeType, size, source, thumbnailUrl }
```

可见范围继续复用 `shares`：

- 无 share 或 `private`：仅自己。
- `all`：共享精选。
- `users`：与我共享。
- 本功能只创建 `read` 权限的媒体分享；现有通用资源能力仍可保存其他权限。

音频必须规范化为 `type = audio`，不再按通用 `file` 注册。历史 `file` 资源若 `metadata.mimeType` 以 `audio/` 开头，资产查询时按音频兼容读取，后续更新时迁移为 `audio`。

### 项目使用关联

新增 `asset_project_links`：

```text
resource_id   TEXT NOT NULL REFERENCES resources(id) ON DELETE CASCADE
project_id    TEXT NOT NULL REFERENCES canvas_projects(id) ON DELETE CASCADE
board_id      TEXT NOT NULL DEFAULT ''
last_used_at  TEXT NOT NULL
created_at    TEXT NOT NULL
PRIMARY KEY (resource_id, project_id, board_id)
```

它只描述“该项目/画布使用了这个资源”，不拥有文件。当前项目视图按 `project_id` 去重返回资源。

### 点赞与收藏

新增：

```text
asset_likes(user_id, resource_id, created_at)
asset_favorites(user_id, resource_id, created_at)
```

两表均以 `(user_id, resource_id)` 为主键，并在资源或用户删除时级联删除。点赞只能作用于当前可访问且处于 `all` 共享状态的媒体；收藏允许任何当前可访问媒体。

## 服务端与权限

新增独立 `asset-library-service.js`，负责媒体识别、范围查询、项目使用记录、共享精选、点赞和收藏，不把这些规则继续堆入 `server.js`。

### 查询接口

```text
GET /api/assets?scope=mine|project|public|shared|favorites
                &projectId=<id>&kind=all|image|video|audio
                &search=<text>&cursor=<opaque>&limit=<1..100>
GET /api/assets/:id
```

返回的资产摘要至少包含：

```json
{
  "id": "resource-id",
  "name": "示例.png",
  "kind": "image",
  "mimeType": "image/png",
  "url": "/output/example.png",
  "thumbnailUrl": "/api/image-thumbnails?...",
  "owner": { "id": "user-id", "displayName": "用户" },
  "mine": true,
  "visibility": "private",
  "projectIds": ["project-id"],
  "liked": false,
  "likeCount": 0,
  "favorited": false,
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601"
}
```

所有范围必须在 SQL/服务层按当前认证用户过滤；前端隐藏卡片不是权限控制。

### 写接口

```text
POST   /api/assets/import                  二进制媒体上传，可带 projectId/boardId
POST   /api/assets/:id/use                 { projectId, boardId }
PATCH  /api/assets/:id/share               { visibility: private|all|users, userIds: [] }
PUT    /api/assets/:id/like
DELETE /api/assets/:id/like
PUT    /api/assets/:id/favorite
DELETE /api/assets/:id/favorite
```

- 导入接口校验 MIME、大小、项目所有权并复用现有安全文件名和分片上传规则；大文件仍走现有分片上传路径，完成后登记同一资源。
- 分享写入复用资源访问服务；只有所有者可以修改，超级管理员只具有下架 `all` 共享的管理能力，不接管文件所有权。
- `/api/assets/:id/use` 要求调用者能够读取资源，并且目标项目/画布属于当前账号；共享素材可以被自己的项目引用。
- 删除实际文件仍由文件/资源管理入口负责。删除时必须先检查画布引用；资产面板第一版只提供“移出收藏、下架共享”，不直接删除实体文件。

### 现有上传和生成结果兼容

- `registerSavedMedia` 统一识别 image、video、audio，并保存 MIME、URL、文件名和来源。
- 现有上传响应增加 `asset` 字段，但保留 `url/filename/mimeType`，避免破坏旧调用者。
- 画布保存或插入资产时调用使用关联接口，使当前项目视图无需扫描整个画布数据库。
- 旧画布节点没有 `assetId` 时继续按 URL 正常显示；当资产库遇到同一 `ref_type/ref_id` 资源时可在再次插入或保存时补齐引用，不批量重写旧节点。

## 一致性与失败处理

- 同一个 `ref_type + ref_id` 只对应一个 `resources` 行，重复登记必须幂等。
- 插入节点成功但使用关联失败时保留节点并显示非阻断提示；下次保存或再次打开可重试登记。
- 资源已下架、删除或权限被撤销时，资产查询接口不再返回，用户不能通过资产库建立新引用；已有旧画布节点继续遵循当前 `/output` 兼容行为。
- 搜索、筛选和分页变化使用请求序号或 `AbortController`，旧响应不得覆盖新结果。
- 点赞、收藏使用幂等 PUT/DELETE；重复操作不重复计数。
- 共享精选下架后，其他账号不能再从资产库把它插入新画布；已有引用不被破坏性移除。

## 测试与验收

### 数据与服务测试

- 数据库迁移可重复运行，原账号、项目、资源和分享数据不丢失。
- 我的资产、当前项目、共享精选、与我共享、收藏五种范围互不越权。
- 图片、视频、音频类型识别正确；历史音频 `file` 兼容读取。
- 项目使用关联幂等；点赞和收藏的 PUT/DELETE 幂等且计数正确。
- 普通用户不能发布、下架或修改他人资产；指定用户之外的账号看不到指定分享。

### 浏览器验收

- 资产库按钮能打开和关闭右侧面板，面板不会破坏画布缩放、平移和节点操作。
- 上传图片、视频、音频后立即出现在“我的资产”和当前项目。
- 双击与拖放分别在视口中心和释放位置建立正确节点，且不会再次上传文件。
- 用户 A 发布共享精选后，用户 B 能看到、点赞、收藏并拖入自己的画布；用户 C 只在被指定共享时看到素材。
- 浅色、深色和 75%、100%、125%、150%、175% 缩放下布局均可操作。
- 刷新浏览器、切换账号和重新打开画布后，资产、共享、点赞、收藏和项目引用保持一致。

## 完成标准

只有在以下条件同时满足时才算完成：

1. 资产库与桌面文件/资源使用同一资源 ID 和实际文件，没有重复二进制副本。
2. 五个资产入口、三种媒体类型、搜索、导入、预览、拖放和双击插入可用。
3. 私有、所有人、指定人权限在服务端生效，共享精选不会自动泄露私有素材。
4. 点赞和收藏持久化且幂等，普通用户不能管理他人资源。
5. 现有画布、上传、生成、项目、共享、主题和系统缩放测试继续通过。
