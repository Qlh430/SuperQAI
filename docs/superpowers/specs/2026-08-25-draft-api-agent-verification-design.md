# 未保存 API 的 Agent 草稿验证

**日期：** 2026-08-25  
**状态：** 已确认，待实施

## 背景

当前“验证 Agent”按钮只发送 `providerId` 与 `modelId`。服务端随后从已保存的设置读取 API 地址、Key 和模型。因此刚填写、尚未保存的 API 接入虽然可以通过“实时概况”或“获取模型”请求访问，却无法进行 Agent 工具调用验证，并错误提示“未找到 API 接入”或“尚未保存 Key”。

用户需要先确认接口与模型可用，再决定是否保存；验证不应让草稿接入进入正式 Agent 或生图路由。

## 目标与非目标

### 目标

1. 未保存的 API 草稿可完成与已保存接入相同的 Agent 实测：文本响应与 `report_agent_probe` 工具调用；配置了识图能力时可选测识图。
2. 验证过程只使用请求内存中的地址、Key、模型和能力配置，不写入设置文件、监控历史、路由健康记录或正式候选池。
3. 验证成功时，界面明确显示“验证通过，尚未保存”；用户保存同一配置后，无需重复验证，直接进入可用候选池。
4. 保存前关闭设置、刷新页面、切换或修改地址/Key/模型时，草稿验证结果失效；不得保留明文 Key。
5. 已保存 API 的原有验证和故障切换行为不变。

### 非目标

- 不让未保存草稿接管聊天、Agent 或生图请求。
- 不把草稿 Key 写入本地设置、日志、监控数据或候选池接口。
- 不自动保存或自动启用通过验证的草稿。

## 方案

采用“临时草稿验证 + 保存时提升”方案。

### 1. 临时验证请求

前端验证时发送一个最小草稿快照：`providerId`、显示名称、是否启用、`baseUrl`、`apiKey`、当前模型及其能力、目标 `modelId`。现有已保存调用仍可只发送 ID；服务端对两种请求共用同一验证器。

服务端优先规范化并校验草稿：地址、Key、模型必须存在，模型必须属于请求的草稿模型列表。随后用草稿对象调用现有模型适配器和 `report_agent_probe`，不读取已保存 Provider 作为前提。

### 2. 临时结果与安全边界

服务端只在进程内缓存通过的草稿结果，缓存键由以下非敏感指纹组成：Provider ID、模型 ID、规范化地址及 Key 的不可逆摘要。缓存只保存能力、适配器、延迟、验证时间和指纹，不保存 Key。缓存 TTL 为 15 分钟，并在地址、Key 或模型变动时不匹配而自然失效。

草稿验证不可写入 `agentCapabilities`、路由健康、监控或设置文件；这样它不会在未保存时被任何自动路由使用。

### 3. 保存时提升

保存设置后，服务端为每个已保存模型计算同样的指纹。如果存在尚未过期的通过验证结果，则将结果写入正式能力登记，并使其在下一次候选池读取中出现；没有匹配结果时维持“待验证”。

这一步不重复请求上游模型，也不会将草稿的验证错误、失败次数或测速数据污染正式路由健康。

### 4. 界面与交互

- 验证按钮在草稿状态可点击，验证中保持当前局部加载态。
- 成功后模型行显示“已验证，未保存”，设置底部继续显示未保存提醒；同时在结果提示里说明“保存后加入 Agent 备用池”。
- 验证失败显示真实上游错误及失败分类，但不更改现有候选池。
- 保存成功后将匹配的 UI 验证状态更新为“Agent 已验证”，刷新候选池。
- 修改地址、Key、模型 ID 或能力时，清除该 Provider 的页面内草稿验证状态，避免错误沿用。

## 数据流

```text
填写草稿 API / 选择模型
        │
        ├── 点击验证 → POST 草稿快照 → 内存验证 → “已验证，未保存”
        │                                      └→ 不进入路由
        │
        └── 点击保存 → 写入设置 → 匹配草稿验证指纹 → 正式能力登记 → 候选池可用
```

## 错误处理

- 请求字段不完整：返回“请先填写 API 地址、Key 和模型”，而不是“未找到 API 接入”。
- 上游超时、认证、余额或工具不兼容：沿用现有标准错误分类；草稿保持可编辑、可再次验证。
- 进程重启或缓存过期：草稿验证不再可提升，用户可保存后再验证；不影响已保存模型。
- 保存失败：不提升、不更改候选池；页面保留当前草稿验证提示，直到刷新/修改/关闭。

## 验收与测试

1. 未保存草稿使用正确地址、Key、模型，可收到验证成功响应；服务端设置文件不发生变化。
2. 草稿验证请求中错误或缺失 Key 得到字段错误，不是“未找到 API 接入”。
3. 通过验证的未保存模型不会出现在 `GET /api/settings/agent-candidates` 的可用候选中。
4. 保存内容与草稿指纹一致后，模型无需再次上游请求即可成为已验证候选。
5. 修改地址、Key 或模型后，先前草稿验证不能提升到新配置。
6. 已保存 Provider 的验证、候选排序及故障切换回归测试通过。
