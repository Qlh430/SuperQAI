# 生成图集比例、叠层与历史拖拽设计

日期：2026-07-30

## 背景

生成图集当前存在四类问题：

1. 图集容器沿用固定媒体高度，并通过 `object-fit: cover` 填充，导致方图在横向节点中被裁成长图。
2. 后方叠层偏移和层数都不明显，用户难以识别这是包含多张结果的图集。
3. 历史入口体积偏大，数量徽标写死为紫色，没有跟随当前主题。
4. 历史结果虽然具备部分拖拽代码，但释放判定与“复制图片”的产品语义不稳定。

## 目标

- 图集封面始终按当前最上层图片的真实宽高比显示。
- 用户仍可通过调整节点宽度放大或缩小图集，高度随比例联动。
- 最多显示五个清晰可见的后方叠层。
- 封面区域兼顾“拖动整个图集节点”和“单击预览当前图片”。
- 历史入口小巧、主题化。
- 历史图片可拖到画布，创建独立图片节点副本。

## 非目标

- 不改变图片生成、删除和历史排序逻辑。
- 不改变图集对下游节点只输出当前最上层图片的规则。
- 不允许自由拉伸破坏当前图片比例。
- 从历史拖出的图片不覆盖已有图片节点。

## 交互设计

### 1. 图集比例与缩放

- 当前最上层图片加载完成后，读取其真实宽高 `naturalWidth / naturalHeight`。
- 图集媒体区域使用该比例作为 `aspect-ratio`。
- 节点宽度继续由用户控制；调整宽度时，媒体区域高度自动按比例变化。
- 切换历史图片为当前图片后，立即切换到新图片比例。
- 新生成图片成为当前图片时，同样更新比例。
- 图片尚未加载或无法读取尺寸时，暂时使用已有节点比例；不抖动到无效尺寸。
- 节点恢复时先使用保存数据和已有比例，图片加载完成后再校正。

### 2. 叠层表现

- 后方最多渲染五层，实际层数为 `min(历史图片数 - 1, 5)`。
- 每层向右下递增偏移，并使用轻微缩放、主题色混合描边和阴影。
- 叠层必须在横图、方图、竖图上都清晰可见，但不能遮挡连接点和关闭按钮。
- 当前封面始终位于最上层，所有后层仅用于表达数量，不接收单独交互。

### 3. 封面点击与节点拖动

- 在封面或叠层可见区域按下鼠标后记录起点。
- 移动距离超过约 `6px` 时进入节点拖动，移动整个“生成图集”节点。
- 未超过阈值并松开时，视为单击，打开当前最上层图片预览。
- 一旦进入拖动，本次手势不再触发预览。
- 拖动过程中保持现有画布吸附、连线刷新和保存机制。

### 4. 历史入口

- 入口缩小到约 `42px`，保持足够的点击区域。
- 使用符合语义的图片堆叠/历史图集图标。
- 数量徽标约 `18–20px`。
- 徽标背景使用当前主题的 `--accent`，文字使用主题对比色；边框和阴影通过主题色混合生成，不再写死紫色。
- 点击入口打开历史结果面板。

### 5. 历史结果面板

- 单击历史图片：设为当前最上层图片，并同步封面比例与下游输出。
- 点击放大按钮：只预览该图片，不切换当前图片。
- 点击下载按钮：下载该图片。
- 按住图片主体并拖动：显示半透明缩略图和复制指针。
- 拖到画布区域释放：始终创建一个新的独立图片节点，位置以释放点为中心。
- 拖到历史面板、图集节点或画布外释放：取消复制。
- 拖出操作不删除历史图片、不改变历史顺序、不改变当前最上层图片，也不覆盖释放点下方的已有节点。

## 数据与状态

- `galleryActiveImageId` 继续作为当前图片的唯一来源。
- 图片对象的已有宽高信息优先复用；缺失时由图片加载事件补全运行时比例。
- 当前比例不需要成为新的业务选择项，它由当前图片派生。
- 保存时继续保存节点宽度、当前图片 ID 和历史图片列表；高度由宽度与当前比例重建，避免保存错误裁切比例。

## 错误与边界处理

- 单图图集不显示后层，但仍支持单击预览和拖动节点。
- 超过六张图片时只显示五个后层，历史入口数量仍展示完整图片数。
- 删除当前图片后，回退图片成为当前图片，并更新比例。
- 图片加载失败时保留稳定占位尺寸，历史面板仍允许删除或切换其他有效图片。
- 触摸板轻微位移通过阈值过滤，避免误触发节点拖动。

## 验证标准

1. 方图、横图、竖图作为当前图片时，封面均无非预期裁切。
2. 改变图集宽度时，高度按当前图片比例同步变化。
3. 有六张及以上历史图片时，封面后可辨识五个叠层。
4. 单击封面打开预览；拖动封面只移动节点，不打开预览。
5. 历史入口尺寸明显小于当前实现，徽标随主题色变化。
6. 历史图片拖到画布后生成独立图片节点，原历史和当前图片保持不变。
7. 刷新或重新打开画布后，当前图片、历史顺序和封面比例正确恢复。
