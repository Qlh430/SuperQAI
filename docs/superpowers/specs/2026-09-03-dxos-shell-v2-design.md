# DX OS 风格桌面壳 V2 设计规格

- 日期：2026-09-03
- 状态：已由用户确认执行
- 依据：现有局域网 AI OS 规格、当前实现，以及对 DX OS 0.2.6 活跃运行时的只读审计

## 1. 目标

把当前“旧工作台外套桌面皮肤”的实现改造成真正由桌面状态驱动的应用系统。无限画布、生图、对话、文件、账户和设置都由统一应用注册表启动，拥有独立窗口生命周期；账户、SQLite、资源 ACL、备份、Electron 主机启动器和现有画布引擎继续复用。

## 2. 本阶段范围

1. 实现可测试的窗口管理内核：打开、聚焦、移动、缩放、最小化、最大化、恢复、关闭、层级、几何持久化和单实例复用。
2. 桌面由窗口状态渲染，不再通过 `selectLegacyTool()` 假装启动应用。
3. 应用注册清单描述名称、图标、角色、宿主、默认尺寸、是否多实例和生命周期钩子。
4. 现有无限画布、生图、对话通过 legacy DOM adapter 接入独立应用窗口；文件、账户、设置使用现有独立 DOM 视图。
5. 建立 sandbox iframe adapter 和受限 `postMessage`/`window.dx.invoke` 协议骨架，后续安装应用可使用；本阶段不强行把庞大的旧画布代码拆包。
6. 文件应用清楚区分“我的内容”和“与我共享”，保留已有按资源共享的权限模型。
7. 桌面采用克制的苹果风格：玻璃层次、柔和背景、交通灯、Dock、启动台、清楚的焦点和运行态反馈；不复制 DX OS 品牌资源。

## 3. 架构

```text
会话与权限
    ↓
AppRegistry ── manifest/role/adapter
    ↓
WindowManager ── state/geometry/z-order/persistence
    ↓
DesktopRenderer ── window chrome/dock/launchpad
    ↓
DOM Adapter（现有应用） | Iframe Adapter（后续应用）
    ↓
现有 HTTP API、SQLite、资源 ACL、共享、备份
```

窗口管理内核不直接访问业务 DOM；桌面渲染器订阅状态变化。业务应用不自行控制全局层级，只通过注册表生命周期钩子响应 `mount`、`activate`、`deactivate` 和 `unmount`。

## 4. 窗口行为

- 窗口首次打开按注册清单的默认尺寸居中，并以小幅级联偏移避免完全重叠。
- 点击窗口或 Dock 图标提升整个窗口到最前层；菜单栏显示当前焦点应用。
- 标题栏可拖动；四边和四角可缩放；拖动与缩放限制在可用桌面区域内。
- 双击标题栏在最大化与恢复之间切换。
- 最小化保留应用 DOM 和内部状态；关闭隐藏窗口但不销毁 legacy adapter，避免画布丢失未保存的界面状态。
- 小屏幕（宽度小于 860px）降级为单窗口全屏模式，禁用自由缩放。
- 几何状态按账号和应用 ID 保存到 `localStorage`，密码、Token 和业务数据不得写入其中。

## 5. 应用模型

注册项至少包含：

```js
{
  id,
  label,
  icon,
  roles,
  adapter: 'legacy-dom' | 'iframe',
  target,
  defaultSize: { width, height },
  minSize: { width, height },
  multiInstance,
  onActivate
}
```

legacy DOM adapter 负责把现有视图切换到对应业务工具，并将其置于窗口内容区，不再让桌面壳直接模拟任意工具点击。iframe adapter 只允许同源受控入口，使用 `sandbox="allow-scripts allow-forms"`；消息必须包含协议版本、请求 ID、动作和参数，宿主按应用白名单决定是否执行。

## 6. 数据和共享

本阶段沿用已有 `resources`、`shares`、`share_members` 表，因为它已具备 owner、所有账号、指定账号、口令和读/评/编/复制权限。文件应用提供三个稳定视图：我的内容、与我共享、全部可见；所有打开动作仍由服务端 `assertRead`/`assertWrite` 决定，前端过滤只用于展示。

未来如需要完全对齐 DX OS，可在其上增加“公共文件”和“部门文件”共享根，但不能削弱现有资源级 ACL。

## 7. 错误处理和安全

- 未登录时不挂载业务应用。
- 会话失效时统一关闭窗口并回到登录门。
- 不存在或无权限的应用不创建窗口。
- iframe 消息来源、窗口引用、动作白名单和参数尺寸都必须校验。
- 几何数据损坏时回退默认值，不能阻止桌面启动。
- 任何业务请求失败显示应用内提示，不使用原生 `alert`/`confirm`。

## 8. 验收标准

1. 可同时打开至少三个应用窗口，并正确聚焦、拖动、缩放、最小化、最大化和关闭。
2. 重新登录同一账号后恢复合理几何，不会恢复到屏幕外；不同账号不共用几何。
3. 无限画布最小化再恢复后仍保留当前画布界面状态。
4. 普通用户看不到账户管理应用，直接调用启动 API 也被拒绝。
5. 文件应用正确显示本人和被共享资源，共享设置仍经过现有服务端 ACL。
6. 小屏浏览器自动进入单窗口模式。
7. 原有账户、资源、备份、Electron 启动检查保持通过。
8. 代码不复制 DX OS 的实现或资源，只按审计得到的行为边界重新实现。
