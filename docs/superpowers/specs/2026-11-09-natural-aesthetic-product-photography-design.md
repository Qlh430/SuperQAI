# 自然美学产品摄影 Skill 设计规格

日期：2026-11-09

## 目标

在 AI OS 当前开发工作台中，通过现有私人 Skill 安装器接入「自然美学产品摄影」。Skill 根据真实产品素材、用户目标和专业摄影方法形成可修改的策划方案；用户确认方案后，Agent 在当前画布创建一个可编辑、连接真实产品素材、尚未执行的图片生成节点。

不新增通用 Skill 系统、独立 Agent、画布执行器、知识库平台或视觉工作台。不运行付费图片生成，不公开发布 Skill，不修改现有用户画布、素材或其他 Skill。

## 当前实现与缺口

- `host-sources/app/skill-registry.js` 与 `skill-import-manager.js` 已提供私人 Skill 目录、清单和经过安全校验的导入/确认流程。Skill 必须通过当前账户的正常安装 API 导入，不得写入系统或公共目录来模拟私人安装。
- `canvas-agent-ui.js` 已支持选中 Skill 后空输入启动、选中素材的视觉输入、需求卡、取消以及付费调用确认。
- `canvas-agent-capabilities.js` 与 `script-before-save-bridge.js` 已有 `request_design_brief`，但当前仅接受海报流程；前端确认后的续跑指令也固定为 `poster-design`。
- Agent 对话通过画布会话 API 保存，并在宿主端检查画布读取/写入权限；尚未保存待确认的设计方案和其来源素材版本。因此刷新后不能可靠恢复待确认决策。
- 已有 `read_skill_reference`、`create_image_node`、画布连接与布局能力，可承载 Skill 文档读取和用户确认后的工作流创建。

## 方案选择

1. **只写 Skill 文档**：实现范围最小，但不能解决海报专属的需求卡续跑与确认状态恢复，且方案确认约束无法可靠落到现有交互。拒绝。
2. **扩展现有设计确认协议并新增标准私人 Skill**：复用 Agent、需求卡、现有会话 API、参考文档工具及画布节点工具；只为新流程泛化必要字段和恢复状态。推荐。
3. **新增独立策划 UI、Agent 执行器和案例检索服务**：控制力更高，但重复已有能力并扩大权限、存储及维护范围。拒绝。

## Skill 内容与案例

Skill 以标准根 `SKILL.md` 描述触发条件、产品保真约束、视觉分析、需求收集、案例选择、方案结构、确认前后边界、节点创建及失败处理。专业摄影方法和案例索引置于该 Skill 自己的 `references/` 中；可选 `agent.skill.json` 只声明现有执行协议需要的阶段和工具，不改变其他 Skill 的格式或行为。

初始案例库限定为四个原创的文字策划方法案例，覆盖透明/反光材质、护肤包装、饰品及小家电等不同摄影问题。每项包含稳定案例编号、适用品类、构图、光线、材质与色彩方法、受众/用途、建议保留/替换/规避项及明确来源。案例描述作为 AI OS 原创策划方法，不冒充真实拍摄、真实生成效果或外部作者作品；没有合法可用预览时不添加伪造图片，并在 UI 中如实呈现无预览状态。匹配以产品特征、材质、用途、受众和用户审美作语义比较，输出实际引用的编号与适配理由；无适配案例时引用通用方法，不伪造案例证据。

## 交互与数据流

1. 用户选择私人 Skill 并提供画布图片；空文本可启动。Agent 通过现有多模态视觉输入读取真实图片。文件名、节点名和用户描述只能作为辅助上下文，不能代替视觉读取。视觉能力不可用或素材不可读时，明确暂停并说明原因。
2. Agent 分析产品类别、用途、轮廓结构、颜色、材质纹理、可见标识、创意依据及必须保持的细节。不能辨明的品牌、材质、结构明确标为待核实。
3. 只询问会改变摄影方案的缺失条件。已知答案不重复询问；非关键项给出默认建议。输出包含专业方向、案例/方法依据、保留/替换/规避合同、创意简述、完整生图提示词、产品特定负面约束及质量核验清单。
4. 复用 `request_design_brief` 的需求卡，将其由海报专属泛化为显式流程类型。需求卡需支持补充必要信息、确认方案、以自然语言修改方案和取消；修改会回到策划阶段，旧方案不再作为确认结果。现有 poster 流程的字段、文案和续跑行为必须保持兼容。
5. 需求卡、策划文本和用户确认需通过既有画布 Agent 会话 API 保存。扩展会话规范的可选 `pendingWorkflow` 字段，限长并白名单化，包含 `workflow`、`skillId`、`boardId`、状态、分析/方案文本、来源节点标识及可验证的来源版本指纹、更新时间。不得保存图片字节、鉴权凭据或跨账户数据。保存和恢复继续经过画布资源的账户 ACL、读写权限及 revision 冲突保护。
6. 待确认状态绑定账户授权下的画布、Skill 和来源版本。素材删除、替换、版本变化、画布切换或 Skill 不可用时，禁止使用旧分析创建节点，并要求重新读取/确认。恢复时先核对来源节点仍存在且版本一致，再恢复卡片；旧格式会话按无待确认任务兼容处理。
7. 只有用户显式确认当前策划后，才续跑同一个 Skill 并允许创建工作流。Agent 复用原素材节点，使用既有 `create_image_node` 写入完整提示词、当前可支持且实际选定的模型参数，并建立真实素材连接；布局由已有节点创建逻辑处理。不得创建重复素材节点、方案文字节点或假生成结果。
8. 方案确认不等于付费生成授权。新节点保留未执行/等待生成状态，所有生成调用仍经过原有付费审批；本轮测试不调用生图服务。任务状态在 Agent 现有状态/会话记录中区分等待信息、分析/策划、等待确认、工作流已创建、等待生成、生成中、成功、失败、取消。

## 边界与失败处理

- 无产品素材：不启动实质分析或建图，要求用户选择/上传素材。
- 视觉读取失败：不得按文件名猜产品；提供重新选择或用户补充信息路径，不宣称分析成功。
- 缺少可匹配案例：使用 Skill 中的通用摄影方法，标注无案例匹配。
- 参数不受模型支持：不伪造参数；说明限制并使用用户明确接受的可用选项，或等待用户调整。
- 用户修改方向、文案、比例或案例：重新生成策划并要求确认；不沿用过期提示词。
- 用户取消：清除待确认状态，不创建节点，不把取消报告为任务成功。
- 保存冲突或恢复校验失败：保留当前可见信息，显示中文错误/重新确认要求，不覆盖其他窗口的会话数据。

## 实施边界

- Skill 内容作为私人安装包，通过现有导入预览/确认流程安装到当前账户；不得放入系统 Skill 或公共精选库。
- 只扩展需求确认工具的类型和呈现、续跑及持久化；复用既有工具权限、资源 ACL、画布连接和生成审批。
- 若某项界面/宿主文件属于独立部署组件，按 `ownership.json` 和 `component-deploy.mjs` 归属选择部署；不得通过 33200 代理刷新谎称后端已加载。
- 自动化测试使用隔离数据和 mock provider；不得读写现有私人画布/素材，也不得调用任何付费图像模型。
- 当前 `status:workbench` 显示开发工作台一致且无待同步文件。真实多模态能力、登录账户下的私人安装及浏览器画布持久化，需分别与 mock 测试报告，不得混为一谈。
- 不打包正式版本、不发布 GitHub、不清理工作区、不重启 AI OS.exe 或 3199 后端。若后端代码必须同步，先按项目规范备份并报告待正常重启状态。

## 验收矩阵

1. **信息不足**：隔离素材由真实多模态输入分析；只询问缺失且影响策划的信息，展示可编辑需求卡。
2. **信息完整**：给出用途、受众、比例及风格后不重复询问，进入具体策划。
3. **不同产品匹配**：至少用两种不同产品特征验证案例引用、推荐理由、提示词、产品特定约束与核验项会随输入变化；至少报告案例总数及每项来源。
4. **方案修改**：先给自然场景方向，再改为极简影棚；确认前后策划和提示词更新，旧方向不混入最终节点。
5. **真实画布构建**：隔离画布仅复用真实产品节点，创建单个可编辑生图节点，包含完整提示词、真实参数/能力限制和真实输入连线；保存并刷新恢复。节点不执行。
6. **失败与安全**：覆盖图片不可读、无案例匹配、参数不支持、用户取消、会话保存冲突、素材指纹变化与 ACL 拒绝；确认不创建无效节点、不泄漏跨账户素材、不调用付费生成。
7. **回归**：既有 poster 需求卡/续跑、私人与公共 Skill 权限、Agent 空输入选择 Skill、素材引用和节点保存恢复不退化。

自动化/mock 结果只证明协议与界面逻辑，不证明模型真的看懂产品。任何真实视觉理解、当前账户安装或已登录浏览器画布验收必须单列实际证据；无法进行时明确列为未验证。
