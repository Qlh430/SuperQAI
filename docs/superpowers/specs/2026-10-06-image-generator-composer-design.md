# 图片生成节点下方操作区

用户已确认：上方只显示图片预览或占位；选中后在正下方展开提示词、参考图、模型/尺寸参数和生成按钮；取消选中收起，输入内容保留。

## 范围与设计

仅图片生成（generator）节点调整。保留现有 400×400 Flora 主体、48px 外部标题带、连接端口与共享工具栏。主体呈现空图片占位或真实生成结果，提示词和参数不再占据主体。

操作面板锚定选中节点下方，中间保留 16px 间距，桌面最大宽度 960px，随可用视口收窄；控件保持屏幕空间可读尺寸，画布缩放和平移时重新定位。接近底边时限高并允许面板内滚动，保持提示词和生成动作可访问；不通过把面板移动到右侧改变用户确认的结构。

面板使用 Neon 语义令牌与 Flora 16px 圆角、统一间距、中文文字和 Lucide 图标。上部为已有参考图及添加入口，中部为提示词，下部为模型、尺寸、清晰度、现有模型高级参数、费用提示与生成动作。高级参数按需显示。用户参考图不新增未有的模型选项、装饰按钮或编造价格。

## 行为与状态

- 只有单选当前 generator 时显示。取消选中、切换节点或删除节点收起；多选不显示某个任意节点的面板。关闭面板不清空数据，也不停止进行中的任务。
- 提示词、参数、参考区、原运行按钮均复用原 DOM，仍属于所属节点的后代，因此既有保存与 API 查询选择器保持有效。
- 面板内点击、拖选文字、下拉菜单与滚动不会移动节点或画布。节点主体仍可拖动，面板随之定位。
- 添加参考图使用宿主上传函数，建立真实素材节点并连接到生成节点；上传失败显示中文错误。已有连接的参考图继续显示和被生成逻辑使用。
- 费用来自既有运行按钮中的价格提示；加载、禁用、运行状态与中文错误保持原行为。提交只触发一次现有按钮点击，不另造 API 链路。
- 生成结果更新到上方预览，面板输入不丢失。参考区和结果区保持不同 DOM 归属，避免既有结果更新函数把图片移动进参考区。

## 架构与约束

新建专用 `flora-generator-composer.js` 管理面板组合、显示状态、定位和清理；`flora-node-shell.js` 接入 mount/sync/unmount。样式位于既有 flora-node-shell.css，宿主适配仅扩展已有 script-before-save-bridge.js 的上传事件处理。控件留在节点内部，不使用 localStorage 存放画布或生成数据。

复用现有 DOM 优于克隆控件：只有一份值与事件来源，已有序列化和模型切换继续生效。克隆会引入双向同步和重复提交风险，故不采用。

部署仅通过 deploy.mjs，先构建并备份。保留现有未提交工作，不纳入无关文件或用户运行数据。

## 验收

先写浏览器失败回归，再实现。检查选择显示、取消隐藏、两节点草稿隔离、多选、输入不拖节点、模型/尺寸保留、参考图、单次提交、中文失败、结果预览、重渲染与清理。390、768、1440、1728 宽度及 0.5/1/1.75 缩放，默认、悬停、选中、焦点、全屏和移动状态截图；Better Design 检查真实 DOM 间距及文字。构建后指定脚本部署，运行 acceptance.cjs 与视频、音频回归。测试使用模拟业务 API，真实登录生成、权限和保存仍需已有用户会话验收。
