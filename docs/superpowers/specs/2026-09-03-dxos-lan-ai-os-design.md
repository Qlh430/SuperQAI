# 局域网 AI 操作系统设计规格

- 日期：2026-09-03
- 状态：已确认总体方向，作为 MVP 实施依据
- 目标项目：当前本地 AI Studio（Node.js 服务 + 原生 HTML/CSS/JS）
- 参考产品：`F:\DXOS-Portable-0.2.0-win-x64` 的 DX OS 便携版

## 1. 背景与目标

当前项目已经具备在线生图、GPT 对话、历史记录、无限画布、生成任务恢复、供应商监控和便携打包等能力，但入口仍是单一的 AI Studio 网页，数据默认以本机共享文件保存，没有最终用户账户和资源级权限。

目标是把它演进为一个“局域网个人 AI 工作操作系统”：一台 Windows 电脑作为可信主机，其他电脑、平板或手机通过浏览器登录；每个账号拥有独立的画布、文件和聊天数据，同时可按权限共享资源。界面采用参考图中的苹果风格桌面、Dock、浮动窗口和应用式导航。

### 1.1 MVP 必须解决的问题

1. 主机启动后可以稳定地为局域网提供网页访问。
2. 超级管理员可以创建、停用、重置普通账号。
3. 普通账号登录后只能看到自己的私有资源和授权共享资源。
4. 无限画布、生图、GPT 对话能在同一个桌面壳中作为独立应用打开。
5. 文件、画布和聊天记录具有统一的私有/共享/回收站语义。
6. 关键数据可以备份和恢复，服务异常可诊断。

### 1.2 非目标

- MVP 不实现多台主机之间的同步。
- MVP 不实现 GPU 工作节点和跨机器任务调度。
- MVP 不实现公开互联网部署、在线注册、计费和复杂组织架构。
- MVP 不直接复制 DX OS 的源代码或品牌资产，只借鉴其桌面式交互和视觉语言。

## 2. 产品形态与部署拓扑

### 2.1 推荐部署

一台 Windows 主机运行 Node.js API 和静态资源服务，监听局域网地址（默认 `0.0.0.0:3199`）。其他设备使用浏览器访问 `http://<主机局域网 IP>:3199`。

```text
┌─────────────────────────────┐
│  局域网浏览器客户端           │
│  桌面壳 / 应用窗口 / 登录      │
└──────────────┬──────────────┘
               │ HTTP + Cookie Session
┌──────────────▼──────────────┐
│  AI OS 主机服务               │
│  账户 · 权限 · 文件 · 画布     │
│  聊天 · 任务 · 应用 · 备份      │
└──────────────┬──────────────┘
               │ 本地文件 + SQLite
┌──────────────▼──────────────┐
│  主机数据目录                 │
│  数据库 / 用户文件 / 输出媒体  │
└─────────────────────────────┘
```

### 2.2 为什么不采用每台电脑独立运行

独立运行会把账号、共享权限、文件同步、版本升级、API Key 和冲突处理分散到每台电脑，难以保证“每个人只看得到授权数据”。中心主机可以把权限判断和文件访问放在同一处，管理员只需维护一个实例；缺点是主机离线时整个系统暂时不可用，因此需要自动启动、健康检查和定时备份来降低风险。

### 2.3 后续扩展：GPU 工作节点

未来可以在另一台有 GPU 的电脑上运行一个工作节点服务。主机保留账号、权限和文件，生成任务通过队列发给工作节点，结果再回写主机。该能力不进入 MVP，避免在账户和共享基础尚未稳定时引入分布式调度复杂度。

## 3. 系统分层

### 3.1 桌面壳（Desktop Shell）

- 顶部系统栏：当前应用名、返回/主页、网络状态、时间和用户菜单。
- 桌面背景：浅蓝到浅紫的柔和渐变，可切换浅色/深色主题。
- Dock：固定常用应用，显示运行状态和未读提示。
- 窗口管理：打开、最小化、最大化、关闭、聚焦、层级和响应式布局。
- 应用启动器：展示已安装应用、最近使用和管理员可用应用。
- 登录门：未认证时只渲染登录页，不加载任何用户资源。

### 3.2 系统服务（System Services）

- `AuthService`：登录、登出、会话续期、密码修改、会话撤销。
- `AccountService`：超级管理员创建/编辑/停用普通账号，重置临时密码。
- `AuthorizationService`：资源所有权、共享范围和操作权限检查。
- `ResourceService`：文件、画布、聊天、媒体和生成任务的统一资源元数据。
- `ShareService`：创建、修改、撤销共享，生成口令访问凭证。
- `AppRegistry`：内置应用清单、应用权限和启动入口。
- `JobService`：统一生成任务状态、错误、取消和恢复。
- `BackupService`：数据快照、媒体清单和恢复校验。
- `AuditService`：记录登录、权限变更、共享变更和危险删除操作。

### 3.3 应用层

MVP 内置应用：

1. 无限画布：迁移现有 canvas 引擎和 Agent 能力。
2. 在线生图：迁移现有图片生成与参考图编辑流程。
3. GPT 对话：迁移现有聊天和历史记录。
4. 文件：统一浏览用户文件和授权共享文件。
5. 账户管理：超级管理员管理账号；普通账号只看个人资料和会话。
6. 设置：主题、主机状态、模型/供应商配置（按权限显示）。

后续应用：图片库、视频、音乐、技能管理、ComfyUI、应用市场、开发者工作室。

## 4. 账户、角色与登录

### 4.1 MVP 角色

- `superadmin`：系统唯一的最高权限账号。可管理账号、系统设置、共享策略、备份和全部审计日志。
- `user`：普通账号。只能访问自己的私有资源和被授权资源，可使用管理员开放的应用。

未来可增加 `admin`、部门管理员和只读访客，但不在 MVP 中引入多级继承权限。

### 4.2 账号字段

```text
users
  id                UUID
  username          唯一登录名
  display_name      显示名称
  avatar_path       可选头像
  role              superadmin | user
  status            active | disabled
  password_hash     MVP 使用 Node.js `crypto.scrypt` 加盐哈希，后续可升级 Argon2id
  must_change_password  首次登录是否必须改密
  created_by        创建者 user id
  created_at
  updated_at
  last_login_at
```

普通账号由超级管理员创建，初始使用临时密码；首次登录必须修改密码。MVP 不开放公开注册，避免局域网内任何人自行创建账号。

### 4.3 会话安全

- 使用服务端会话表和随机不可预测的 session token。
- Token 仅存于 `HttpOnly`、`SameSite=Lax` Cookie，生产环境支持 `Secure`。
- 登录接口限流；连续失败触发短暂锁定。
- 登出、停用账号、重置密码时撤销相关会话。
- 所有写操作使用 CSRF 防护或同源校验。
- API 响应不得返回密码哈希、供应商密钥或其他账号敏感字段。

## 5. 数据隔离与共享模型

### 5.1 资源统一模型

所有用户内容都抽象成资源，至少包含：

```text
resources
  id
  type              file | canvas | chat | image | video | job
  owner_user_id
  workspace_id      用户个人空间或共享空间
  title
  storage_path      大文件的相对路径
  metadata_json
  created_at
  updated_at
  deleted_at        软删除时间
```

现有 `image-history.json`、`chat-history.json`、`canvas.db` 和 `output/` 不会在第一步强制重写；会通过适配层补充 `owner_user_id`，再逐步迁移到统一资源索引。

### 5.2 默认可见性

- 新建资源默认“仅自己”。
- 服务端每次查询先得到当前用户身份，再应用所有权/共享授权过滤。
- 不能通过猜测文件路径、画布 ID 或历史记录 ID 绕过过滤。
- 超级管理员可以审计和恢复资源，但普通情况下仍在界面中按资源权限操作。

### 5.3 共享设置

```text
shares
  id
  resource_id
  created_by
  visibility       private | all | users | password
  permission       read | comment | edit | copy
  password_hash    仅 password 模式使用
  expires_at       可选
  created_at
  updated_at

share_members
  share_id
  user_id
```

界面提供四个选项：仅自己、所有人、指定人、口令。指定人模式通过账号选择器授权；口令模式只保存哈希，不保存明文。共享默认只读，资源所有者可以提升为可评论、可编辑或可复制。

### 5.4 文件存储

建议将数据根目录固定为可迁移目录，例如：

```text
data/
├── system.db
├── users/<user-id>/files/
├── users/<user-id>/canvas/
├── users/<user-id>/chat/
├── shared/
├── output/
├── backups/
└── logs/
```

路径只由服务端根据资源 ID 生成，客户端不能提交任意文件系统路径。大文件下载必须经过权限检查；缩略图可以缓存，但缓存也要绑定资源权限。

## 6. 应用注册与窗口通信

### 6.1 应用清单

每个应用使用统一清单描述：

```json
{
  "id": "canvas",
  "name": "无限画布",
  "subtitle": "素材、提示词与生成结果",
  "entry": "canvas",
  "icon": "...",
  "permissions": ["resource.canvas.read", "resource.canvas.write"],
  "enabledFor": ["superadmin", "user"]
}
```

MVP 应用先以内置模块实现，仍通过注册表启动，以便后续替换为外部应用包。应用不能自行绕过系统服务访问磁盘；必须通过经过授权的 API 访问资源。

### 6.2 现有功能迁移

- 保留现有 `server.js` 的图片、聊天、画布和任务接口，先增加认证中间层。
- 将 `index.html` 的当前功能导航拆成桌面壳、应用注册表和应用视图。
- 现有 canvas 相关模块（分页、虚拟化、Agent、媒体管理）作为“无限画布应用”的内部依赖继续使用。
- 先用兼容适配层给旧历史数据补上默认 owner，再进行显式用户归属迁移。

## 7. API 设计（MVP）

### 7.1 认证与账户

```text
POST   /api/auth/login
POST   /api/auth/logout
GET    /api/auth/session
POST   /api/auth/change-password

GET    /api/admin/users
POST   /api/admin/users
PATCH  /api/admin/users/:id
POST   /api/admin/users/:id/reset-password
POST   /api/admin/users/:id/revoke-sessions
```

### 7.2 资源与共享

```text
GET    /api/resources?type=file|canvas|chat
GET    /api/resources/:id
PATCH  /api/resources/:id
DELETE /api/resources/:id

GET    /api/shares
POST   /api/resources/:id/shares
PATCH  /api/shares/:id
DELETE /api/shares/:id
POST   /api/shares/:id/unlock
```

### 7.3 应用和系统状态

```text
GET    /api/apps
GET    /api/system/health
GET    /api/system/backup/status
POST   /api/admin/backup
```

所有现有图片、聊天、画布和 ComfyUI 接口在迁移期保留原路径，但必须从认证上下文取得 `user_id`，禁止由客户端直接传入可伪造的 owner。

## 8. 苹果风格界面规范

### 8.1 视觉方向

- 背景：低对比度蓝紫渐变，必要时叠加轻微噪点。
- 窗口：大圆角、半透明浅色面板、柔和阴影和细边框。
- 控件：蓝色主操作、胶囊按钮、分段选择器、浅色输入框。
- 排版：中文优先，标题清晰，次级信息使用灰蓝色。
- 动效：窗口打开/关闭、Dock 呼吸提示、加载进度使用短时缓动，不使用持续晃动。

### 8.2 响应式策略

- 桌面浏览器：多窗口 + Dock。
- 平板：单窗口模式，保留侧栏和应用切换。
- 手机：单列应用视图，底部导航替代 Dock。
- 所有关键操作必须同时支持键盘和触控。

### 8.3 账户管理界面

参考截图的窗口布局：左侧账号列表和搜索，右侧显示用户头像、角色、状态、密码状态和资源额度；底部提供添加、停用和删除入口。删除默认进入回收站或要求超级管理员二次确认。

### 8.4 共享设置界面

资源卡片上提供“共享”按钮，弹窗显示“仅自己 / 所有人 / 指定人 / 口令”，并显示当前权限、成员和到期时间。共享变更写入审计日志。

## 9. 自动启动、局域网和运维

### 9.1 主机桌面应用与自动启动

主机电脑需要有一个正式的 Windows 桌面应用入口，例如 `AI OS Host.exe`，而不是要求用户记住命令行或手动运行 `server.js`。该应用负责启动/停止本地 Node 服务，并提供主机状态和设置入口；局域网内的其他设备仍然通过浏览器访问同一服务。

主机应用必须提供：

- 桌面快捷方式和开始菜单图标。
- 双击图标后启动主机服务，检查健康状态，并打开本机 AI OS 窗口。
- 可选“开机自动启动”开关，默认由超级管理员在主机设置中控制。
- 启动后可最小化到系统托盘，托盘菜单显示服务状态、局域网访问地址、打开系统和退出服务。
- 关闭窗口时默认最小化到托盘；选择“退出”才停止主机服务。
- 服务异常时显示错误原因，并支持重新启动服务。

MVP 的自动启动实现优先采用 Windows 启动项或任务计划程序，由桌面应用创建/移除对应启动项；关闭开关后不再随 Windows 启动，但用户仍可随时双击桌面图标手动启动。稳定版可以将 Node 服务进一步包装成 Windows 服务，以获得更强的崩溃自动重启能力，但不改变桌面应用的使用方式。

推荐的启动流程：

```text
Windows 开机
    ↓（已开启自动启动）
AI OS Host.exe
    ↓
启动/检查 server.js
    ↓
打开主机窗口 + 注册系统托盘
    ↓
监听 0.0.0.0:3199，局域网设备可访问
```

### 9.2 网络边界

- 默认只面向局域网，不开放公网端口。
- Windows 防火墙只允许专用网络访问应用端口。
- 页面显示主机在线状态和当前地址。
- 管理员可以关闭 LAN 访问，仅保留本机访问。

### 9.3 备份与恢复

- 每日或手动生成数据库 + 用户元数据快照。
- 媒体文件按清单校验，备份支持排除缓存和临时上传目录。
- 恢复前创建当前数据快照，恢复后校验数据库完整性和媒体引用。
- 备份操作只有超级管理员可执行，并记录审计日志。

## 10. 错误处理与可观测性

- 登录失败、无权限、资源不存在分别返回明确的 401/403/404。
- 共享口令错误不泄露资源是否存在。
- 生成任务失败时保留任务记录和错误分类，可重试或取消。
- 页面提供主机健康、磁盘空间、任务队列和最近错误摘要。
- 服务器日志按天滚动，不记录密码、Cookie 或完整 API Key。

## 11. 测试策略

### 11.1 单元与服务测试

- 密码哈希、登录限流、会话撤销。
- 所有权和共享矩阵：私有、全员、指定用户、口令、只读/编辑。
- 管理员与普通用户的 API 权限。
- 软删除、回收站和恢复。
- 旧数据迁移和重复执行安全性。

### 11.2 浏览器测试

- 登录 → 打开桌面 → 启动无限画布 → 保存资源。
- 用户 A 创建资源并共享给用户 B；B 可见，C 不可见。
- 共享改为撤销后，B 的旧页面也不能继续读取。
- 管理员创建账号、重置临时密码、停用账号。
- 移动端和桌面端的窗口/导航降级。

### 11.3 运维测试

- 主机重启后服务自动启动。
- 局域网另一设备能访问，公网地址不可访问。
- 备份恢复后账户、共享、画布和媒体引用一致。
- 生成任务中途重启后的恢复行为。

## 12. 分阶段实施路线

### Phase 0：基础准备

- 建立系统规格、数据迁移策略和测试夹具。
- 抽离认证/授权边界，但暂不改变现有应用视觉。

### Phase 1：MVP 核心（本次第一轮）

- `system.db` 和账户/会话表。
- 超级管理员初始化、普通账号管理、登录和登出。
- 资源 owner 过滤和最小共享模型。
- 苹果风格桌面壳和应用注册表。
- 无限画布作为第一个内置应用。
- 现有生图和 GPT 对话接入用户上下文。
- Windows 自动启动脚本、健康检查和基础备份。

### Phase 2：协作增强

- 文件应用、图片库、回收站和更完整共享权限。
- 账号分组、应用权限、审计日志界面。
- 备份计划、恢复向导、磁盘空间和任务监控。

### Phase 3：平台化

- ComfyUI 和视频/音乐应用。
- 应用包导入、插件权限和应用市场。
- GPU 工作节点和任务队列。
- 可选的远程访问、HTTPS 和多主机同步。

## 13. 关键决策与验收标准

### 已确认决策

- 部署：中心主机 + 局域网浏览器。
- 账号：超级管理员分配普通账号，不开放公开注册。
- 隔离：每个账号独立画布、文件、聊天空间。
- 共享：仅自己、所有人、指定人、口令四种范围。
- 风格：苹果风格桌面壳和浮动应用窗口。
- MVP：不包含 GPU 工作节点。

### MVP 验收

1. 新设备在局域网访问主机地址可以看到登录页。
2. 超级管理员可以创建普通账号，普通账号首次登录必须改密码。
3. 两个普通账号互相看不到对方的私有画布、文件和聊天。
4. 一个账号共享资源后，授权账号可以按权限访问，未授权账号无法访问。
5. 无限画布、生图和 GPT 对话可以从同一个桌面进入，并且新数据归属当前账号。
6. 主机桌面存在 AI OS Host 图标；双击后可启动系统并打开主机窗口。
7. 开启自动启动后，Windows 重启可以自动启动主机应用；关闭开关后不再自动启动，但仍可通过桌面图标手动启动。
8. 主机重启后服务自动恢复，管理员可以生成并验证备份。

这份规格是后续实施计划、代码评审和上下文恢复的依据；如果实现中出现新需求，应先更新本文件的决策或阶段边界，再修改代码。
