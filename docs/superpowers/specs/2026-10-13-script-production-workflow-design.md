# 脚本生成节点与四步制作工作台设计

日期：2026-10-13

本文件记录已确认的产品方向与实施规则。用户已授权实现可操作版本；准备操作可调用文本模型，图片和视频仍由用户明确发送后生成。

## 已确认范围

1. “脚本生成”是无限画布右键菜单“生成节点”下的一个新节点。
2. 新节点复用现有 Flora 节点壳体、标题、端口、选中态、工具栏、操作区及 Neon 语义令牌，交互参考用户图2。
3. 脚本节点可输入故事或完整剧本，运行文本模型后产出结构化分镜表，并创建人物组、场景组、道具组。
4. 打开脚本节点进入“脚本 / 资产 / 合成故事板 / 视频生成”四步工作台。
5. 资产阶段仅准备现有图片生成节点及其提示词、参考素材和关联信息。用户可逐个查看、修改、生成，也可明确执行全部或选中项。
6. 故事板阶段依赖前面真实生成或上传的资产图，准备的也是现有图片生成节点。其提示词和参考图预填，等待用户最后点击发送才生成图片。
7. 首版在同一全屏工作台增加第四步“视频生成”，准备视频节点后支持用户单项或批量发送生成。前面步骤完成后不得自动运行视频；配音、字幕和成片合并暂不纳入本轮。
8. 用户图中的视觉只供功能与交互参考，产品使用现有 Neon/Flora 风格、简体中文和官方组件。

## 执行边界

整个工作流区分“准备”和“执行”，不得用一个状态含混表示。

| 用户动作 | 允许发生 | 不得自动发生 |
| --- | --- | --- |
| 发送剧本 | 调用所选文本模型分析，生成分镜及资产提示词，创建组、待生成资产节点和连线 | 资产生图、故事板生图、视频生成 |
| 浏览、修改资产 | 保存设定、提示词、引用及参数 | 发送图片生成请求 |
| 单项资产发送 | 只运行该资产图片节点 | 运行其他资产或下游故事板 |
| 执行全部资产 / 选中资产 | 对本次明确选定范围排队生图 | 扩展为故事板或视频生成 |
| 准备故事板 | 通过 Skill 和文本模型整理提示词，绑定真实资产图片，创建待生成故事板图片节点 | 发送故事板图片生成请求 |
| 故事板发送 / 执行选中故事板 | 运行明确选定的故事板图片节点 | 自动创建并运行视频节点 |
| 第四步准备视频节点 | 预填镜头提示词、素材、参数及连线 | 发送视频生成请求 |
| 第四步单项发送 / 执行选中视频 / 执行全部待生成视频 | 对本次明确选定的视频节点排队生成 | 自动配音、加字幕或合并成片 |

用户点击图片或视频节点现有发送按钮，或工作台明确范围的批量生成按钮，就构成执行对应范围的授权，不额外叠加重复确认弹窗。页面打开、步骤切换、刷新、重连和上游完成事件均不得自动生图或生成视频。

四步 Skill 的默认权限只允许准备该步骤内容。真实图片及视频生成走明确的节点发送或用户选择的批量执行路径，不由模型根据“创建节点”推断“立即运行”。

## 画布与工作台关系

- 脚本节点是整个制作流程的入口和组织中心，保存原文、分镜及关联关系。
- 人物、场景、道具节点均使用已有图片生成节点，不另造一套资产生图器。
- 故事板节点同样使用已有图片生成节点，额外记录来源镜头及制作流程身份。
- 视频节点使用已有视频节点及其模型适配能力。
- 工作台显示同一份画布业务数据；在工作台编辑提示词与在画布节点编辑是同一次修改。
- 脚本到资产的连线表达来源；资产到故事板的引用必须指向具体生成节点和当前采用的真实图片。
- 业务来源连线与送给模型的图片参考需区分，不能把未出图节点或整份结构化剧本当成图片参考。
- 创建组与连线复用现有画布操作接口。相同流程与资产使用稳定 ID，重复准备更新对应节点，不增生重复组。
- 首次自动排列按来源在左、资产居中、故事板在右组织；后续修改保留用户调整过的位置和布局。

## 第一步：脚本

### 输入与全局设定

输入支持粘贴剧本、引用已有文本节点和上传现有文档支持的文件。完整剧本默认保留原剧情和对白；由想法扩写时显式进入创作模式。

全局设定包括画幅、风格描述与参考、目标时长、所选文本模型。未指定视频模型时，不将任何视频模型的上限写成剧本约束。

### 分镜表

字段包括：镜号、计划时长、场景引用、人物与服装引用、道具及状态引用、画面描述、景别与构图、人物调度、运镜、光线色调、对白及说话者、音效、静态图提示词、视频提示词。

默认显示常用字段，其他字段按需展开。支持逐镜编辑、新增、删除、排序、筛选和选中镜头重新整理。移动端以逐镜卡片显示。

资产引用使用实体 ID，并以 `@资产名` 显示。人物、场景、道具采用现有语义颜色加类型标识区分；点击可以查看资产、替换引用、定位画布节点。改名只改显示，不破坏引用。

原文事实与模型补充设定分开记录。矛盾、未明确外观或无法解析的引用给出可处理的中文提示，不静默改写原文。

分镜表通过结构校验后才批量写入画布。模型返回格式错误时给出可重试原因，不保存半截表格为成功结果。

## 第二步：资产

工作台按人物、场景、道具分栏，与画布上的分组对应。每个资产保留名称、设定、提示词、参考素材、出现镜号、生成历史、当前选用图及关联节点 ID。

### 全屏工作台中的操作位置与范围

- 第二步顶部是人物、场景、道具分类标签及各类数量，切换后只改变浏览内容。
- 正文为当前分类的资产卡片，可单项查看、编辑和生成，支持多选。
- 底部固定全局操作栏，包含图片模型、适用的画幅/分辨率/质量参数，以及“一键生成全部资产（N项）”。按钮位于打开脚本节点后的全屏工作台，不放在画布外层工具栏或脚本节点操作区。
- “全部资产”覆盖本流程三类中可执行的待生成资产，不随当前分类改变。显示总待生成数量及分类数量；不包含已成功资产、故事板或视频。
- 多选时提供“生成选中资产（N项）”，选中范围与全局范围明确区分。
- 全局参数作为批量默认值，单项明确设置优先；不可执行项显示原因，不静默忽略或伪报全部成功。
- 接受任务后显示批量进度和逐项状态。底部操作栏不遮挡最后一行卡片；移动端使用同一语义的紧凑排列和滚动留白。

进入本步时，资产是“待生成”状态。用户可以：

- 查看并编辑单项设定与提示词；
- 上传或引用已有图片；
- 在单个节点按发送；
- 执行全部待生成资产或执行选中资产；
- 只重试失败项，保留已成功结果。

人物发送前选择“角色四视图”或“角色人设图”。四视图布局定义为正面、侧面、背面、脸部特写；人设图重点展示人物整体、服装、配饰和细节。人物批量执行统一选择默认类型，已有单项设置优先，不逐人重复弹同一问题。

同一人物服装变化、同一道具明显外观变化可建立版本或状态；不把每次出现重复识别成新实体。

复用当前图片生成节点的模型选择、参考带、发送、停止等待、结果历史、下载与错误交互。工作台当前选用图与节点当前输出同步；不强加每张图额外审批步骤。

“执行全部”只覆盖这次展示的待生成资产范围。再次运行已有结果须明确选择重新生成，不因切换页面或下一步骤而重新发送。

## 第三步：合成故事板

本步的准备产物是待生成的图片生成节点，不是已经生成好的故事板图片。

准备时读取已保存分镜、全局设定及相关资产的当前选用图，整理适合图像模型的提示词，并按确定的顺序预填参考图。每个节点显示对应镜号、提示词、参考缩略图、模型、画幅和待生成状态，允许发送前修改。

组织模式支持不合并、每2镜、每3镜、自动分组。分组保留镜头 ID 和顺序。具体故事板画面版式属于可配置的提示词模板；不将参考图8的四列版式写成唯一规则。

缺少某镜必要资产图时，显示具体缺失项并阻止运行该节点；其他依赖齐全的节点可独立准备或执行。不能用空参考、占位图或随机图片替代缺失资产。

用户最后点击发送才调用图片模型。成功结果进入现有图片节点的历史，同时在工作台预览，并保留所用提示词及参考版本用于追溯。

上游选用图变化后，标记受影响故事板“参考已变化”，由用户决定更新引用或保留原版本，不自动重画。

## 第四步：视频生成

视频生成属于同一个脚本全屏工作台的第四步，无须返回画布才能批量操作。从已生成故事板准备视频节点，带入镜头提示词、来源镜号、相关资产及可用参考图，并建立连线。准备只创建和预填；用户在第四步单项发送或点击明确的批量生成按钮才执行。

- 正文按镜头顺序展示视频卡片，包含来源故事板、参考图、视频提示词、模型和参数，生成前均可查看和修改。
- 底部提供视频模型、其支持的生成方式与参数，以及“生成全部待生成视频（N项）”；多选时提供“生成选中视频（N项）”。
- 复用现有视频节点的任务、进度、结果、停止等待、失败重试与历史能力。工作台与画布共享同一节点，生成结果可预览和下载。
- 第三步完成只更新第四步可用素材，不自动调用视频接口。
- 缺少实际故事板图、参考不完整或模型不支持当前方式时，显示具体原因并阻止对应项发送，其他满足条件的项可单独执行。
- 默认按原镜头准备视频节点。多镜合并故事板须选择或提取对应画面；按故事板组生成一段多镜视频需要用户明确选择且模型支持，不能因图片拼版而默认合并剧情镜头。
- 首版交付独立视频片段，不自动配音、加字幕或合并成片。

展示拼版和视频实际参考需区分。整张多格故事板可供支持其语义的模型作为参考；若用户选择首帧或首尾帧模式，应明确选用或提取对应画面，不把多格拼版默认当作视频首帧。

计划镜头时长和模型实际生成时长分别保存。模型能力只约束生成任务的参数与打包，不倒推剧情镜头数量。

## Skill 分工

| Skill | 负责 | 输出 |
| --- | --- | --- |
| 剧本拆解与分镜 | 原文理解、叙事节奏、对白、镜头与实体引用 | 结构化分镜、资产清单、矛盾和建议设定 |
| 资产设定与提示词 | 角色身份与服装、场景布局、道具状态、风格一致性 | 图片节点可直接编辑的设定与提示词 |
| 故事板提示词与参考编排 | 将分镜转成静态故事板图要求，选择相关已生成资产 | 故事板图片节点的提示词、版式描述、参考映射 |
| 视频提示词与模型适配 | 读取分镜与真实故事板，整理动作、时间顺序、运镜及所选模型支持的引用方式 | 预填视频节点提示词、参考映射及有效参数，不执行生成 |

四者使用统一的实体、镜头、风格与版本契约，接入现有宿主 Skill 注册和文本模型选择体系。第四步按所选模型复用现有视频提示词适配规则。

模型只负责内容与引用候选，节点 ID、权限判断、结构校验、参考图解析、排队和画布操作由程序负责。程序不得把模型文字中的“运行全部”当成用户生成授权。

## 数据、状态与局部更新

- 原始剧本、分镜、资产、引用、任务和结果由宿主服务保存，不使用 localStorage 保存制作数据。
- 分镜、资产、节点都用稳定 ID 关联。显示镜号改变不改变实体身份。
- 准备状态与图片任务状态独立。准备可处于未准备、准备中、已准备、需要更新、准备失败；图片任务沿用待生成、排队、生成中、成功、失败的现有状态。
- 生成请求以用户选择的节点、提示词和参考版本构成一次任务快照。生成中编辑的新内容不能悄悄替换已发送内容。
- 更新上游只影响引用它的下游内容，保留人工修改字段、已有结果、历史及用户布局。重新分析展示变更范围后再替换相应人工内容。
- 批量执行采用现有任务能力和受控并发，单项失败不抹掉其他成功结果；重复点击与请求重试不重复创建节点或提交同一任务。
- 关闭工作台和刷新不取消宿主已接受任务，也不重新提交；恢复时读取真实任务状态。
- 创建、修改和运行节点都受当前账户及画布有效权限校验。只读共享不能发起生成或修改。

## 《穿越回来只为一件事》验收样例

- 人物：小林、古人；同事是可选项。老板只有消息对白，不默认生成人物图。
- 场景：办公室和休息区；多次办公室剧情共用资产。办公室原文标题“白天”与电脑时间23:48冲突，建议深夜设定，保留原文并给出确认项。
- 道具：电脑、手机、桶装泡面、金元宝、纸条。泡面可含打开和未开封两个状态。
- 原文明确的消息、纸条及片尾字幕准确保存为文本；需要精确视觉文字时使用后续文字覆盖或独立设计，不能把随机生图文字当作准确原文。
- 首次发送剧本后只出现分镜表、三类资产组、带提示词的待生成资产节点，没有图片请求。
- 资产批量执行后得到真实资产图，但故事板尚未运行。
- 准备故事板后仅出现带提示词和真实参考的待生成图片节点；用户单项或选中批量发送后才出图。
- 全屏工作台第二步的分类切换不改变底部“全部资产”的三类待生成范围。
- 第四步准备的视频节点有提示词、素材和连线，仍待用户执行；用户发送后才生成视频，画布与工作台显示同一结果。

## 实施拆分和验收

建议按同一产品契约分四段开发：

1. 脚本节点、结构化数据、第一步表格及资产节点准备；
2. 资产工作台、单项与批量执行、双向同步；
3. 故事板图片节点准备、用户发送与双向同步；
4. 视频生成工作台、节点准备、用户单项/批量执行及结果同步。

每段完成后继续下一段，保持首版范围。开发前将本草案定稿为实施计划。

验收除四宽度、无 pageerror/横向溢出和 Neon/Flora 状态一致性外，重点检查：准备动作产生0次图片/视频请求；单项运行只发送1项；资产“全部”位于全屏工作台且覆盖三类待生成项，视频“全部”只覆盖第四步待生成项；引用实际已生成图片；刷新不重复执行；重试不重复节点；失败提示中文；双向编辑一致；上游更新不自动重生成；保存、返回、撤销与权限有效。

改动运行时先备份，仅用 deploy.mjs 部署；先 build 再 acceptance，自动化服务用独立端口和临时数据，只结束自己进程。模拟 API 验收与真实账户、模型、画布业务验收分别报告；不得虚构 Better Design 动态审查结果。
