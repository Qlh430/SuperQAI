# 画布 Agent 直接生图闭环设计

日期：2026-08-24  
状态：已实施并通过专项、全量与浏览器闭环验证  
适用范围：画布 Agent 的生图意图识别、MCP 执行、模型选择、节点布局与结果验收

## 1. 背景与问题

当前 Agent 面对“生成一张苹果图片”这类明确生图需求时，只创建图片生成节点便结束。节点使用的坐标又把节点左上角放在视口中心，导致节点视觉上偏离窗口中央。图片模型由模型参数或画布下拉框决定，列表仅表示已经配置，不能保证对应服务此刻可用。

画布现有 `runCanvasImageEdit()` 已经具备成功后自动创建图集、连接生成节点并追加图片的能力，因此不需要让 LLM 手工拼接四个脆弱步骤。需要补齐的是明确的意图边界、一个高层 MCP 执行合同、可靠的模型解析和以真实结果为准的验收闭环。

补充验收发现两个恢复路径问题：页面首次加载模型候选失败后会一直保留空缓存；已有生成节点运行成功后，结果已经进入其连接图集，但 `run_canvas_node` 没有返回该图集信息，导致 Agent 再次调用 `update_gallery` 并误报“生成节点没有图片”。此外，Agent 在发现相关旧节点时不应直接运行并产生费用，而应先把视口定位到该节点，让用户决定复用、修改还是新建。

## 2. 用户可见目标

- 用户明确要求直接生图时，一次完成“创建生成节点、选择可用模型、执行生成、创建并填充图集”。
- 用户只是头脑风暴、询问建议或比较方案时，Agent 只讨论，不因谈到图片而自动产生费用。
- 用户在讨论后说“按第二个方案生成”“就按刚才的做”时，Agent 使用当前画布对话上下文直接执行，不重复询问已经明确的信息。
- Agent 新建的单节点或工作流默认出现在当前可见画布区域中央，不被右侧 Agent 面板遮挡。
- 图片模型由执行层自动选择，LLM 不猜测模型名；没有可用模型时不创建不可执行的空节点。
- 未指定模型时默认使用 `gpt-image-2`（image2）系列，并在所有已接入该模型的接口中选择最快且稳定的候选。
- 用户明确点名模型时只在该模型的接口中选择；指定模型不可用时停止并提示，不静默替换模型。
- 发现与当前需求相关的已有生成节点时，先将画布镜头定位到该节点并高亮，由用户选择“直接再生成、修改后生成、新建生成”。
- 只有图片真实返回并写入图集后，Agent 才报告完成。

## 3. 意图与授权边界

Agent 自动判断当前话语属于“讨论、准备、执行”中的哪一种，不要求用户切换模式。

### 3.1 讨论

示例：“苹果海报怎么做好看？”“我们先聊聊适合什么风格。”“比较一下写实和插画方向。”

行为：只对话和读取当前画布上下文，不创建节点，不运行生成，不产生费用。

### 3.2 准备

示例：“把刚才三个方向整理到画布。”“先建一个生图节点，我自己再调。”“把提示词写进节点，但先不要生成。”

行为：只执行用户明确要求的安全操作，可以创建或更新草稿节点，但不执行付费生成。

### 3.3 执行

示例：“直接生成一张苹果图片。”“帮我画一张 1:1 的产品图。”“就按第二个方向生成。”“创建完直接出图。”

行为：把这句话视为对本次明确数量和范围内生图的授权，直接进入完整生图闭环，不再弹出第二次确认。

以下情况仍需询问或确认：

- 用户没有给出数量且请求可能扩展为多张或批量生成；
- 请求同时包含多个付费变体，但数量不能从上下文可靠推断；
- 用户明确说“先别生成”“只讨论”“只建节点”；
- 删除、批量覆盖等其他高风险操作仍遵守既有确认规则。

“明确直接生图即本次授权”只覆盖当前画布、当前任务和可推断的明确生成数量，不跨画布、不跨任务保存，也不授权后续无关付费操作。本规则仅取代旧设计中“每次 `run_canvas_node` 都必须二次确认”的直接生图场景；其他付费操作保持原边界。

## 4. 推荐架构

采用“LLM 理解意图 + Skill 规定流程 + MCP 复合工具执行 + Broker 校验边界”的混合架构。

### 4.1 LLM 的职责

- 理解用户是在讨论、准备还是明确执行。
- 从本画布对话、选中节点和 `@` 引用中补全提示词、画幅和参考素材。
- 决定是否调用高层工具，但不选择具体服务商、不直接操作 DOM、不声称未验证的完成结果。

### 4.2 Skill 的职责

核心 Skill 增加直接生图规则：

1. 明确直接生图时优先调用高层工具，不拆成多个低层调用。
2. 讨论和准备阶段不得误触发高层付费工具。
3. 工具完成后依据结构化结果收尾；失败时保留已创建节点并说明可理解的未完成原因。

专业 Skill 仍可调用低层工具完成电商套图、海报等多节点流程；普通单次生图不必激活专业 Skill。

### 4.3 新增 MCP 复合工具

新增能力 ID `image.generate-to-gallery`，工具名 `generate_image_to_gallery`。输入保持最小：

```json
{
  "prompt": "完整图片提示词",
  "model": null,
  "size": null,
  "resolution": null,
  "reference_node_ids": [],
  "title": "生成图集"
}
```

`model` 只在用户明确指定模型时由 LLM 填写模型名或别名；默认传 `null`。LLM 不得指定服务商或接口，具体接口仍由确定性路由选择。工具内部顺序为：

1. 校验当前 `boardId + runId + callId` 和引用节点归属。
2. 若候选缓存为空或无法满足本次模型要求，自动重新加载一次图片候选。
3. 解析当前可用图片模型和兼容的尺寸、清晰度。
4. 计算当前可见画布中生成节点与图集的整体居中布局。
5. 创建图片生成节点并写入参数、参考连接和所属画布。
6. 调用现有图片节点运行函数。
7. 复用现有逻辑在成功时创建并连接图集、追加结果。
8. 验证图集存在、连接存在、图片数量增加，再返回成功结果。

结构化成功结果至少包含：

```json
{
  "ok": true,
  "node_id": "...",
  "gallery_node_id": "...",
  "image_count": 1,
  "status": "completed"
}
```

该工具属于付费工具，但 Agent Host 可以根据本轮经过验证的“明确直接生图授权”放行。授权判断由可信 Host/Broker 完成，不能由模型在工具参数里伪造。

## 5. 图片模型自动选择

自动选择放在确定性执行层，不放在 LLM 提示词中。

### 5.1 候选条件

模型只有同时满足以下条件才进入候选：

- 所属 API 服务商已启用；
- 已配置密钥和地址；
- 模型声明图片生成能力；有参考图时还必须声明图片编辑能力；
- 模型与请求的画幅、清晰度和参考图模式兼容；
- 服务商最近的监测状态不是明确离线或认证失败。

未指定模型时再增加一项强约束：候选的原始模型 ID 或模型家族必须属于 `gpt-image-2`（image2）。如果当前设备没有可用 image2 候选，则停止生成并提示配置，不自动改用 Gemini、Midjourney 或其他模型。

用户明确指定模型时，先按候选 ID、原始模型 ID、显示别名和模型家族进行规范化精确匹配，再在匹配结果内选择接口。没有匹配到可用候选时停止并说明指定模型不可用。

### 5.2 排序规则

1. 排除明确离线、认证失败、余额异常、无地址、无密钥或能力不兼容的接口；
2. 优先最近有真实生图成功记录、成功率高且连续失败少的候选；
3. 在稳定性相近时选择图片请求响应时间更短的接口；
4. 其余符合要求的同模型接口按稳定顺序兜底。

Agent 面板不显示模型名称；画布节点仍显示最终实际选择的模型，便于用户检查和手动调整。

### 5.3 失败与切换

- 在请求提交前发现地址、密钥、能力或兼容性无效时，可以自动选择下一候选。
- 请求已经提交后，如果返回明确的“未受理”错误，可以切换下一候选；必须通过明确错误类型判断，不能只凭模糊文本。
- 超时、连接中断或服务端状态不明时，不自动重复提交，避免同一请求可能被重复计费。
- 没有候选时不创建空节点，Agent 用中文提示用户到设置中配置或启用图片模型。
- 候选缓存为空或缺少目标模型时，执行层自动重新读取一次 `/api/image-models`；刷新仍无候选才判定不可用。

这套规则不通过额外付费生图来探测模型。它复用设置、能力声明、接口监测和真实历史调用数据，因此不会为了“测试可用性”产生费用。

## 6. 节点居中与视口行为

当前坐标函数返回的是画布坐标，但创建函数把它当作节点左上角，造成视觉偏移。改造后区分“视口中心点”和“节点左上角”。

### 6.1 单节点

当 Agent 只创建一个节点时：

```text
left = viewportCenterX - nodeWidth / 2
top  = viewportCenterY - nodeHeight / 2
```

当前可见视口以 `#infiniteCanvas` 的实际矩形为准，已经自然排除右侧 Agent 面板。

### 6.2 生图工作流

生成节点在左、图集在右，间距使用现有画布连接布局值。两者总包围盒的中心与可见视口中心重合。图集只有在生图成功后创建，但预先为它保留位置，避免结果出现时整体突然跳动。

如果中心区域已有节点，使用轻量碰撞检查向下或向右寻找最近空位；只在 Agent 创建时运行，不加入拖拽、缩放或渲染循环。

节点创建后不强制重置用户缩放，也不在用户正在拖拽或缩放时抢夺视口。必要时只选中新创建的结果，并进行短距离、可取消的“确保可见”平移。

## 7. 执行闭环与智能恢复

高层工具采用以下状态：

```text
理解意图 → 预检 → 创建节点 → 提交生成 → 等待结果 → 验证图集 → 完成
```

- 预检失败：不创建节点，不产生费用，返回可修复原因。
- 创建后、提交前失败：保留节点并标记“待处理”，允许用户手动修复。
- 提交后失败：保留节点、参数和错误状态，不自动进行不确定的付费重试。
- 图已返回但图集更新失败：安全地重建连接或图集并重新验收，不重复请求图片接口。
- `run_canvas_node` 必须返回图片运行函数的真实结构化结果，包括连接图集 ID 和图片数量，不能仅根据节点状态文字报告成功。
- `update_gallery` 对“生成节点已经连接目标图集且结果已存在”的情况按幂等成功处理，不重复添加，也不误报节点没有图片。
- 底层英文错误、HTTP 状态、调用 ID 和堆栈不直接显示；先转换为结构化错误，再由 Agent 用中文说明。

Agent 最终答复必须区分：

- “已生成并加入图集”；
- “已创建节点，但生成未完成”；
- “尚未执行，因为没有可用生图模型”。

## 8. 已有相关节点的复用决策

当当前画布中存在提示词、节点类型或对话语义与新需求相关的图片生成节点时，Agent 不得直接运行该节点。

1. 调用安全的视口定位能力，把画布镜头平移到候选节点并选中、高亮；不修改节点的画布坐标，不破坏用户排版。
2. 在 Agent 面板展示该节点当前提示词、模型和是否已有结果。
3. 提供三个明确选项：
   - **直接再生成此节点**：保持节点提示词与参数，再执行一次；用户点击即构成本次单张付费授权。
   - **按当前需求修改后生成**：先把提示词更新为当前对话需求，再运行同一节点；执行前展示将替换的提示词摘要。
   - **新建节点并生成**：保留旧节点不变，创建新节点、填入当前需求并完成图集闭环。
4. 用户没有选择前只定位和说明，不执行付费请求。

只有明显相关的生成节点进入该决策。普通素材图、无关节点或仅关键词偶然相同的节点不会阻止直接生图。用户通过 `@` 明确引用某节点时优先使用该节点作为候选。

## 9. 当前画布上下文

- 意图判断使用当前画布保存的连续对话，因此“按第二个方案生成”可以引用之前讨论。
- 工具使用的节点 ID 必须来自当前画布摘要、当前选区、`@` 引用或同一次工具结果。
- 生图授权、运行状态和结果只属于当前 `boardId + runId`。
- 切换画布后旧任务守卫立即失效；旧请求即使晚到，也不能创建图集、连接节点或保存到新画布。

## 10. 性能约束

- 不增加定时器、DOM 观察器或每帧计算。
- 模型候选在请求预检时读取一次并缓存到本次运行，不随画布交互重复计算。
- 候选刷新使用共享中的 Promise 合并并发请求；只有空缓存或目标模型缺失时触发，不加入画布渲染循环。
- 节点定位只更新一次视口变换和选中态，不移动节点、不增加常驻监听器。
- MCP 继续使用进程内 transport，不增加额外网络协议往返。
- 等待 LLM 或图片接口时保持画布拖拽、缩放、选择和查看可用。
- 节点创建、连接渲染和保存复用现有防抖机制；复合工具只在阶段边界调度检查点。

## 11. 兼容性与迁移

- 保留 `create_image_node`、`create_gallery_node`、`connect_nodes` 和 `run_canvas_node`，供专业多节点 Skill 和手动编排使用。
- 普通明确单次生图优先使用 `generate_image_to_gallery`。
- 现有 LLM Connector 无需知道画布实现，只需从统一 MCP Tool 定义生成对应模型的工具 schema。
- 更换 LLM 不影响生图工作流、模型解析、画布隔离和验收逻辑。
- 便携部署到另一台电脑后，模型候选根据该设备自己的 API 设置重新计算，不携带旧电脑密钥或不可用接口。

## 12. 验收标准

### 意图边界

- 输入“苹果海报怎么设计”只返回讨论内容，不修改画布。
- 输入“先创建节点，不要生成”只创建节点，不调用图片接口。
- 输入“直接生成一张苹果图片”不二次确认，自动完成节点、生成和图集。
- 讨论后输入“按第二个方案生成”能复用同画布上下文并执行。

### 模型选择

- LLM 不传模型名称也能选择兼容候选。
- 默认只从可用的 image2 接口中选择，并优先稳定且响应更快的接口。
- 用户指定 Gemini、Midjourney 或其他模型时，只在指定模型候选中路由；不可用时停止并提示。
- 首次候选加载失败后，下一次生图会自动重新加载，不需要刷新整个网页。
- 禁用、无密钥、无生成能力或明确离线的模型不会被选中。
- 首选模型失效但请求尚未提交时会选择下一候选。
- 超时状态不明时不会重复提交产生潜在重复费用。
- 无可用候选时不创建死节点，并给出中文设置提示。

### 节点与结果

- 单节点的视觉中心与当前可见画布中心基本重合。
- 生成节点和图集作为整体居中，右侧 Agent 面板不会遮住结果。
- 生图成功后存在一条生成节点到图集的连接，图集中至少有一张真实图片。
- 已有相关生成节点时，画布镜头定位并高亮该节点，节点原坐标保持不变，未选择操作前不会生成。
- 三个复用选项分别能够复用原提示词、更新提示词后复用、保留旧节点并新建生成。
- 运行已有节点后，Agent 能从 `run_canvas_node` 直接获得图集结果，不会重复调用 `update_gallery`；即使重复调用也按幂等成功处理。
- 只有上述验收通过，Agent 才显示任务完成。

### 安全与性能

- 明确直接生图授权仅作用于当前画布、当前任务和明确数量。
- 切换画布后旧响应不能写入新画布。
- 同一 `runId + callId` 不会重复执行付费请求。
- Agent 工作期间画布拖拽、缩放、选择和渲染保持流畅。
- 全部静态检查、MCP 协议测试、Agent 浏览器测试和画布性能测试通过。
