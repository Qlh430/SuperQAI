# 画布 Agent 路由可靠性与任务恢复设计

**状态：已实现并通过回归（2026-08-24）**

## 目标

让画布 Agent 在单个模型或接口变慢、超时、本地服务短暂重启时仍能给出明确反馈并继续完成任务；明确的直接生图命令在所有 Agent LLM 暂不可用时，仍可通过同一套 MCP 工具协议安全执行。

## 已确认的根因

1. 运行时把 `fetch()` 返回响应头之前的全部时间当成“连接时间”，固定 4 秒中止；部分兼容接口会在模型生成后才返回响应头，因此能力验证可在 21.6 秒通过，正常任务却会在 4 秒被杀死。
2. 当前四次备用尝试实际是同一 `sub2.de5.net` 接口上的两个模型、两种协议；接口级故障时并没有跨接口容灾。
3. 其他 API 已被模型发现，但仍处于待验证状态，未进入可执行候选池。
4. 验证成功提示先于候选池刷新显示，模型按钮仍保持旧的“验证中” DOM，造成互相矛盾的状态。
5. 本地服务重启或 `fetch failed` 没有被归类为可恢复错误，会落入笼统失败文案。
6. 明确的直接生图需求完全依赖 Agent LLM 先返回工具调用，导致 LLM 全部超时时画布无法使用已有的确定性高层生图工具。

## 路由设计

### 候选身份和顺序

- 设置界面继续以“接口 + 模型”为用户可见候选；协议适配器仍是内部实现。
- 运行时先按用户保存的主模型和备用顺序排序，再做接口多样性展开：第一轮每个不同 `baseUrl` 只取最优协议候选，第二轮才尝试同接口的其他模型或协议。
- 主模型设置仍保存在本机 `settings.json`；部署到另一台电脑时因为候选指纹不同，界面提示重新选择，不继承不可用的本机接口。

### 自适应首响应等待

- 不再把固定 4 秒当成所有接口的首响应上限。
- 候选有历史首字或验证耗时时，首响应等待为 `clamp(历史耗时 × 1.5 + 1000ms, 8000ms, 30000ms)`；没有历史时为 10 秒。
- HTTP 鉴权、余额、限流、5xx、协议错误仍立即切换，不等待计时结束。
- 总任务时限仍受全局 90 秒预算约束；单个慢接口不能无限占用任务。

## 候选按需验证

- 自动检测只在用户打开“Agent 模型”设置页后启动，不在画布渲染、缩放、拖拽线程中运行。
- 当可用候选少于 3 个不同接口时，从已发现候选中优先选择与当前主模型同名、但接口不同的模型；不足时再选择常见支持工具调用的文本模型。
- 串行验证、同一时间最多一个请求，每次打开设置页最多补齐 3 个不同接口；离开设置页或切换标签后立即中止当前自动验证，不再启动后续请求。再次打开时重置本轮尝试记录，使瞬时失败可以重试。
- 接口多样性按规范化后的完整 API 基址判断；同域名下不同反代路径仍作为独立接口验证和排序。
- 验证只调用文本与无副作用探针，不操作画布，也不调用图片生成。

## 明确生图命令兜底

- 仅匹配明确祈使式生图请求，例如“生成一个苹果图片”“帮我画一张海报”。带有“讨论、头脑风暴、建议、怎么设计、要不要”等探索语义时不触发。
- 仅在首次获取 Agent LLM 响应时路由全部不可用，且当前画布没有需要用户选择处理方式的相关生图节点时触发。模型已经执行过任一画布工具后再断线，只保留进度并提示继续，不得转入兜底付费生图。
- 进入兜底前重新序列化当前画布和选中节点，不使用请求开始时的旧快照。
- 兜底生成仍构造标准 `generate_image_to_gallery` MCP 工具调用，经 MCP Session、Broker、当前画布作用域和付费确认执行；不绕过工具协议和安全边界。
- 执行成功后直接结束当前任务，不再请求已故障的 LLM 续写；执行失败则保留画布与对话并显示具体原因。

## 验证状态界面

- 后端返回验证结果后立即把按钮更新成“Agent 已验证”或明确失败，再异步刷新候选排名。
- “能力已通过”和“运行质量”分开显示：工具调用通过是能力结论；耗时大于 10 秒显示“响应较慢”，样本不足显示“稳定性待观察”。
- 已验证候选进入备用池后显示接口、模型、响应时间、成功率与连续失败次数，不再出现成功提示和“验证中”并存。

## 错误恢复

- `Failed to fetch`、本地服务不可达、响应流提前断开、上游全部超时统一归类为可恢复错误。
- 界面保留任务、对话和画布，并提供“继续任务”；未知程序错误才使用通用失败提示。
- 继续任务重新读取当前画布，禁止重复已完成的工具调用。

## 性能边界

- 不增加轮询或常驻定时器。
- 自动验证仅在设置页可见时串行运行。
- 路由排序和直接生图意图判断均为纯内存操作，不读取大型画布数据，不改变节点位置。
- 所有延迟回调继续校验当前 `boardId`、`runId` 和 Broker scope；图片模型异步发现返回后、创建节点前再次校验，旧画布结果不能写入新画布。
- 便携包显式包含自动验证策略模块，并由包完整性检查阻止缺文件的压缩包发布。

## 验收标准

1. 21.6 秒验证成功的模型显示“已验证 · 响应较慢”，按钮不再卡在“验证中”。
2. 有两个不同接口时，第一次失败后的下一次尝试必须切到另一接口，而不是同接口的另一协议。
3. 首响应历史为 5 秒的接口不会在 4 秒被误杀；21.6 秒已验证接口可获得最多 30 秒首响应预算，仍受 45 秒单次和 90 秒总预算限制。
4. 待验证候选在 Agent 设置页按接口去重、串行补齐，不影响画布交互。
5. 空画布输入“生成一个苹果图片”，所有 Agent LLM 超时时仍能进入 MCP 生图与付费确认流程。
6. 输入“讨论一下苹果海报怎么设计”时不得触发确定性生图兜底。
7. 本地服务重启导致的网络错误显示可恢复提示而不是笼统失败。
8. 设置关闭后自动验证请求被中止；下一次打开仍可重试之前的瞬时失败。
9. 首轮工具已完成、后续 LLM 断线时不触发本地生图兜底，也不产生额外付费请求。
10. 图片模型列表延迟返回期间切换画布，不得在新画布创建任何节点。
