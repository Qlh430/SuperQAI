# AI OS Agent 主控视频制作设计

## 目标和边界

用户在现有画布向 Agent 描述想要的视频。AI OS 自己管理「剧本 -> 角色/场景 -> 分镜 -> 参考图/定帧 -> 逐镜视频 -> 审片 -> 成片」的状态和产物；小云雀、即梦、MiniMax H3 以及设置中其他可用的图片/视频模型只是可选择的执行后端。关闭画布、重启服务、等待上游数小时或重新打开对话，都不能丢失已提交任务或已审定的镜头。

本设计不是一次对话里自动生成完影片，也不把成片结果委托给某个第三方 Agent。每阶段可审阅、修改和继续；用户决定生图、生视频模型及付费执行范围。现有普通画布和各业务 Skill 保持可用。没有配置模型时仍可完成剧本、设定和分镜；无法合成时如实交付片段，不冒充成片。

为使范围可审查，实现分成三个可独立验收的子项目，依次交付：

1. **导演项目与通用 Skill**：结构化项目、阶段状态、分镜画布布局和 Agent 工具；即使不运行任何模型，也能保存、审阅、修改、重开继续。
2. **多模型逐镜制作**：可选图片/视频生成后端、模型参数适配、异步跟进、逐镜审批和返工。
3. **本地合成与交付**：按审定镜头合片、可选连续音轨、成片节点、导出和便携版 FFmpeg 命令行程序打包。

## Agent 的专业 Skill

新增 AI OS 内置「视频导演与制片」Skill，包含简短的主指令和按需读取的参考文件，避免每一轮注入长篇材料。参考文件分别定义创作简报、剧本/节拍、角色与场景圣经、镜头表、定帧与视频提示词、连续性/审片、合成验收。通用 Skill 不锁定风格或供应商；品牌广告、动画短片、MV 等已有专业 Skill 可沿用其题材规则，但共用同一项目状态与执行工具。当前运行时一次只激活一个业务 Skill，因此不假定 Skill 嵌套：通用阶段约束在项目工具中强制实施，业务 Skill 可以声明相同能力，引用相应专业规范。

路由优先级为用户显式选择的业务 Skill、与请求唯一匹配的专用 Skill、最后是通用「视频导演与制片」Skill。专用 Skill 保留其风格和领域指令；项目工具的阶段校验、审核门禁和镜头身份约束对所有 Skill 一致生效。未明确匹配时不根据「视频」一词挤掉已有专用 Skill。Agent 可以在已有业务 Skill 下使用同一套导演项目工具，无须嵌套激活第二个 Skill。

工作规则：

- 先明确用途、受众、媒介、目标时长、画幅、对白/字幕/音乐以及用户素材；未明确主体时问一句关键问题，不替用户虚构事实。
- 输出一个可编辑的故事结构，确认后锁定剧本版本。角色、场景、服装、道具和视觉规则形成稳定的「设定圣经」，后续镜头引用其 ID 而非复制一串易漂移的描述。
- 镜头表的每一行记录镜头 ID、顺序、时长、叙事目的、场景/角色、构图/景别、动作、运镜、首尾衔接、对白与声音、图片提示词、视频提示词、参考节点、模型选择及验收点。时长总和应与项目目标匹配；单镜时长必须由选定后端允许。
- 每个阶段生成完整可见产物并等待用户确认；选中某镜重做时只失效该镜以及依赖它的片段/成片。批量生成前提示预计调用次数及模型，用户确认后才执行。
- 审片检查角色外观、场景连续性、动作方向、关键物体、对白、时长、比例、违背参考图的变化以及跨镜衔接。标记问题并给出局部返工方案，不自行声称未经确认的画面已通过。
- 工具返回 `queued/running` 时说明正在等待；只有返回有效视频并写入画布后才标记已生成。失败保留原任务和已生成产物，不盲目重投付费任务。

## 持久化项目合同

一个视频项目绑定一个画布 ID，具有独立稳定的 `projectId`、修订号、目标参数、阶段版本、审批记录、角色/场景表、按顺序排列的稳定 `shotId` 和各镜头的画布节点引用。不能以屏幕坐标、节点标题或数组索引作为关联主键。现有「画布项目」用于库与分享，与这里的「视频制作项目」概念不同；一个画布默认至多有一个活跃视频制作项目，普通画布不受影响。

项目可见入口是一个紧凑的「视频项目」节点/顶部工作台，细节通过项目侧栏编辑；持久化记录在画布 SQLite 中按画布内部主键作用域保存，不仅存在 Agent 的对话历史或 localStorage。节点/连线仍使用现有画布存储。新表 `video_production_projects(board_pk PRIMARY KEY REFERENCES boards(pk) ON DELETE CASCADE, project_id UNIQUE, revision, document_json, updated_at)` 存结构化文本、状态、版本和节点/任务/素材 ID，不复制图片或视频字节；媒体依现有资源机制存储。新表 `video_production_operations(board_pk REFERENCES boards(pk) ON DELETE CASCADE, operation_id, result_json, PRIMARY KEY(board_pk, operation_id))` 保存写操作的结果，用于同一请求超时后的幂等重放。服务端事务中先检查操作 ID，随后按 `board_pk + revision` 条件更新，冲突返回最新修订号和可重试诊断，不做无条件覆盖。画布软删除时同步清理这两张表对应记录；物理删除依外键级联清理，不能让旧项目记录绑定重建的同名画布。

状态为 `brief -> script -> bible -> storyboard -> stills -> clips -> assembly -> delivered`。每阶段保留 `draft/awaiting_review/approved/stale` 和审批时的版本；镜头分别保留 `planned/still_ready/queued/rendering/clip_ready/approved/needs_revision`。运行任务另有 `taskId`、服务端状态、所选模型、参数、提交时的镜头版本和结果 ID。等待任务不是失败；返回晚于当前镜头版本的结果保留在历史中但不得替换已审定结果。上游角色/场景修改只使真正引用它的镜头失效；顺序、时长或已批准片段变化使成片失效，保留上一个可播放的成片历史。

删除项目或清除产物走现有危险操作确认；对既有普通节点的移动、缩放或改名不改变项目身份。丢失引用显示「需重新关联」，不静默创建假结果。每阶段的确认同时可由用户在项目界面或 Agent 对话中完成，更新同一项目状态。

## 画布呈现

项目提供两种同步视图：上方紧凑的阶段/镜头导航用于审阅、跳转和批准；下方仍是可平移、缩放、编辑、连线、分组的原有无限画布。不要把整个项目放进巨大的单卡片，也不强迫用户离开画布。

布局采用「制作资料区 + 逐镜行 + 成片区」：

```text
项目简报 -> 剧本/节拍 -> 角色/场景设定
S01  镜头说明/图片提示词 -> 参考图 -> 候选图集/选定帧 -> 视频提示词/生成节点 -> 视频输出
S02  镜头说明/图片提示词 -> 参考图 -> 候选图集/选定帧 -> 视频提示词/生成节点 -> 视频输出
...
已审定片段（顺序、入出点） + 连续音轨 -> 成片合成 -> 成片视频输出
```

用已有文字、图片、图集、视频生成、视频输出、连线和自动排布机制；新增项目/镜头身份与状态标记、阶段审阅界面和成片工具。镜头行的列宽按真实节点尺寸计算，列头固定对应「提示词/参考图/图片结果/视频生成/片段」，同镜头在同一行；用户调整的节点位置不应在后台任务回传时被重排。新增镜头或用户主动点「整理本项目」时才重排项目节点，不碰画布上不属于项目的节点。缺失产物显示占位和原因，不伪造预览。

选中一个镜头时高亮其文字、参考图、生成节点和结果的现有连线，并在侧栏显示审核与模型选择。模型下拉来自用户 API 设置和对应能力目录，分别针对生图/生视频过滤；显示可用输入、支持比例、时长与清晰度。换模型只改该镜头的生成设置，旧结果留在历史。小屏保持侧栏可收起、导航可滚动、各节点文字不溢出。

## 执行、权限与模型适配

在 `canvas-agent-capabilities.js`、`canvas-agent-tool-adapters.js` 和 `CanvasAgentCanvasApi` 里增加有限的项目工具，例如 `create_video_project`、`update_video_script`、`upsert_video_shots`、`approve_video_stage`、`bind_shot_asset`、`choose_shot_model`、`render_shot`、`check_shot_task`、`approve_shot_clip`、`assemble_video_project`、`get_video_project`。输入/输出采用有版本的结构化合同；每个写工具校验当前画布、项目、镜头 ID 与版本，返回可供 Agent 续做的下一阶段状态和节点 ID。列举项目时只给紧凑摘要，按镜头查询详情，避免 Agent 80 节点上下文上限截掉后面镜头。12 步单轮上限意味着每轮完成一个有意义的阶段或一批镜头，再从持久项目继续，而不是靠模型记住所有进度。

当前 `create_video_node` 实际固定创建 MiniMax H3；应保留该工具的兼容性，同时新增通用视频节点创建/执行路径，让用户可选择 API 视频目录中的模型，H3 也是可用选择之一。现有图片生成器继续使用图片目录和模型特性约束。执行前按模型能力验证参考图数量、首/尾帧、比例、时长和分辨率；UI 只展示支持的参数。不能因为某模型失败自动换供应商并继续扣费；需再次获得用户选择或明确的预授权。

所有付费工具沿用 Agent 风险审批，批量按实际镜头数和模型展示成本相关信息（没有可靠价格时只显示调用次数，不虚构费用）。已提交任务的重试先按原 `taskId` 查询，不重发；项目与现有 API 视频任务持久化及视频输出历史关联。成功只有在本地画布的目标镜头结果节点完成写入后才成立。生成任务完成与当前打开的画布无关：服务端持久跟踪，前端进入项目时对账并按 board/project/shot ID 回填，防止结果错入其他画布。

## 成片合成

新增受控服务端合成任务，使用可执行的 FFmpeg/FFprobe，而不是 Electron 的 `ffmpeg.dll`。便携版须随应用携带兼容 Windows 的程序，构建时检查存在性与调用权限，并随发行物记录许可证/来源；开发环境可从显式配置路径探测。绝不为缺少 FFmpeg 而暗中安装软件。

只有每个参与片段都已审定、输入媒体真实可读且没有排队任务时可合成。按镜头批准顺序和可选入/出点执行；先探测素材并统一目标分辨率、帧率、采样率/音轨格式，再拼接，避免来源编码差异造成黑帧、静音或不同步。默认保留片段声音；若选择连续音乐/旁白，明确音轨优先级、混音/淡入淡出和结束策略，不能默默覆盖原声。可先交付无额外配乐的片段合成；不具备配音/音乐生成时允许用户提供音频素材，不虚构该能力。

服务端只读取项目获准的本地媒体或经现有安全下载层缓存的外部生成结果；限制下载大小、协议、目标地址和并发，不把任意 URL 或 shell 命令传给 FFmpeg。用数组参数调用进程，支持超时/取消与临时文件清理，原片段永不改写。成功后先探测真实时长、分辨率和音轨，再存入成片视频输出节点及历史；失败保留可重试的任务诊断和旧成片。新一版镜头审定后标记旧合成结果过期，用户仍可回看。

## 验收与回归

- 从一句视频需求创建项目；审阅剧本/设定/分镜；在不生图的情况下关闭并重开画布，阶段和镜头节点/连线仍一致。
- 用户分别选择两种图片模型、两种视频模型完成不同镜头；界面只提供各自支持的参数，Agent 不越过确认、不隐式换模型。
- 视频上游排队、服务重启、重新进画布后显示同一任务；结果只回填所属镜头且不会重复付费；失败时只返工该镜。
- 更改角色、单镜提示词、镜头顺序分别触发正确范围的过期状态；旧版本结果可追溯，不覆盖新版审定结果。
- 不合格或仍排队片段阻止合成；合格片段输出真实可播放文件，顺序、时长、音轨和成片节点历史正确；缺失 FFmpeg 时明确提示，不丢素材。
- 普通画布、现有品牌/MV/3D Skill、生图、H3、API 视频、保存/恢复及 5 万节点虚拟化没有回归。桌面和移动视口检查节点对应列、文本、状态、交互及回传布局。

## 实施先后与明确不做

先完成项目/Skill/画布审阅的可恢复闭环，再让新镜头执行已有模型节点，最后接入本地合成和便携包校验。每一阶段均有单元、服务接口和浏览器端验收；不会以撰写 Skill 文档代替运行时功能。

首版不做自动配音/作曲、帧级非线性剪辑、真实素材外部网站抓取、跨项目共享资产同步，也不强制使用小云雀 CLI。第三方短剧 Agent 可以将来作为明确的可选委托模式，不进入 AI OS 主控链路。
