# MiniMax H3 文生视频兼容设计

## 目标

让同一个 MiniMax H3 画布节点同时支持纯文生视频和多模态参考生成，不再要求用户至少连接一项图片、视频或音频素材。

## 生成模式判定

节点不增加模式开关，而是根据提示词自动判断：

- 提示词不包含 `<Picture n>`、`<Video n>` 或 `<Audio n>` 时，按纯文生视频提交。
- 提示词包含引用标签时，按参考生成提交，并沿用现有的引用筛选和编号重排规则。
- 是否连接了未引用素材不改变模式；未在提示词中引用的素材不上传给 ComfyUI。

该规则与已有的“提示词引用哪个素材，就只上传哪个素材”行为保持一致，避免模式开关与提示词内容发生冲突。

## 前端行为

`runCanvasMinimaxH3Node` 继续要求视频描述非空，但删除“至少连接一项参考素材”的拦截。

提示词包含素材标签时，`validateCanvasH3PromptReferences` 仍检查编号是否指向当前 H3 节点已连接且可用的素材：

- 所有标签有效：允许提交。
- 任一标签无对应素材：阻止提交，并显示现有的“当前不存在”错误。
- 提示词没有标签：校验通过，允许使用空素材数组提交。

节点空状态提示改为“输入描述即可生成，参考素材可选”，明确告知用户文生视频可直接使用。图片、视频和音频的连接上限仍分别为 9、3、3。

## 服务端行为

`normalizeMinimaxH3Request` 继续校验提示词、素材数量、画幅、分辨率、步数、时长和种子，但不再要求素材数组至少有一项。

`selectPromptReferences` 的行为调整为：

- 没有任何引用标签时，返回原提示词以及三个空素材数组。
- 存在引用标签时，只返回被引用素材，并将稀疏编号重排为连续编号。
- 引用编号越界时继续抛出明确错误。

`prepareMinimaxH3Workflow` 已能删除模板中的示例参考节点；当三个素材数组均为空时，不创建任何 `LoadImage`、`LoadVideo`、`GetVideoComponents` 或 `LoadAudio` 节点，也不向 H3 节点写入参考输入。提示词、画幅、分辨率、调度步数、时长和种子仍正常写入工作流。

## 兼容与安全

- 已有参考生成流程保持不变。
- 已连接但未引用的素材不上传，避免不必要的传输和编号错配。
- 纯文生视频请求仍只能使用非空提示词。
- API 端继续拒绝超过 9 图、3 视频或 3 音频的请求，以及不存在的素材引用标签。
- ComfyUI 地址、上传来源限制、超时和 MP4 输出契约保持不变。

## 验证

- 聚焦服务端测试先证明当前纯文本请求会失败，再验证规范化结果包含原提示词和空素材数组。
- 工作流测试验证纯文本请求不会生成任何参考加载节点，且 H3 节点不存在参考输入键。
- 前端静态契约测试验证“至少连接一项参考素材”拦截被移除，新空状态提示存在。
- 浏览器测试使用无素材 H3 节点提交纯文本，验证请求只携带空素材数组，并能进入成功轮询流程。
- 回归测试继续覆盖有效引用筛选、编号重排、无效引用拦截及 9/3/3 上限。
- 最后运行 H3 聚焦检查、浏览器检查、JavaScript 语法检查和完整项目检查。
