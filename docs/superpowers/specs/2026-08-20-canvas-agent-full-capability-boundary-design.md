# 画布 Agent 完整能力、Skill 与安全边界设计

## 状态

设计方向已确认。本规格将画布 Agent 从目前的 8 个基础工具扩展为“仅操作当前画布的完整内容执行者”，同时保证画布流畅度，杜绝跨画布写入。

## 目标

用户可以先与 Agent 多轮头脑风暴，再要求它把讨论结果直接落实到当前画布。Agent 可以调用完成任务所需的画布内容功能，但不能管理其他画布、应用设置、API 接入、历史记录或回收站。

## 产品原则

1. 一张画布只对应一条连续对话和一个执行边界。
2. 讨论不等于执行。只有用户表达“创建、生成、修改、排列、连接、删除、执行”等明确操作意图时，Agent 才调用工具。
3. 用户明确把任务全权交给 Agent 后，Agent 自行补全合理的创意和参数选择，连续执行安全操作，不再反复追问。
4. 付费生成、删除和批量覆盖始终需要用户确认。
5. 缺少非必要细节时使用画布默认值。只有缺少不可替代素材、需求互相冲突或继续操作会越过安全边界时才暂停询问。
6. Agent 不得给画布渲染、拖拽、缩放、选择、撤销或自动保存增加持续运行的负担。

## 能力范围

### Agent 可以调用的当前画布内容能力

- 创建文字、图片生成/编辑、LLM、ComfyUI、MiniMax H3 视频、媒体、循环、图集、分组和宫格编辑节点。
- 图片或媒体参考节点只能使用用户本次附加的素材，或当前画布中已经存在的素材。
- 修改各类节点已经在界面开放的字段，包括文字、提示词、模型、尺寸、清晰度、画面比例、视频时长、ComfyUI 模式与选项、图集标题与布局、宫格规格、间距和单格缩放。
- 执行图片、LLM、ComfyUI 和视频生成节点。
- 连接和断开节点、调整参考素材顺序，并使用选中或通过 `@` 明确引用的节点作为输入。
- 移动和排列节点、复制节点、创建和解散分组、添加或移除分组成员。
- 从图片创建宫格编辑器、调整宫格布局，并把切片结果提取到图集。
- 在现有界面能力允许的范围内，添加、移除、排序和切换图集图片。
- 用户确认后，删除当前画布中的一个或多个节点。

### 明确不开放给 Agent 的能力

Agent 不能：

- 读取、切换、新建、重命名、移入回收站、恢复、清空或永久删除画布。
- 访问其他画布的节点、素材或对话。
- 修改 API 服务商、密钥、模型配置、价格、偏好设置、主题、本地存储或应用配置。
- 操作全局历史、撤销/重做、回收站、账号、会员或计费界面。
- 在用户没有主动添加文件时读取任意本地文件，也不能复用不属于当前请求或当前画布的素材。
- 未经单独设计和用户明确操作，触发浏览器下载、外部发布或分享。

## 总体架构

### 三层 Skill 系统

目前产品已有 5 个用户可见的业务 Skill，但通用执行规范仍分散在运行时提示词、工具定义和前端判断中。改造后采用三层结构：

1. **核心执行 Skill**：隐藏且始终生效的 `canvas-agent-core`，只负责意图识别、当前画布隔离、全权执行规则、确认规则、错误恢复和完成标准。
2. **业务 Skill**：产品精修、电商套图、海报设计、社交媒体套图、图生视频等具体工作流。一次运行最多加载一个主业务 Skill 的完整正文。
3. **动态能力目录**：根据能力代理注册表自动生成精简的工具名称、用途、风险等级和参数结构。Skill 只能引用能力 ID，不能直接调用画布全局函数。

核心执行 Skill 不显示在技能书列表中，因为每次 Agent 运行都会自动使用它。用户可见的业务 Skill 仍然是可选项：用户手动选择时直接加载；自动模式首轮只提供每个 Skill 的 ID、名称、简短适用场景和能力标签，不再一次性塞入全部 Skill 正文。

### 业务 Skill 按需激活

自动模式不再把所有业务 Skill 正文拼进第一次模型请求，而是遵循以下流程：

- 普通聊天和常规画布操作只使用核心执行 Skill。
- 请求明确符合某个专业工作流时，规划器发出内部 `activate_canvas_skill` 调用，并附带 Skill ID 和简短原因。
- 服务端校验 Skill 后，只注入该 Skill 的完整说明，并把它声明的能力与当前画布能力取交集，然后沿用现有无状态上下文继续同一次任务。
- 用户手动选择 Skill 时跳过自动识别，直接加载所选 Skill。
- 一次任务最多有一个主业务 Skill，不能递归激活，也不能同时加载多份完整 Skill 正文。
- Skill 不存在、配置错误或越权时，返回结构化结果并退回核心执行 Skill，不中断整个对话。

额外的 Skill 识别轮次只发生在自动匹配专业工作流时。问候、移动节点、连接节点、创建文字等简单任务不会承担这部分延迟。

### Skill 文件规范

每个 `SKILL.md` 的头部只声明精简的路由和权限元数据：

```yaml
name: poster-design
description: 设计营销、活动和节日海报。
canvas:
  label: 海报设计
  icon: monitor
  triggers: [海报, 主视觉, 活动视觉]
  capabilities: [node.image.create, node.text.create, node.update, node.connect, node.arrange, node.run]
  required_context: optional-image
```

Markdown 正文只描述业务流程、判断节点、输出标准和业务恢复方式，不重复全局画布隔离、确认、故障转移和幂等规则；这些统一放在核心执行 Skill 中。

能力 ID 是稳定的产品接口。加载 Skill 时发现未知能力 ID，运行时直接拒绝该 Skill。能力代理把 Skill 获得的能力 ID 转换成模型实际可见的工具子集，所以新增工具不会自动授权给全部业务 Skill。

### Token 与加载预算

- 始终加载的核心执行 Skill 控制在约 800–1200 个输入 Token。
- 自动模式中的每个业务 Skill 路由摘要控制在约 60 个 Token 以内。
- 一次运行最多注入一个完整业务 Skill 正文。
- 只发送当前核心/业务能力真正需要的工具参数结构，不发送无关工具。
- Skill 文件解析结果和能力目录按“文件路径 + 修改时间”缓存。
- 拖拽、平移、缩放、选中、渲染和自动保存期间不会读取 Skill 文件。
- Skill 文件改变后，只在下一次 Agent 请求时刷新缓存，不增加轮询。
- 对话和画布摘要继续保留现有数量限制，新增 Skill 不会让历史上下文无限增长。

### 当前画布能力代理

所有 Agent 工具都必须经过统一的 `CanvasAgentCapabilityBroker`，模型不能直接调用画布全局函数。一次任务开始时，能力代理创建不可变作用域：

```js
{
  boardId,
  runId,
  scopeVersion,
  abortSignal,
}
```

每次工具请求都携带 `board_id`、`run_id` 和 `call_id`。查找节点前、修改前以及每个异步操作完成后，都要重新检查：

- `boardId` 不能为空，并且必须等于当前打开画布的 ID。
- `runId` 必须仍是该画布正在运行的 Agent 任务。
- `scopeVersion` 不能因画布切换或恢复而失效。
- 每个目标节点都必须存在于当前画布，并属于该 `boardId`。
- 同一个运行和调用 ID 不能已经执行完成。

任何检查失败都返回结构化的 `scope_expired` 结果，后续不再修改画布。切换画布会取消请求、递增作用域版本、清除待确认操作，并阻止旧异步任务把结果写入新画布或新画布对话。

### 节点归属

每个新建或恢复的节点在运行时元数据中记录所属 `boardId`。Agent 适配器拒绝操作已经脱离页面的节点，以及所属画布与当前画布不同的节点。

长时间运行的生成函数接收一个可选画布守卫。在写入状态、媒体结果、图集、连接或触发保存之前重新检查画布归属，防止用户切换画布后，旧请求污染新画布。

### 工具注册表

工具采用声明式记录，不再继续扩大单个 `switch`：

```js
{
  name,
  description,
  risk,
  maxTargets,
  validate(args, context),
  execute(args, context),
  summarize(result),
}
```

风险等级为 `safe`（安全）、`paid`（付费）、`destructive`（删除）和 `bulk-overwrite`（批量覆盖）。注册表按节点创建、编辑、关系、组织、媒体执行、宫格/图集和删除能力拆分模块。

模型工具参数结构和前端执行能力来自同一份注册记录，避免出现“模型以为能调用，但前端没有实现”的漂移问题。

## 全权执行策略

只要用户表达了明确可执行意图，安全操作在普通模式和全权委托模式下都可以直接执行。全权委托改变的是 Agent 的决策方式，而不是安全权限：

- Agent 可以自行选择合理的默认参数、布局、当前画布已经配置的模型、节点位置和中间步骤。
- 可以合理推断的审美与参数细节不再询问用户。
- 可以连续调用多个安全工具，直到用户目标真正完成。
- 不能绕过必要确认，也不能突破当前画布边界。

以下操作始终暂停，并显示一张合并确认卡：

- 任意付费的 `run_canvas_node` 操作。
- 任意节点删除。
- 影响多个现有节点，或替换已有生成媒体/内容的批量覆盖。

确认卡显示操作类型、影响节点数量以及是否可能产生费用。批准只适用于当前画布、当前运行和卡片中列出的调用。后续新出现的付费、删除或批量覆盖操作需要再次合并确认；安全操作不需要确认。

## 完整执行流程

1. 用户和 Agent 在当前画布所属的连续对话中讨论目标。
2. 出现可执行意图后，客户端保证当前画布有稳定 `board_id`，获取有限的当前画布摘要和选中/引用素材，并创建画布作用域。
3. 运行时加载核心执行 Skill，以及用户手动选择的业务 Skill；自动模式则先加载精简路由目录。
4. 自动路由命中业务 Skill 后，服务端只注入该 Skill，并继续同一次任务。
5. LLM 从经过权限过滤的工具中选择操作。全权委托要求规划器自行补全合理选择，避免不必要的澄清。
6. 能力代理校验并依次执行安全操作；连续 DOM 操作数量较多时分成小批次，并在批次之间让出一帧。
7. 付费、删除或批量覆盖操作合并成一次确认后再执行。
8. 工具结果按 `run_id + call_id` 去重，并通过无状态工具上下文回传给模型。
9. Agent 完成后续安全步骤，并说明实际完成的画布修改。
10. 任何时刻切换画布都会让旧作用域失效；旧任务不能写入新画布。

## 性能规则

- 不增加新的 `setInterval`、轮询、DOM 变更监听器或逐帧 Agent 工作。
- 只在用户发送 Agent 请求或主动继续中断任务时生成画布摘要。
- 每批工具只构建一次节点查找表，用完立即释放。
- 同一画布同一时间最多允许一个 Agent 任务修改内容。
- DOM 批量操作最多处理 40 个目标，超过交互耗时预算时拆成小批次并让出一帧。
- 复用现有防抖保存和连接渲染。一次多工具任务只请求最终渲染/保存检查点，避免每个子步骤同步序列化画布。
- 图片编码最多处理 3 张选中或引用素材，并异步执行。
- Agent 对话继续独立保存，不进入画布 JSON、撤销快照、拖拽、缩放或渲染循环。

## 错误与恢复

- 画布作用域过期属于正常停止状态，不显示红色技术错误。旧画布保留已经完成的操作，并在自己的对话中记录简短中断提示。
- 目标节点不存在时返回结构化结果，让 Agent 根据最新当前画布摘要安全地重新规划。
- 工具调用状态丢失继续使用现有无状态重放和模型线路切换机制。
- 已完成调用不得自动重复；付费调用还要按操作类型和目标节点额外去重。
- 不向用户显示模型名称、服务商原始错误、HTTP 信息、`call_id` 或 trace ID。
- 一个安全操作失败时，不回滚其他已经成功且无关的操作。Agent 要说明已经完成什么、还有什么未完成。

## 测试与验收标准

### 画布隔离

- 在画布 A 启动延迟工具，切换到画布 B，再让旧 Promise 返回：画布 B 的节点、连接、保存内容、撤销栈和对话全部保持不变。
- 携带画布 A `board_id` 或节点 ID 的工具在画布 B 上必须在修改前失败。
- 重新打开画布 A 时恢复其对话，并允许新任务；不能复活已经失效的旧任务。

### 能力与 Skill 覆盖

- 每个工具参数结构都对应真实可执行适配器；所有计划开放的内容操作都有注册项。
- 核心执行 Skill 始终生效，但不出现在用户技能书中。
- 简单自动任务不包含任何完整业务 Skill；专业任务只能加载一个完整业务 Skill。
- 每个业务 Skill 的能力 ID 都必须对应已注册能力，未声明能力对该 Skill 不可用。
- Skill 文件修改后，下一次请求自动加载新内容，不增加轮询，也不要求重启服务。
- 浏览器流程覆盖创建、编辑、执行、连接/断开、复制、分组、宫格切片、图集修改、排列和删除。
- 用户先讨论，再说“按刚才方案直接执行”时，Agent 使用当前画布对话上下文完成安全步骤，不再重复澄清。

### 确认策略

- 安全工具直接执行。
- 付费生成、删除和批量覆盖在确认前绝不能执行。
- 全权委托只减少非必要追问，不能绕过确认。
- 切换画布、任务结束或出现新风险调用后，旧批准不能继续复用。

### 流畅度

- 现有全部画布性能检查继续通过。
- 不增加 Agent 定时器、DOM 观察器或动画循环。
- Agent 等待 LLM 或外部生成服务时，拖拽、平移、缩放和选择保持可操作。
- 浏览器测试确认等待动画和对话更新不会触发画布序列化或同步批量渲染。

## 最终交付边界

本次实现开放所有已经具备稳定界面行为的“当前画布内容操作”。“所有功能”不等于把 `script.js` 中的内部函数全部暴露给模型：渲染辅助函数和全局应用管理功能继续保持私有。

以后新增画布内容功能时，必须先在能力代理中注册，才能被模型发现和调用；新增专业工作流则通过独立业务 Skill 按需加载，不继续扩大核心提示词。
