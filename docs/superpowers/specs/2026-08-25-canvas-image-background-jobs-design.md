# 画布生图后台任务设计

## 目标

将画布节点的生图请求从浏览器长连接改成可恢复的服务端后台任务。慢接口继续生成时不误判失败；刷新画布后可继续查询；请求已经提交但结果不确定时禁止自动重试，避免重复扣费。

## 已确认边界

- 仅改变画布图片生成节点的执行链路；普通对话、Agent 推理路由和其他画布节点保持不变。
- 创建任务不代表再次授权付费：一次用户确认只创建一个后台任务。
- 接口明确返回认证、余额、限流或连接失败时，后续任务可切换备用接口。
- 请求提交后超时属于 `unknown`，不自动重新提交。用户继续任务时使用已经准备好的备用接口。
- 默认总执行上限为 15 分钟，可通过 `IMAGE_JOB_TIMEOUT_MINUTES` 在 5–30 分钟内调整。
- 画布节点在 `queued/submitting/running` 阶段持续显示“生成中”，但不阻塞拖拽、缩放或其他画布交互。

## 架构

新增独立的 `image-job-manager.js`。它负责状态机、持久化、截止时间和结果清理，不依赖 DOM 或具体图片供应商。服务端新增：

- `POST /api/image-jobs`：创建任务并立即返回 `job_id`。
- `GET /api/image-jobs/:job_id`：读取任务状态和最终结果。

任务状态为 `queued → submitting → running → completed`。明确错误进入 `failed`；超过总执行上限、服务重启中断或提交结果不确定进入 `unknown`。`unknown` 与 `completed/failed` 都是终态，不能由客户端触发自动重试。

服务端后台执行复用现有 `/api/images` 的同一套生图逻辑和模型记录，不复制供应商判断。任务状态持久化到 `data/image-jobs.json`；启动时将遗留的运行态任务恢复成 `unknown`，避免误认为仍在执行。

## 画布数据流

1. 节点在付费请求前完成健康接口预检。
2. 前端创建后台任务，把 `job_id` 写入节点并保存画布。
3. 前端每 1.5 秒查询一次任务；轮询请求轻量且不占用画布渲染循环。
4. 完成后沿用现有逻辑写入图集、历史记录和节点状态。
5. 刷新或重新打开画布时，检测节点保存的 `job_id`，恢复轮询而不创建新任务。
6. `failed` 显示明确错误；`unknown` 显示“结果待确认”，保留节点与图集，不自动重试。

## 超时与扣费安全

- Agent 的 45/90 秒推理超时不控制后台生图任务。
- 后台任务默认等待 15 分钟；达到上限后中止本地等待并进入 `unknown`。
- 已获得上游 `task_id` 的供应商继续通过任务查询获得结果。
- 没有 `task_id` 的同步兼容接口只能标记结果未知，不能安全自动重提。
- GrsAI 的提交超时不再自动重新提交；只有明确、未受理的错误才交给下一次任务的模型预检处理。

## 验收

- 创建任务接口在实际生图完成前返回。
- 慢任务保持运行状态并最终完成，不触发第二次调用。
- 超时任务只调用供应商一次并进入 `unknown`。
- 页面刷新后使用原 `job_id` 恢复结果，不产生新任务。
- 节点按钮在运行期间显示生成态，完成或终止后恢复。
- 现有同步 `/api/images`、模型选择、图集写入和完整检查保持通过。
