# 生成节点底部控件响应式布局设计

## 背景

生成节点底部当前使用三列网格：比例选择占据剩余宽度，分辨率选择和生成按钮使用固定宽度。节点变窄时，比例选择会被压缩到难以识别；节点变宽时，比例选择又会无限拉长。

用户需要继续自由拉宽节点，以便查看长提示词，因此不能限制节点的最大宽度。生成按钮必须始终与比例、分辨率处于同一行。

## 目标

- 生成节点仍可自由拉宽，提示词输入框和模型选择框继续占满节点宽度。
- 比例、分辨率和生成按钮始终处于同一行。
- 窄节点下三个控件仍保持可读、可点击。
- 宽节点下比例和分辨率控件不随节点无限拉长。
- 生成按钮始终位于底部控制行右侧。
- 只改变生成节点，不影响其他类型的画布节点。

## 布局规则

### 常规与宽状态

底部控制行使用四列：

1. 比例选择：合理固定上限，目标宽度约 180px。
2. 分辨率选择：目标宽度约 112px。
3. 弹性空白：吸收节点增加的宽度。
4. 生成按钮：目标宽度约 120px，并保持右对齐。

提示词输入框和模型选择框继续横跨整行，随节点宽度增长。

### 窄状态

底部控制行仍为单行三列：

1. 比例选择：允许压缩，但必须保留可读的最小宽度。
2. 分辨率选择：允许小幅压缩，但必须完整显示常见标签，例如“自动尺寸”。
3. 生成按钮：保持稳定宽度，不换行。

生成节点采用约 320px 的专用最小宽度，避免三个控件继续被压缩。该最小宽度仅应用于包含提示词、模型、比例、分辨率和生成按钮的生成节点。

## 实现边界

- 优先使用现有的 CSS 容器查询，因为 `.canvas-node` 已启用 `container-type: inline-size`。
- 为生成节点增加明确的类型类名或复用现有可稳定识别的类名，避免规则误伤图片结果节点。
- 调整节点拖拽缩放的最小宽度计算，使生成节点与 CSS 最小宽度一致。
- 恢复旧画布时，如果保存的生成节点宽度小于新下限，视觉宽度应自动提升到下限；不修改提示词、模型、比例或分辨率数据。
- 不改变图像生成请求、模型限制、分辨率校验或 Auto 自动尺寸行为。

## 验收标准

- 将生成节点缩到最窄时，比例、分辨率和生成按钮均在同一行，文字没有消失或严重截断。
- 将生成节点拉宽时，提示词输入框和模型选择框随节点增长。
- 将生成节点拉宽时，比例和分辨率保持合理宽度，生成按钮保持在最右侧。
- 分辨率显示“自动尺寸”时仍完整可辨认。
- 其他画布节点的最小宽度和控件布局保持不变。
- 页面无新增 JavaScript 错误，现有检查继续通过。
