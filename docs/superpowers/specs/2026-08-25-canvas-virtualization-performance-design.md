# 无限画布虚拟化与 3000 节点性能设计

日期：2026-08-25

## 背景与诊断结论

现有画布已经实现图片缩略图、视口外图片 `src` 卸载、视口变换的动画帧合并，以及历史画布渐进恢复。这些措施降低了原图下载和解码压力，但没有减少常驻节点 DOM、控件、监听器及 SVG 连线数量。

压力测试使用一半图片节点、一半文字节点，并创建相邻节点连接。实测结果如下：

| 节点数 | 画布 DOM 元素 | 历史恢复耗时 | 单次连线重绘 | 最长主线程任务 |
| ---: | ---: | ---: | ---: | ---: |
| 1000 | 约 9000 | 约 2.2 秒 | 约 107ms | 约 252ms |
| 2000 | 约 18000 | 约 9.3 秒 | 约 405ms | 约 947ms |
| 3000 | 约 27000 | 约 19 秒 | 约 968ms | 约 2140ms |

主要根因：

1. 所有复杂节点始终作为完整 DOM 常驻，视口外只卸载图片地址，不卸载节点结构。
2. `getCanvasNode(id)` 每次通过 DOM 选择器查找；连线重绘对每条连接多次查找节点，随节点和连线增加出现接近二次增长。
3. 图片质量刷新通过 `querySelectorAll` 全量扫描画布图片，仍与总节点数线性相关。
4. 保存、撤销和部分批量操作把 DOM 当作唯一数据源，因此无法安全卸载视口外节点。
5. `.canvas-plane` 与连线 SVG 固定为 `4000 × 3000`，运行语义并非真正无界。
6. 历史渐进恢复只是把长任务切成批次，最终仍创建全部 DOM，无法消除持续内存、布局、合成和重绘成本。

## 目标

- 单张画布稳定承载 3000 个混合节点和约 3000 条连接。
- 平移、缩放和节点交互不因画布总节点数增长而持续卡顿。
- 视口内文字、图片和节点内容稳定出现，不再因资源与主线程压力形成空白节点。
- 旧画布打开时自动进入优化后的运行架构，无需用户迁移、压缩或重新保存。
- 保留拖动、缩放、连线、选择、复制、撤销、生成、下载、裁剪、遮罩和历史恢复能力。
- 保持现有服务端画布 JSON 格式兼容，不删除原图或用户数据。

## 非目标

- 不把全部复杂节点重写为 Canvas 或 WebGL 控件。
- 不改变图片生成、下载、裁剪、遮罩或连接输出所使用的原图地址。
- 不要求启动时批量转换全部历史文件。
- 不依赖大型第三方画布框架或原生编译依赖。
- 不保证 3000 个复杂编辑器完全重叠并同时以完整交互形态显示；高密度场景使用轻量层级显示。

## 方案选择

### 采用：混合式 DOM 虚拟化

全部节点以轻量模型常驻，只有视口附近、选中、编辑或运行中的节点挂载完整 DOM。空间索引负责查询可见节点，连接渲染只处理可见路径，图片资源只跟随已挂载节点。该方案能复用现有复杂表单和编辑器，同时从根本上控制 DOM 规模。

### 未采用：仅使用 CSS `content-visibility`

该方案改动较小，但 3000 个复杂节点、监听器和 SVG 路径仍然常驻；历史恢复和内存成本不会消失，无法满足目标。

### 未采用：完整 Canvas/WebGL 重写

纯渲染器能提供更高上限，但现有输入框、选择器、图片编辑、裁剪、遮罩和生成状态都需要重写为覆盖层，范围和兼容风险超出本次目标。

## 总体架构

### 1. 规范化节点模型存储

新增画布模型存储，以 `Map<string, CanvasNodeModel>` 保存全部节点；DOM 不再是唯一数据源。模型保留现有序列化字段，并增加仅存在于运行时的修订号、挂载状态和几何缓存。运行时字段不得写入服务端 JSON。

```js
{
  id: "node-42",
  kind: "image",
  x: 1240,
  y: -380,
  width: 320,
  height: 260,
  // 现有节点类型字段保持原样
  runtime: {
    revision: 8,
    mounted: false,
    geometryRevision: 3
  }
}
```

同时维护：

- `modelsById`：O(1) 取得任意节点模型。
- `mountedById`：O(1) 取得当前已挂载节点 DOM。
- `nodeOrder`：保持序列化和层叠顺序稳定。
- `pinnedIds`：保存选中、拖动、编辑、裁剪、遮罩或运行中节点。
- `dirtyIds`：记录需要从 DOM 写回模型的已挂载节点。

### 2. 无依赖网格空间索引

使用固定单元格的空间哈希索引，不增加外部依赖。节点根据模型中的 `x`、`y`、`width`、`height` 写入覆盖的网格单元；移动或缩放节点时只更新受影响单元。

- 默认单元格边长为 768 画布像素。
- 查询使用当前画布变换反算可见画布矩形。
- 挂载缓冲区默认扩展 640 屏幕像素。
- 卸载缓冲区默认扩展 960 屏幕像素，形成迟滞区，避免边缘节点反复挂载。
- 查询结果与 `pinnedIds` 合并后才计算挂载差异。

空间索引是派生数据。发现缺失、重复或几何版本不一致时，从 `modelsById` 自动重建，不修改用户节点。

### 3. 节点虚拟化协调器

协调器在单个 `requestAnimationFrame` 中合并平移、缩放、节点移动和容器尺寸变化。每次刷新执行：

1. 计算挂载矩形和卸载矩形。
2. 从空间索引查询应显示节点。
3. 合并固定节点和当前交互节点。
4. 对比 `mountedById`，生成挂载、降级和卸载任务。
5. 按每帧 6–8ms 时间预算执行任务；首屏节点优先，缓冲区节点随后。
6. 完成后安排图片质量和可见连线刷新。

卸载节点前必须先把可编辑状态同步回模型，再断开 ResizeObserver、图片资源观察、临时 Object URL 和节点专属监听资源。挂载时通过现有节点渲染函数从模型恢复。

### 4. 节点适配层

为现有节点类型提供统一生命周期接口：

```js
{
  mount(model, context) -> HTMLElement,
  syncFromElement(model, element) -> CanvasNodeModel,
  dispose(element, context) -> void,
  getGeometry(model, element?) -> { x, y, width, height, ports }
}
```

通用适配器复用现有 `restoreCanvasBoardNode`、`serializeCanvasNode`、图片资源管理和节点尺寸逻辑。只有存在特殊异步资源或内部状态的节点类型提供定制钩子。首批必须覆盖文字、图片、上传、图集、组、LLM、Comfy、循环、网格编辑器、Minimax H3、视频、音频和视频输出节点。

### 5. 层级显示与高密度保护

缩放较低或视口内候选节点过多时，完整表单没有可读性。协调器根据缩放和密度选择显示等级：

- 完整层：正常挂载现有节点，支持全部交互。
- 紧凑层：显示节点外观、类型、标题、状态和图片缩略图，隐藏复杂控件。
- 概览层：使用轻量节点壳显示位置、颜色、类型及是否包含图片或运行结果。

选中或主动打开的节点无条件提升到完整层。降级只改变运行时显示，不修改或丢弃模型内容。这样即使大量节点集中在一个视口，也不会同时创建数千个完整编辑器，同时用户仍能看到节点存在而不是空白区域。

### 6. O(1) 节点访问和可见连线

`getCanvasNode(id)` 改为查询 `mountedById`；需要操作视口外节点的业务读取模型，不通过 DOM 搜索。连接端点由节点几何缓存和端口规则计算，节点挂载后用实际尺寸校准缓存。

连接渲染流程：

1. 连接数据继续完整保存在 `canvasState.connections`。
2. 按节点 ID 从模型 Map 直接取得端点，单条连接查找为 O(1)。
3. 使用连接包围盒与扩展视口做相交判断。
4. 只为可见或正在创建的连接生成 SVG 路径。
5. 使用事件委托处理连接点击，不为每条路径创建独立闭包。
6. 路径数据未变化时复用元素，只更新发生变化的连接。

视口外连接不进入 DOM，但不会从连接数据中删除。

### 7. 真正无界的坐标平面

移除 `4000 × 3000` 作为节点和连接的逻辑边界。节点继续使用画布坐标，允许正负方向扩展。画布平面只作为变换容器，不依赖固定宽高裁剪内容；背景网格根据 `x`、`y`、`scale` 更新 `background-position` 和 `background-size`，保持无限延展视觉。

选择框、拖放坐标、端口位置和连线路径都使用画布坐标与视口坐标转换，不读取固定平面尺寸。

### 8. 图片资源生命周期

现有缩略图和原图地址规则继续使用，但资源生命周期由节点挂载状态驱动：

- 未挂载节点不创建 `<img>`，不进入图片队列。
- 紧凑层和概览层最多请求缩略图，不请求原图。
- 完整层按现有缩放与稳定计时规则决定缩略图或原图。
- 节点卸载时调用图片资源管理器释放观察和显示地址。
- 节点重新挂载时使用模型中的原图地址查询缩略图缓存。
- 图片失败时显示轻量错误状态并按退避策略重试；原图地址始终保留。

## 数据流

### 打开新旧画布

1. 读取现有画布 JSON。
2. `normalizeCanvasBoardForVirtualization(board)` 为缺失宽高、节点类型别名和旧字段提供运行时默认值。
3. 规范化只发生在内存中，不要求写回旧文件，也不改变未知字段。
4. 一次遍历建立 `modelsById`、`nodeOrder` 和空间索引，不创建全部节点 DOM。
5. 恢复画布视口后立即查询首屏节点并挂载。
6. 首屏完成后按帧预算填充缓冲区节点和可见连接。
7. 用户第一次真实编辑或保存时，继续输出与现有接口兼容的完整画布 JSON。

因此所有旧画布在每次打开时自动采用虚拟化、索引、可见连线和图片生命周期优化，无需批量迁移；未识别的旧字段在模型中透传，避免数据损失。

### 平移和缩放

1. 输入事件只更新待处理视口状态。
2. 下一动画帧写入一次变换。
3. 协调器查询空间索引并增量更新挂载集合。
4. 图片和连线只针对本次可见集合刷新。
5. 操作停止后按现有防抖策略保存最终视口，不创建内容撤销快照。

### 节点编辑、拖动和缩放

1. 交互开始时把节点加入 `pinnedIds`。
2. 输入值、尺寸和位置更新写入模型并增加修订号。
3. 几何变化同步更新空间索引和连接端点缓存。
4. 交互结束后记录一次撤销检查点并安排保存。
5. 节点离开卸载缓冲区且不再固定时才允许释放 DOM。

### 异步生成和媒体任务

任务 ID、状态和结果地址保存在模型中。运行中的节点固定挂载；如果页面切换或恢复流程使节点未挂载，异步结果先写入模型和任务存储，节点下次挂载时恢复最终状态。异步回调不得把已释放 DOM 当作唯一写入目标。

### 保存、撤销、复制与删除

- 保存前同步 `dirtyIds` 中仍挂载的节点，再从 `nodeOrder` 和 `modelsById` 序列化全部节点。
- 撤销快照来自模型存储，不依赖当前视口挂载集合。
- 恢复快照时重建模型和空间索引，再只挂载当前视口节点。
- 复制读取选中模型；粘贴创建新模型并更新索引。
- 删除先从模型、空间索引、选择集合和连接数据中移除，再释放已挂载 DOM。
- 组计数和批量操作使用模型关系计算，不能只统计已挂载 DOM。

## 错误处理与恢复

- 单个节点适配失败时保留原始模型，挂载轻量错误卡片，其他节点继续显示。
- 错误卡片允许重试挂载；重试不得生成重复节点 ID。
- 图片缩略图失败时显示占位并退避重试，主动查看仍可请求原图。
- 模型与空间索引不一致时自动重建索引，并记录诊断信息。
- 已卸载节点收到过期异步回调时，只更新匹配修订号的模型；旧回调不得覆盖新内容。
- 虚拟化任务被新一帧视口状态取代时取消未执行任务，以最新视口为准。
- 页面隐藏时暂停非必要挂载和原图晋级；恢复可见时重新查询视口。
- 旧画布中未知节点类型使用通用只读错误卡片展示其位置和原始类型，原始数据继续参与保存。

## 性能预算与验收标准

标准压力画布包含 3000 个混合节点、约 1500 张图片和 2999 条连接，节点分布覆盖远超 `4000 × 3000` 的正负坐标区域。

1. 首屏可见节点在点击打开后 1 秒内出现，不等待全部复杂 DOM 创建。
2. 平移和缩放帧延迟 P95 不高于约 18ms，不出现连续超过 50ms 的长任务。
3. 分散布局下完整挂载节点数量稳定在视口与缓冲区范围，目标不超过约 150–200 个。
4. 单次可见连接刷新目标低于 16ms，且不随画布总节点数呈二次增长。
5. 平移到远端节点后，文字和节点壳在两帧内挂载；图片资源完成后不得保持空白。
6. 视口外图片不请求原图，卸载节点释放图片显示资源。
7. 保存并重新打开后，3000 个节点的字段、坐标、尺寸、图片、任务状态和 2999 条连接完整一致。
8. 旧格式压力画布首次打开即使用相同虚拟化路径，用户无需执行迁移操作。
9. 删除、复制、撤销和组操作对视口外节点同样正确。
10. 现有自动检查、浏览器关键路径和完整 `npm run check` 全部通过。

## 测试策略

### 纯规则测试

- 空间网格插入、移动、删除、跨单元格节点和负坐标查询。
- 挂载矩形、卸载矩形及边缘迟滞。
- 完整、紧凑和概览显示等级选择。
- 可见连接包围盒裁剪和端点几何。
- 旧节点字段规范化、未知字段透传和序列化往返。

### 状态与适配器测试

- 节点模型与挂载 Map 的一致性。
- 每种节点适配器的挂载、写回、释放和重新挂载。
- 视口外节点参与保存、撤销、复制、删除和组计数。
- 异步结果写入未挂载节点模型，重新挂载后正确显示。
- 单节点恢复失败不影响其他节点。

### 浏览器压力测试

- 3000 节点首次打开时间、DOM 数量、长任务和堆内存。
- 连续平移、缩放、快速反向移动时的帧延迟及挂载抖动。
- 从原点移动到正负远端坐标，验证文字、图片和连接恢复。
- 高密度和低缩放场景触发轻量显示，选中后恢复完整节点。
- 视口外图片网络请求和离开视口后的资源释放。
- 保存、重新加载并逐字段比较完整模型与连接。
- 用旧格式画布重复相同测试，验证自动适配路径。

### 回归测试

- 节点拖动、缩放、选择、框选、分组、连接和断开。
- 文字、图片、上传、图集、LLM、Comfy、循环、网格编辑器、Minimax H3、视频、音频和视频输出节点。
- 生成、下载、裁剪、遮罩、复制、撤销、历史打开和画布保存。
- 语法检查、现有静态契约检查和完整 `npm run check`。

## 预期代码边界

- `canvas-virtualization-rules.js`：纯几何、空间索引、显示等级和可见连接规则。
- `canvas-virtual-store.js`：节点模型、顺序、修订号、脏节点和序列化往返。
- `canvas-virtualizer.js`：挂载协调、帧预算、固定节点和资源释放。
- `script.js`：接入现有节点渲染、交互、保存、撤销和异步任务。
- `styles.css`：无界平面、轻量节点壳和显示等级样式。
- `index.html`：加载新增模块并更新缓存版本。
- `tools/`：规则、静态契约、浏览器压力和旧画布兼容测试。

模块之间以模型和明确接口通信；空间索引不读取 DOM，模型存储不负责渲染，虚拟化协调器不包含具体节点业务逻辑。
