# CPAMP 启动可靠性修复设计

## 目标

让当前电脑上的 CPAMP 在 WSL 重启或 WSL 地址变化后，仍能通过一次双击可靠启动，并保持以下地址可用：

- 管理页：`http://localhost:18317/management.html`
- 本机 API：`http://127.0.0.1:8317`
- 局域网 API：`http://192.168.1.8:8317`

## 已确认根因

容器内部服务正常，但原启动脚本在 Docker 启动前取得一次 WSL IP。WSL 网络随后从 `172.18.112.203` 切换到 `172.18.164.3`，Windows `portproxy` 仍指向旧地址，因此管理页超时，局域网中继也无法通过启动验证。

## 设计

1. 把“连续读取到相同 WSL IP 才认为网络稳定”的逻辑放入独立辅助脚本，便于自动测试。
2. 启动 Docker 后重新等待 WSL 地址稳定；只使用这个最终地址创建 Windows 端口转发。
3. 验证时若发现 WSL 地址再次变化，重新创建转发后再测，最多进行有限次数重试。
4. 清理失效的局域网中继 PID；新进程启动后必须确认 PID 仍存活并且 `192.168.1.8:8317` 已返回 HTTP `401`。
5. 新增 `启动CPAMP.bat`。双击后以绕过脚本执行策略的方式调用 PowerShell，脚本自动申请管理员权限；失败窗口保持打开并显示具体错误。

## 错误处理

- `7890` 未监听时，明确提示先启动代理软件。
- WSL 地址无法稳定时停止，不写入可能失效的转发规则。
- Docker 内服务不可访问时停止，不把问题误报成 Windows 端口故障。
- Node 中继启动失败时清理错误 PID 并显示错误。

## 验证

- 自动测试模拟地址序列“旧地址 → 新地址 → 新地址”，必须选择新地址。
- 自动测试检查 Docker 启动后才调用稳定地址逻辑，并检查双击启动器参数。
- 真实执行启动脚本，验证管理页 HTTP `200`、无密钥模型接口 HTTP `401`，以及局域网地址 HTTP `401`。
