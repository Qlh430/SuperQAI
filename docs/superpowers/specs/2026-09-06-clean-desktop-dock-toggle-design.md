# AI OS 干净桌面与 Dock 窗口切换设计

## 目标

用户登录 AI OS 后首先看到没有应用窗口的纯净桌面。无限画布只有在用户点击 Dock 图标后才打开，并先显示独立的项目管理首页；点击某张画布卡片后才进入该画布编辑器。再次点击当前已聚焦应用的 Dock 图标时，应用窗口最小化而不是继续停留在桌面。

## 已确认交互

- 登录或刷新已登录页面：只初始化桌面、Dock、账号与窗口运行时，不自动打开任何应用。
- 首次点击无限画布：创建窗口并进入 `canvasLibraryScreen`，`canvasEditorScreen` 保持隐藏。
- 点击项目中的画布卡片：同一窗口从项目首页切换到编辑器。
- 点击当前已聚焦应用的 Dock 图标：最小化该窗口。
- 点击已最小化应用的 Dock 图标：恢复窗口并保留最小化前所在页面。
- 点击正在后台显示但未聚焦的应用图标：只聚焦该窗口并保留页面。
- 关闭无限画布后重新打开：视为新的应用启动，进入项目首页。
- 通过共享文件携带 `resourceId` 打开：允许直接进入目标画布，不受普通 Dock 启动首页规则影响。

## 架构

桌面层负责窗口生命周期，不把 Dock 点击全部等同于 `openApp`。新增单一 Dock 切换入口，先读取窗口快照：当前聚焦且未最小化则调用窗口管理器的 `minimize`；已有但未聚焦或已最小化则恢复/聚焦；不存在时调用 `openApp`。普通 Canvas 新建窗口继续发送 `{ screen: "library" }`，显式 `resourceId` 参数继续走直达逻辑。

Canvas 应用继续使用同级的 `canvasLibraryScreen` 与 `canvasEditorScreen`。项目首页不是编辑器遮罩，也不渲染编辑器内容；页面切换只由 Canvas 页面状态控制器完成。

## 根因

`activateSession` 在桥接已就绪时调用 `openApp("canvas")`，`ai-os-legacy-workbench-ready` 在会话已存在时也调用同一逻辑，两条互斥时序路径共同造成登录后自动打开无限画布。Dock 当前直接调用 `openApp`；窗口管理器会复用并聚焦已有单实例窗口，因此再次点击不会最小化。

## 验收标准

1. 登录完成后 `aiOsWindowLayer` 中没有可见应用窗口，顶栏当前应用显示“工作台”。
2. 第一次点击无限画布 Dock 图标后，只显示项目首页。
3. 点击画布卡片后编辑器可见、项目首页隐藏。
4. 再次点击无限画布 Dock 图标后窗口隐藏且 Dock 标记为最小化。
5. 再点一次恢复到原编辑器；关闭后重开则进入项目首页。
6. 其他单实例应用具有相同 Dock 最小化/恢复行为。
7. 资源直达、共享、主题、缩放、资产库及完整检查不回归。

## 非目标

- 不修改数据库、共享权限、项目或画布持久化格式。
- 不实现多实例 Dock 菜单、窗口预览或动画重做。
- 不修改 `.git`，不执行提交。
