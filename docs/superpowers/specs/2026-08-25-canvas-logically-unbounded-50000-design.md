# 5 万节点保证与逻辑无硬上限画布设计

日期：2026-08-25

状态：设计已确认，待实施计划

## 1. 背景

现有画布已经完成第一阶段虚拟化：模型与 DOM 分离、视口挂载、空间网格、可见连线裁剪、图片生命周期、低缩放概览和真正无固定平面尺寸。3000 个混合节点压力画布已经可以保持有限 DOM，并能在远端恢复文字、图片和连接。

下一阶段的瓶颈已经从浏览器 DOM 转移到持久化和数据传输：服务端仍把所有画布保存在单个 `data/canvas-boards.json` 中，打开、保存和部分历史操作仍需要读取、传输或序列化完整画布。这个结构无法为 5 万节点提供稳定保证，也无法做到节点总数增长时客户端内存保持有界。

本设计把单机本地画布升级为：

- 5 万混合节点、10 万连接和 2.5 万媒体引用的明确保证规模；
- 节点数、连接数和画布尺寸不设置业务硬上限；
- 视口工作集、DOM、媒体解码和查询响应始终有界；
- 旧画布首次打开自动、无损、可回退地迁移；
- 项目继续保持轻量，不引入完整画布框架或外部数据库服务。

“逻辑无硬上限”不表示数学意义上的无限内存或无限精度。系统不设置产品数量上限，实际极限由磁盘、操作系统和有限数值范围决定；5 万节点以内提供量化性能保证，超过后通过更积极的 LOD 保持可操作和数据完整。

## 2. 目标与非目标

### 2.1 目标

1. 单画布稳定承载 50,000 个混合节点、100,000 条连接和 25,000 个媒体引用。
2. 打开、平移、缩放、编辑和保存的主要开销由可见工作集决定，而不是由总节点数线性决定。
3. 节点进入视口后始终先出现节点壳、文字或明确媒体状态，不出现无提示空白。
4. 日常保存只提交增量操作，不再重写完整画布 JSON。
5. 旧画布在首次打开时自动迁移，未知字段、任务状态和媒体引用完整保留。
6. 迁移、保存和异常退出可恢复，失败不得破坏旧数据。
7. 新增生产依赖默认保持为 0；优先使用 Node 24 内置 SQLite、浏览器原生能力和现有画布模块。
8. 复杂逻辑进入独立小模块，不继续扩大已经庞大的 `script.js` 和 `server.js`。

### 2.2 非目标

- 不迁移到 React、tldraw、PixiJS 或其他完整画布框架。
- 不把输入框、选择器、裁剪器等复杂节点全部重写为 GPU 控件。
- 不提供多用户实时协同、云同步或远程数据库服务。
- 不保证超过 5 万节点后仍保持同一性能数字，但不得设置任意数量上限或降低数据完整性。
- 不在本阶段重构与大画布无关的代理、模型路由、生成工作流和站点主题。
- 不自动删除旧 JSON、用户备份或现有未提交业务文件。

## 3. 方案比较与选择

### 3.1 采用：SQLite + R*Tree + 视口数据源 + 混合渲染

SQLite 作为本地权威数据层，R*Tree 负责视口空间查询，浏览器只缓存视口和 overscan 数据。详细节点继续使用现有 DOM；大量连接和概览图元使用轻量原生 Canvas/WebGL 层。这个方案保留现有复杂节点能力，同时消除整画布 JSON 和全量客户端模型的瓶颈。

当前开发环境的 Node v24.13.0 已实际验证可以通过 `node:sqlite` 创建 R*Tree。由于 Node 的 SQLite JavaScript API 仍处于 active development，所有调用必须隔离在仓储适配器和专用数据库 Worker 内；应用层不得直接依赖 `DatabaseSync`。SQLite 文件格式、SQL schema 和迁移协议是持久契约，底层 Node 绑定未来可以替换而不改变画布接口。

### 3.2 未采用：自研分块文件与 WAL

分块 JSON 或二进制文件可以继续兼容 Node 18，但事务、崩溃恢复、索引一致性、并发写入、schema 迁移和损坏修复都需要自行实现。它把成熟数据库已经解决的问题重新带回项目，不符合轻量和可靠性目标。

### 3.3 未采用：整体更换画布引擎

完整 Canvas/WebGL 框架能提高纯图元吞吐量，但现有复杂表单、图集、生成任务、裁剪、遮罩、网格编辑器、视频和 Agent 节点都需要重新适配。当前瓶颈主要是全量存储和传输，而非已完成虚拟化后的详细节点渲染，因此整体更换引擎成本过高。

## 4. 总体架构

```text
浏览器交互层
  ├─ CanvasViewportDataSource：视口查询、取消、预取、LRU
  ├─ CanvasPagedStore：热节点、固定节点、revision、待提交操作
  ├─ 现有 CanvasVirtualizer：DOM 挂载与 LOD
  ├─ CanvasMediaScheduler：缩略图/原图优先级和释放
  └─ CanvasPrimitiveLayer：聚合节点和大规模连接
                │
                │ 视口查询 / 增量操作 / 分页导出
                ▼
Node HTTP 服务
  ├─ CanvasQueryService：参数校验、响应预算、版本令牌
  ├─ CanvasCommandService：幂等操作、批量事务、revision
  ├─ CanvasMigrationService：旧 JSON 迁移与校验
  └─ CanvasRepositoryClient：与 DB Worker 通信
                │
                ▼
专用 Canvas DB Worker
  ├─ SQLite WAL 数据库
  ├─ 节点与连接 R*Tree
  ├─ LOD 聚合瓦片
  ├─ 操作日志与 schema 迁移
  └─ 完整性检查、备份与分页导出
```

Node 的 `DatabaseSync` 是同步接口，因此只允许在专用 Worker 线程中运行。HTTP 主线程通过有界消息队列请求数据库，长迁移、聚合重建和导出不会阻塞其他接口。数据库 Worker 是单写入者，读写事务、重试和关闭顺序由它统一管理。

## 5. 数据模型

### 5.1 画布与节点

`boards` 保存画布名称、视口、schema 版本、迁移状态、内容 revision 和时间戳。

`nodes` 保存：

- 内部整数主键与外部字符串节点 ID；
- `board_id`、稳定层叠顺序和节点类型；
- 精确的 `x`、`y`、`width`、`height`；
- 节点 revision、创建和更新时间；
- 完整 `payload_json`。

高频空间字段单独建列，未知业务字段继续保存在 `payload_json` 中并原样往返。运行时挂载状态、临时对象 URL 和 DOM 引用不得进入数据库。

`node_spatial` 使用 R*Tree 保存节点包围盒，以节点整数主键关联 `nodes`。R*Tree 的浮点边界只作为候选索引；查询边界根据坐标量级保守扩张，返回结果再用 `nodes` 中的双精度坐标精确过滤，避免边界节点漏查。

### 5.2 连接

`connections` 保存外部 ID、起止节点、端口、样式、路由元数据、revision 和完整 payload。`connection_spatial` 保存连接当前包围盒，端点移动时在同一事务中更新。

近景查询返回与扩展视口相交或端点已加载的真实连接。远景不返回全部连接，而从 LOD 瓦片返回按方向、类型和密度聚合的轻量图元。

### 5.3 媒体

原图和视频继续使用内容寻址文件或现有 URL，不把大型二进制数据塞进 SQLite。`media_refs` 只保存节点引用、资源标识、原图地址、缩略图地址、尺寸、状态和最近访问时间。资源清理必须先验证没有节点引用。

### 5.4 操作与幂等性

`board_operations` 保存操作 ID、画布、基础 revision、操作类型、必要的前后值、提交状态和时间。每个客户端批次拥有唯一操作 ID；重复提交返回原确认结果，不重复创建或删除。

撤销从“整画布快照”改为增量命令的逆操作。只对需要整体替换的导入操作创建数据库级检查点，不在浏览器中复制 5 万节点。

### 5.5 LOD 聚合瓦片

`lod_tiles` 保存按画布、层级和瓦片坐标聚合的节点数量、类型分布、状态、精确边界及少量预览 ID。层级根据实际占用范围自动扩展，不假设固定画布宽高。批量导入时一次构建；增量编辑只更新受影响瓦片。

低缩放查询先读取 LOD 瓦片，响应图元数量受预算控制。用户放大后才进入 R*Tree 详细查询，确保总节点超过保证规模时远景响应仍然有界。

## 6. 客户端数据与渲染

### 6.1 有界分页存储

现有 `CanvasVirtualStore` 演进为 `CanvasPagedStore`，只常驻：

- 当前视口与动态 overscan 内的节点和连接；
- 选中、拖动、编辑、裁剪、运行和待提交的固定节点；
- 最近访问的有限 LRU 项；
- 远景 LOD 图元。

缓存逐出前必须先提交或保留待提交操作。固定节点不得被逐出。LRU 数量和估算字节数同时受限，避免少量超大 payload 绕过条目数量限制。

### 6.2 视口查询

视口请求包含画布 ID、画布坐标边界、缩放、响应预算、已知 revision 和请求世代号。响应包含真实节点或 LOD 图元、连接、画布 revision、分页游标和是否被预算截断。

平移进入 overscan 边缘时预取相邻区域。新视口产生后取消旧请求；即使取消来不及生效，世代号不匹配的响应也不得写入当前 store。服务端只选择当前显示等级所需字段，近景需要完整 payload，远景只返回聚合和预览字段。

### 6.3 渲染分层

- 详细层继续复用现有 DOM 节点适配器，支持全部交互。
- 紧凑层使用轻量 DOM 壳，保留标题、类型、状态和缩略图。
- 概览层使用原生 Canvas/WebGL 绘制聚合节点与连接，不创建逐节点 DOM。
- 选择、编辑或主动打开的节点无条件提升为详细层。

默认不引入 PixiJS。优先使用原生 Canvas2D；只有基准测试证明连接或概览无法达到帧预算时，才启用隔离且按需加载的原生 WebGL2 模块。

### 6.4 坐标与原点重定位

画布没有固定宽高，节点可以位于正负方向。数据库保存双精度世界坐标；渲染时以当前视口中心作为局部原点，把较小的局部坐标交给 CSS、Canvas 或 WebGL，避免极远坐标导致像素抖动。保证测试覆盖至少正负 10 亿画布单位；更远的有限坐标仍可保存，并通过相同原点重定位显示。

## 7. 数据流

### 7.1 打开画布

1. 浏览器获取画布元数据、revision 和当前视口首批数据。
2. 服务端根据缩放选择详细查询或 LOD 查询，不读取全部 payload。
3. 首屏节点优先进入 store 和虚拟化挂载队列。
4. 节点壳和文字先出现，媒体调度器随后加载缩略图或原图。
5. 首屏稳定后再预取 overscan 和相邻区域。

打开时间由首屏工作集决定，而不是由 5 万节点的完整 JSON 大小决定。第 11 节的打开时间指标适用于已经迁移并处于 `active` 状态的画布；旧 JSON 的首次迁移单独计时，必须在 1 秒内显示可取消、可重试的明确进度，但完成时间可以随旧文件大小增长。

### 7.2 平移和缩放

输入事件只更新视口和本地变换，每帧最多执行一次挂载与图元刷新。视口仍在 overscan 内时不访问数据库；越过阈值后发送新查询并取消旧请求。平移进行中暂停非必要原图解码和低优先级挂载，停止后恢复细节。

### 7.3 编辑和保存

编辑先乐观写入 `CanvasPagedStore`，增加本地 revision，并加入待提交操作。操作按动画帧或短时间窗口合并，通过命令接口提交到 DB Worker 的单个事务。确认后更新服务端 revision；失败只回滚相关操作，并保留可重试状态。

节点位置或尺寸变化时，节点表、R*Tree、相邻连接包围盒和受影响 LOD 瓦片在同一事务内更新。

### 7.4 图片和媒体

节点数据与文字具有最高加载优先级。媒体按“明确占位 → 缩略图 → 原图”三级晋升：

- 概览层不加载原图；
- 紧凑层最多加载缩略图；
- 可见详细层在交互稳定后加载原图；
- 离开视口取消请求、断开观察并释放对象 URL；
- 失败显示明确状态、退避重试，不能让整个节点空白。

### 7.5 导出、导入和全画布操作

导出通过数据库游标分页流式生成兼容 JSON，不在浏览器或服务端一次构造完整对象。导入在临时画布事务中分批写入、重建索引并校验，通过后原子切换。搜索、全选、统计等全局操作在数据库执行，只把结果 ID 或聚合返回客户端。

## 8. 旧画布自动迁移

每张旧画布使用以下状态机：

```text
pending -> migrating -> validated -> active
              │
              └------> failed（旧画布继续可用，可重试）
```

迁移步骤：

1. 复制原始 `canvas-boards.json` 为带时间戳的只读备份。
2. 在临时数据库事务中分批写入画布、节点、连接和媒体引用。
3. 批量构建 R*Tree、连接包围盒和 LOD 瓦片。
4. 校验节点数、连接数、唯一 ID、端点关系、有限坐标和 payload 规范化哈希。
5. 校验通过后提交事务并标记 `active`。
6. 新数据库至少成功打开和保存一次之前，旧 JSON 不得删除或改写。

任何步骤失败都回滚临时事务。旧接口保持只读回退路径，用户仍可打开旧画布并重试迁移。迁移器必须保留未知节点类型和未知字段；无法渲染的节点显示错误壳，但原始 payload 继续参与保存和导出。

迁移应自动发生，但不能用长任务阻塞首屏：小画布可直接迁移；较大旧画布显示明确迁移进度，并在 DB Worker 中执行。

## 9. 错误处理与恢复

### 9.1 数据库生命周期

- 开启 WAL、外键约束、defensive 模式和 busy timeout。
- 所有写操作经过单写入队列和事务。
- 正常关闭时停止接收新命令、排空已确认队列、checkpoint 后关闭数据库。
- 异常退出后依靠 WAL 恢复已提交事务；未确认客户端操作从待提交队列重发。
- 启动执行轻量 `quick_check`；发现异常先复制数据库现场，再尝试恢复或回退备份，禁止直接覆盖损坏文件。

### 9.2 Worker 与请求失败

DB Worker 意外退出时，HTTP 层暂停写入、保留有界等待队列并重启一次。重启后先检查数据库和操作幂等表，再恢复查询。重复失败进入只读保护模式，界面明确提示，不继续冒险写入。

视口请求超时或被取消时保留当前已显示内容；不得先清空画布再等待新响应。网络或本地服务恢复后按最新世代号重试。

### 9.3 版本和冲突

节点和画布都有 revision。单机正常路径采用乐观并发控制：基础 revision 匹配才提交；不匹配时读取服务器最新值，并只对可安全重放的移动、文本输入等操作重放。不能自动合并的修改保留本地副本并提示用户选择，绝不静默覆盖。

### 9.4 媒体失败

媒体状态与节点基础内容分离。缩略图或原图失败时，节点标题、状态、控件和保存数据仍正常出现。媒体任务带超时、指数退避、最大并发和手动重试入口。

## 10. 轻量化预算

1. 不增加完整画布框架，不迁移现有 UI 技术栈。
2. 新增第三方生产依赖默认保持为 0；Node 内置 SQLite 通过适配层使用。
3. 支持的本地运行时提升为 Node 24.13.0 或更高的 Node 24 LTS；便携包和启动脚本必须验证或携带兼容运行时。
4. 新增浏览器模块压缩后总量目标不超过 150KB；概览/WebGL 模块按需加载。
5. 任意缩放级别详细 DOM 节点不超过 800，画布相关总 DOM 不超过 1200。
6. 浏览器画布相关 JavaScript heap 稳态不超过 350MB。
7. Node 服务端因画布数据层增加的 RSS 稳态不超过 250MB。
8. 缓存同时按条目数和估算字节数淘汰，不能随总节点数线性增长。
9. 数据库响应和浏览器挂载都有明确数量与时间预算；超过预算返回游标或 LOD，不一次返回全部数据。
10. 压力测试截图、临时数据库和性能追踪写入忽略目录，仓库只保留测试程序、固定夹具和最终报告。

## 11. 性能与正确性验收

### 11.1 基准环境

Windows 10/11、4 核 CPU、16GB 内存、集成显卡、SSD、1920×1080、当前稳定版 Chrome 或 Edge。

标准压力画布包含：

- 50,000 个混合节点，其中包含 15,000 个文字或基础节点、15,000 个图片节点、10,000 个生成或复杂表单节点、5,000 个音视频节点，以及 5,000 个组、Agent 或工作流节点；
- 100,000 条连接；
- 25,000 个图片或媒体引用，分布在图片、生成结果和音视频节点中；
- 稀疏、密集、重叠和正负远坐标区域；
- 至少覆盖正负 10 亿画布单位。

### 11.2 时间和帧预算

- 冷启动打开标准画布后 2 秒内可操作，热启动 1 秒内可操作。
- 平移和缩放 P95 帧耗时不超过 20ms，P99 不超过 50ms。
- 拖动、选择和输入响应 P95 不超过 50ms。
- 本地视口查询 P95 不超过 75ms。
- 平移和缩放期间不得出现超过 100ms 的主线程长任务。
- 节点进入视口后一帧内出现节点壳或明确状态，文字和基础内容 300ms 内可见。
- 本地图片缩略图 800ms 内可见；失败时在相同时间内出现明确错误占位。

### 11.3 有界资源

- 详细 DOM、总画布 DOM、浏览器 heap 和服务端 RSS 满足轻量化预算。
- 反复往返同一区域后 DOM 不持续增长，LRU 能回到稳定区间。
- 视口响应不得因低缩放命中全部节点而返回无界 payload。
- 视口外图片不得晋升原图，离开视口后释放显示资源。

### 11.4 数据完整性

- 旧画布迁移前后节点数、连接数、ID、端点、关键字段和 payload 哈希一致。
- 保存、关闭、重新打开后逐字段一致。
- 导出再导入后逐字段一致。
- 删除、复制、撤销、分组、生成任务和视口外节点操作正确。
- 强制结束服务、关闭浏览器和保存中断后，已确认操作恢复，未确认操作可安全重试。
- 超过 5 万节点后继续允许创建、保存、查询和导出，只允许提高 LOD，不允许丢弃数据。

## 12. 测试分层

### 12.1 日常自动测试：2–3 分钟

- schema、仓储、R*Tree 和 LOD 纯规则测试；
- 节点/连接增量 CRUD、幂等重试和 revision 冲突；
- 视口查询预算、分页、取消和过期响应；
- 媒体优先级、取消和错误占位；
- 旧字段透传和小型旧画布迁移；
- 现有语法、静态契约和关键回归测试。

### 12.2 本次交付强制测试：10 分钟

在标准 5 万节点画布上连续执行平移、缩放、远端跳转、选择、编辑、创建、移动、删除、撤销和媒体加载。记录帧耗时、查询延迟、DOM、heap、RSS、长任务和内容可见时间。

10 分钟结束时：

- 内存应进入稳定区间，较稳定值增长不超过 15%；
- DOM 不持续增长；
- 不出现无提示空白节点；
- 不出现数据丢失、重复操作或过期视口覆盖；
- 保存重开校验通过。

### 12.3 快速崩溃恢复测试

在迁移、批量编辑和自动保存的不同阶段强制结束 Worker 或服务进程，立即重启并校验 WAL、幂等操作、只读保护和备份回退。不通过等待时长模拟故障。

### 12.4 可选发布级测试

60 分钟 soak test 只在大版本发布、数据库 schema 大改或怀疑存在慢性内存泄漏时后台执行。它不是日常测试，也不阻塞本次交付。

## 13. 模块边界

服务端新增或拆分：

- `canvas-db-worker.js`：唯一 SQLite 所有者、prepared statements、事务和关闭流程。
- `canvas-repository.js`：与 DB Worker 通信的稳定仓储接口。
- `canvas-schema.js`：schema、版本和迁移 SQL。
- `canvas-query-service.js`：视口、LOD、分页和响应预算。
- `canvas-command-service.js`：增量命令、幂等、revision 和逆操作。
- `canvas-legacy-migrator.js`：旧 JSON 备份、迁移、校验和回退。

浏览器新增或演进：

- `canvas-viewport-data-source.js`：请求世代、取消、overscan 和预取。
- `canvas-paged-store.js`：热模型、固定节点、LRU 和待提交操作。
- `canvas-media-scheduler.js`：节点优先、缩略图、原图、取消和重试。
- `canvas-primitive-layer.js`：LOD 节点和大规模连接图元。
- `canvas-virtualizer.js`：继续负责 DOM 生命周期，通过分页 store 获取模型。

`script.js` 只负责把现有交互接到这些接口；`server.js` 只注册路由和生命周期，不包含 SQL、空间查询或迁移细节。

## 14. 实施顺序与发布策略

1. 建立 SQLite Worker、schema、仓储契约和纯规则测试。
2. 实现旧 JSON 迁移、校验、备份和只读回退。
3. 增加视口查询与分页客户端数据源；迁移验证期间保留旧 JSON 的只读打开路径作为功能开关回退，不允许两套写入路径同时修改同一画布。
4. 将保存、撤销和全局操作改为增量命令与数据库查询。
5. 接入连接空间查询、LOD 瓦片和轻量概览层。
6. 接入媒体调度和有界 LRU，完成所有复杂节点回归。
7. 运行 5 万节点基准和 10 分钟强制稳定性测试。
8. 达到门槛后默认启用新路径；旧 JSON 只读回退至少保留一个发布周期。

每一步都必须通过独立测试和功能开关验证，不能一次性替换全部持久化路径。迁移成功且经过保存重开验证之前，旧文件和用户备份不得清理。

## 15. 仓库清理原则

当前大量未提交文件混合了有效运行模块、测试、设计文档、恢复备份和生成截图。实施阶段只执行以下清理：

- 把可再生的压力测试截图、trace、临时数据库和 PID 文件加入忽略规则；
- 删除前先确认没有代码、文档或构建脚本引用；
- 保留恢复备份、旧画布数据和用户业务文件，除非用户明确指定删除目标；
- 设计、实现计划、固定测试夹具和最终基准报告纳入版本控制；
- 相关运行代码和测试按阶段创建清晰检查点，不重置现有用户改动。
