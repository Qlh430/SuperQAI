# 模型下拉悬停颜色设计

## 问题与根因

模型下拉框已经定义了 `option:hover` 和 `option:focus-visible` 的主题浅色背景，但深色模式下普通选项规则的选择器优先级更高。浏览器实测选项已进入 `:hover` 状态，计算背景仍保持 `--field`，因此用户看不到预选反馈。

## 采用方案

为深色模式补充同等或更高优先级的未选中项悬停与键盘聚焦规则：

- 未选中项悬停或聚焦时使用 `var(--accent-soft)` 背景。
- 文字继续使用 `var(--ink)`。
- 已选中项保持 `var(--accent)` 与 `var(--accent-contrast)`。
- 使用 `:not(:checked)`，避免悬停覆盖当前选中的实色状态。

## 交互约束

- 不添加位移、缩放、阴影、提示线或过渡动画。
- 不修改原生 `<select>`、模型数据、选择事件和键盘行为。
- 颜色自动跟随黄黑、红蓝及其他配色主题。
- 不支持可样式化原生选项的浏览器继续使用系统默认悬停反馈。

## 验证

- 源码回归检查要求深色模式存在 `option:not(:checked):hover` 与 `option:not(:checked):focus-visible` 的主题色规则。
- 浏览器中验证黄黑深色主题：悬停前为 `--field`，悬停后为 `--accent-soft`。
- 验证选中项悬停后仍为 `--accent`。
- 运行完整 `npm run check` 与 `git diff --check`。

## 非目标

- 不制作动画。
- 不开发自定义下拉组件。
