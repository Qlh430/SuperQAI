# Agent 自动路由与候选池设置设计

> 已被 `2026-08-21-agent-model-ranking-design.md` 取代。当前实现不再提供速度、均衡、稳定等策略选项；用户只选择一个主候选，备用顺序由可靠性排名自动维护。

> 实施状态：已完成。验证：`npm run check`、当前代码服务的浏览器检查、候选池端点检查和便携版依赖检查均通过。

## 目标

让画布 Agent 默认从已配置且可用的模型中自动择优，并在设置页用中文展示路由策略和候选池状态；用户可改为速度优先、稳定优先或指定首选模型。

## 决策

- 默认策略是 `balanced`（均衡推荐），不再把 `CANVAS_AGENT_MODEL` 当作所有请求的强制优先项；环境变量仅保留为没有设置候选时的保底路由。
- `speed`、`balanced`、`stability` 使用相同候选集，但对首字延迟、失败率和连续失败的权重不同。
- `preferred` 仅在用户在设置中明确选择模型时启用；它在健康可用的候选之间优先匹配该模型，仍可被熔断和故障切换覆盖。
- 候选池自动从已保存且启用的 API、远程 `/models` 模型列表和 Agent 能力实测记录构建。同一模型在不同 API 接入、地址或 Key 下是独立候选，分别记录首字延迟、成功率、连续失败和熔断状态。通过实测（文本 + 工具调用）的候选才可执行；新发现的文本模型显示为“待 Agent 实测”，不会在后台静默发起付费推理。
- 每次读取设置页候选池、保存 API 设置、Agent 实测完成或路线健康记录变更时，候选池会重新计算。界面不显示密钥、模型请求内容或内部模型名称给普通 Agent 对话面板。

## 设置数据

在 `settings.json` 中持久化：

```json
{
  "agentRouting": {
    "mode": "balanced",
    "preferredModel": ""
  }
}
```

`mode` 只能是 `speed`、`balanced`、`stability`、`preferred`。当 `mode` 不是 `preferred` 时，`preferredModel` 仅保留为用户下次切换可用的选择，不影响排序。

## 自动评分

候选均先满足当前任务能力要求、处于启用状态且未熔断。随后按策略计算分数：

- 首字响应时间采用 EWMA，最近一次样本占 30%，历史占 70%。
- 失败率会加入惩罚，避免偶尔很快但常超时的接口。
- 每个连续失败会加入额外惩罚；达到阈值后进入短熔断，鉴权/余额问题进入长熔断。
- 未实测候选不会被执行；已实测但没有历史数据的候选附带小幅未知惩罚。

权重从速度优先到稳定优先逐步增加失败率与连续失败的影响。一次任务成功路由后仍固定该候选，只有失败才切换，保障工具链上下文一致。

## 界面

API 接入页顶部增加“Agent 路由”卡片：策略选择、首选模型下拉框、可用数量、待实测数量和刷新动作。下方候选池以轻量表格展示模型、API 接入名称、接口地址、状态、首字延迟、成功率、连续失败次数和当前选择依据。

只有进入 API 设置页、点击刷新或保存 API 设置时，服务端才会异步扫描已启用接口的 `/models` 列表，并把结果限制为当前 Agent 模型、用户已配置的文本模型和已有实测记录，避免加载大量无关模型。扫描不发起模型推理，也不占用画布主线程；“Agent 实测”仍由用户主动点击。

## 错误与兼容

- 旧设置缺少 `agentRouting` 时自动补齐为 `balanced`。
- 无可用候选时仍使用环境变量保底；保底失败后沿用既有错误提示与重试检查点。
- 无法读取候选池端点时，设置页显示可恢复的错误，并保留 API 配置编辑能力。

## 验证

- Router 单测覆盖四种排序策略、熔断过滤、显式首选和历史分数。
- Server 静态/行为测试覆盖设置归一化、候选池接口及不泄露 key。
- UI 测试覆盖策略控件、自动候选池状态和刷新入口。
- 完整 `npm run check`、浏览器检查及便携版检查必须通过。
