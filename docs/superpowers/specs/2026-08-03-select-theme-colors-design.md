# 下拉选项主题色一致性设计

## 背景与根因

在线生图的模型选择使用原生 `<select>`。项目已经为支持 `appearance: base-select` 的浏览器提供了主题变量样式，但更高优先级的深色模式规则仍将选中项背景写死为 `#60a5fa`、文字写死为 `#07111f`，同时把普通选项背景写死为 `#101827`。因此黄黑主题的 `--accent: #ffd100` 无法生效，界面出现蓝色高亮。

## 采用方案

保留原生 `<select>` 和现有 `base-select` 渐进增强，仅把通用及深色模式下拉选项的固定颜色替换为主题令牌：

- 普通选项背景使用 `var(--field)`。
- 普通选项文字使用 `var(--ink)`。
- 选中项背景使用 `var(--accent)`。
- 选中项文字使用 `var(--accent-contrast, #202020)`。

规则保持全局适用，使在线生图、画布和其他原生下拉框都跟随当前配色主题。黄黑主题显示黄色选中态；红蓝、芥末蓝等主题使用各自的强调色。

## 约束

- 不修改模型列表、保存偏好或表单事件逻辑。
- 不新增第三方依赖或自定义下拉组件。
- 保持浅色、深色以及不支持 `base-select` 的浏览器可用。
- 保证选中文字使用主题对比色令牌，避免强调色背景上的可读性下降。

## 验证

- 源码回归检查禁止深色选中项继续使用硬编码蓝色。
- 浏览器中验证黄黑深色主题：普通选项等于 `--field`，选中项等于 `--accent`，文字等于 `--accent-contrast`。
- 浏览器中验证红蓝深色主题会自动切换到其强调色。
- 运行项目完整 `npm run check` 与 `git diff --check`。

## 非目标

- 不重构所有表单控件。
- 不改变下拉框尺寸、字体、选项排序或键盘行为。
