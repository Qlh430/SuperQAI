# 画布图片原子清晰度升级设计

## 背景

画布图片采用缩略图与原图两级加载。当前质量切换调度在请求新质量前调用 `unload()`，会立即删除正在显示图片的 `src`；原图任务被缩放交互打断时也会再次清空图片。因此本地缓存命中时仍会出现短暂空白，网络较慢时会表现为图片消失和反复闪烁。

部分图片在原图已经加载后仍保持模糊，直到画布再次移动。这与可见图片使用 `content-visibility:auto`、图片源切换和画布整体 CSS transform 共同造成的陈旧栅格有关。当前虚拟化已经限制实际挂载节点，可见图片不需要依赖 `content-visibility:auto` 节省绘制。

## 目标

- 缩略图升级到原图的整个过程中，当前图片始终可见。
- 缩放、平移、请求取消、失败和重试均不能清空可见图片。
- 用户停止交互后，符合原图条件的可见图片无需再次移动画布即可自动变清晰。
- 原图加载失败时继续显示现有缩略图，不退化为空白或错误占位。
- 不增加常驻的第二套图片 DOM，不扩大节点挂载上限，不影响原有图片预览、裁剪和高倍查看交互。
- 保持缩略图与原图并发限制，避免大画布产生下载和解码洪峰。

## 非目标

- 不改变画布节点的数据格式、图片 URL 或缩略图存储协议。
- 不强制所有离屏节点加载原图。
- 不调整 5 万节点场景层的纹理预算或画布节点虚拟化阈值。
- 不引入常驻双图片层、全画布原图预载或新的前端框架。

## 方案比较

### A. 原子单图片升级（采用）

保持当前 `<img>` 和已显示资源。后台预载并解码目标原图，只有在请求仍然有效且解码完成后才提交新 `src`。取消或失败只撤销目标请求，不撤销当前显示内容。

优点是 DOM、显存和节点结构不增加，适合大画布；缺点是需要把“当前显示质量”和“正在请求质量”分开管理。

### B. 双图片层交叉淡入

缩略图与原图分别使用两个 `<img>`，原图加载后淡入。

视觉实现直接，但会增加图片 DOM、合成层和显存，不适合数百个挂载图片节点。

### C. 可见节点直接加载原图

取消缩略图升级过程，所有可见节点直接请求原图。

实现简单，但会放大网络、解码和内存压力，破坏大画布流畅性。

## 架构设计

### 1. 分离显示状态与请求状态

`ImageResourceManager` 继续使用 `data-image-quality` 表示已经显示的质量，使用 `data-requested-quality` 表示当前目标质量。当元素已经显示缩略图或原图时，请求中的状态只记录在目标质量和请求令牌中，`data-image-quality` 保持当前显示质量；只有首次加载且没有任何可显示资源时才允许将显示质量标记为 `loading`。进入请求状态不得删除已有 `src`，也不得把已经显示的缩略图当作未加载内容。

调度器切换任务时只取消旧任务的意图，不调用 `unload()`。只有以下情况允许真正释放图片：

- 图片离开虚拟化保留范围并经过现有延迟卸载；
- 节点被卸载或删除；
- 用户切换到非画布视图，且该图片不再需要显示；
- 场景层接管当前密集视口。

### 2. 原图预载、解码和原子提交

原图请求仍通过受控队列执行。预载图片触发 `load` 后先调用 `decode()`；解码失败但资源已完整加载时允许继续提交，网络错误则保留现有缩略图。

提交前再次验证：

- 节点仍连接在 DOM；
- 当前请求目标仍为原图；
- 图片的原始 URL 与任务创建时一致；
- 没有更新的质量请求取代当前任务。

提交时保留当前缩略图作为元素背景兜底，设置已经解码的原图 URL，等待目标 `<img>` 完成解码并经过一帧绘制后再清除背景。这样即使浏览器在 `src` 切换时短暂清除内容，用户仍看到缩略图。

### 3. 取消、降级与失败

- 原图任务在交互期间被暂停或取消：当前缩略图继续显示，旧任务完成后因请求令牌失效而不得覆盖新状态。
- 原图失败：恢复请求状态为当前显示质量，保留缩略图；沿用现有失败退避，避免重复请求闪烁。
- 原图已经显示后收到缩略图请求：不主动降级，不替换已经清晰的内容。
- 图片真正离屏：沿用延迟卸载，释放 `src` 和兜底背景。

### 4. 静止画布清晰度收敛

停止缩放或平移后的现有空闲计时器继续决定原图升级时机。每个新挂载图片都会根据当前 `detailReady` 状态独立计算目标质量，因此不依赖下一次画布移动。

可见的已挂载图片不再使用 `content-visibility:auto`；虚拟化和视口资源管理已经负责限制挂载与下载。原图提交完成时更新质量状态并触发一次元素级重绘，使浏览器丢弃旧缩略图栅格，而不改动画布 transform。

### 5. 性能边界

- 缩略图并发维持 6，原图并发维持 2。
- 不新增常驻图片元素；临时预载对象在任务完成后可回收。
- 不为离屏节点请求原图。
- 相同图片、相同目标质量的重复调度保持幂等。
- 原图切换不得触发全画布重绘，只刷新对应图片元素。

## 数据流

1. 画布缩放或平移开始，质量计算选择缩略图作为交互期目标。
2. 已显示缩略图保持不变；如果存在原图任务，只使其请求令牌失效。
3. 交互停止并超过空闲阈值，质量计算将可见且需要清晰细节的图片目标设为原图。
4. 原图队列预载并解码资源，期间缩略图继续显示。
5. 请求仍有效时原子提交原图；目标元素完成解码后标记为 `original` 并进行元素级重绘。
6. 请求失败或被取代时丢弃结果，当前显示资源不变。

## 错误处理

- 原图网络错误、解码错误或超时不能删除现有缩略图。
- 旧请求晚到时通过请求令牌和 URL 校验丢弃，不得覆盖更新后的节点图片。
- 节点在请求期间被卸载时安全结束任务，不访问已释放节点。
- 没有缩略图可用的首次加载仍允许显示现有背景占位，但成功加载后不得在质量切换中再次回到空白。

## 测试设计

### 单元回归

- 已显示缩略图请求原图时，整个请求期间 `src` 始终存在。
- 取消原图请求不会删除当前 `src`。
- 原图失败继续显示缩略图并恢复稳定状态。
- 旧原图请求晚到不会覆盖更新后的 URL 或目标质量。
- 已显示原图收到缩略图目标时不会降级。
- 原图完成后目标状态为 `original`，且完成逻辑等待解码。

### 浏览器回归

- 在“画布 17”中将同一图片固定在屏幕中心，从 55% 连续缩放到 217%。以 10 ms 采样，挂载期间 `src` 空窗计数必须为 0。
- 停止缩放后不再发送任何输入，图片必须自动进入 `original`，自然宽度与原图一致。
- 对多张图片连续缩放，页面错误为 0，图片不能反复在 `thumbnail/unloaded/loading` 之间震荡。
- 原图请求失败场景中缩略图持续可见。

### 全量回归

- 旧画布矩阵、画布历史缩略图、图片按需加载、画布浏览器核心和全项目检查通过。
- 5 万节点性能门槛与场景层测试不得退化。

## 验收标准

- 可见图片质量升级期间没有任何无 `src` 的采样帧。
- 原图加载过程中视觉内容连续，没有闪白、闪背景或图片消失。
- 停止交互后无需再次移动画布即可完成原图升级。
- 原图失败仍显示缩略图。
- 原有缩放、放大查看、裁剪、节点虚拟化和旧画布打开行为保持不变。
