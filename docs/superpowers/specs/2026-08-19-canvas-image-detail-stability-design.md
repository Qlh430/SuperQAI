# 画布图片清晰度稳定策略设计

## 背景

画布当前使用按需图片资源策略：只有画布缩放达到 160% 且停止操作 300ms 后，可见图片才加载原图。任何平移或缩放都会立即把 `canvasDetailReady` 设为 false，导致已经加载完成的原图切回最长边 768px 的缩略图；停止后再切回原图，因此用户会看到明显的“移动时变模糊，停下后再清晰”。

现有规则还只检查整个画布的缩放比例，不考虑图片节点在屏幕上的实际显示尺寸。即使用户把图片节点放得很大，只要画布缩放低于 160%，图片仍保持缩略图，也会显得模糊。

## 目标

- 画布缩放达到 100% 时，可见图片停止操作 300ms 后加载原图。
- 画布缩放低于 100% 时，如果图片节点在屏幕上的最长显示边超过 768px，也应在停止操作后加载原图。
- 已经加载清晰原图且仍满足原图显示条件的图片，在平移或缩放过程中继续保持原图，不再闪回缩略图。
- 新进入视口或尚未加载原图的图片，在持续操作期间仍使用缩略图，停止 300ms 后再按需加载原图。
- 视口外图片继续卸载；低倍率下显示尺寸较小的节点继续使用缩略图。

## 非目标

- 不让画布中所有图片始终加载原图。
- 不修改原图文件、缩略图尺寸、缩略图质量、下载地址或画布序列化结构。
- 不改变历史记录、引用卡片、聊天图片和编辑器的图片加载规则。
- 不增加新的用户设置或界面控件。

## 设计

### 1. 原图需求判定

将画布原图的基础缩放阈值从 `1.6` 调整为 `1`。可见图片满足以下任一条件时，视为“需要原图”：

1. 画布缩放比例大于或等于 100%；
2. 图片节点的画布尺寸乘以当前画布缩放后，屏幕最长显示边大于 768px。

屏幕显示尺寸由现有节点 `renderedWidth`/`renderedHeight`（缺失时使用节点宽高回退值）乘以 `canvasState.scale` 得到。判断使用缩略图最长边常量 `THUMBNAIL_MAX_SIDE`，避免另设不一致的数值。

### 2. 移动期间保持已加载原图

图片质量规则增加当前资源状态输入。对可见且“需要原图”的图片：

- `detailReady` 为 true 时返回原图；
- 当前已经是 `original` 时，即使移动刚把 `detailReady` 设为 false，仍返回原图；
- 当前是缩略图、加载中或未加载时，在持续操作期间返回缩略图。

这样只保留已经清晰的图片，不会因为拖动画布而启动一批新的原图加载。

### 3. 停止操作后的加载

保留 300ms 空闲计时，但计时不再因画布缩放低于 100%而提前退出。计时结束后设置 `detailReady = true`，由每张图片自己的“100%阈值或屏幕显示尺寸”条件决定是否加载原图。

在低倍率全局视图中，节点屏幕尺寸通常小于 768px，因此仍只使用缩略图；被放得很大的节点即使画布低于 100%，也能在停止操作后加载原图。

### 4. 降级与卸载

- 图片离开带缓冲的可见区域时继续卸载。
- 画布缩小且节点屏幕最长边不再超过 768px时，图片可恢复缩略图。
- 覆盖编辑、裁剪等明确要求原图的 `canvasForceOriginal` 行为保持最高优先级。
- 原图加载失败时继续沿用现有缩略图回退逻辑。

## 测试

扩展纯规则检查，覆盖：

1. 原图基础阈值为 100%。
2. 100% 且空闲时加载原图。
3. 100% 持续移动时，新图片仍使用缩略图。
4. 100% 持续移动时，已经加载的原图保持原图。
5. 低于 100% 但屏幕最长边超过 768px时，空闲后加载原图。
6. 低于 100% 且屏幕尺寸较小时继续使用缩略图。
7. 视口外图片仍返回卸载状态。

扩展画布接线检查，确认每张图片把当前质量状态和屏幕显示尺寸传入规则，并确认 300ms 计时不再被全局缩放阈值提前阻断。最后运行项目完整检查。

## 验收标准

- 画布达到 100% 后停止 300ms，可见图片变为清晰原图。
- 已清晰图片在拖动画布或继续缩放时不出现缩略图闪烁。
- 持续移动时，新进入视口的图片不会立即批量加载原图。
- 低于 100% 时，放大到屏幕最长边超过 768px的图片节点能够显示原图。
- 低倍率全局浏览时，小节点保持缩略图且视口外图片继续卸载。
