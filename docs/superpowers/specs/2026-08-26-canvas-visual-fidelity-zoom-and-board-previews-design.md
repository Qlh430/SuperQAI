# 画布无感缩放与历史缩略图设计

## 目标

无限画布在任意缩放比例下都必须保持同一套完整节点外观。用户只能感知到节点随画布连续变大或变小，不能看到“完整节点 ↔ 摘要卡 ↔ 区域方框”的外观切换。

同时恢复“选择画布”中的可辨识缩略图，并保证旧画布无需手工转换即可自动获得预览。

## 已确认的根因

1. 当前 3099 端口的 Node 进程启动于新规则之前，数据库 Worker 仍在内存中执行“低缩放即进入 LOD”的旧逻辑。实时接口已复现：“苹果”只有 94 个节点，11% 时却返回 `mode=lod` 和 `lodLevel=2`。
2. 新的画布列表接口只返回分页元数据，不再附带 `board.nodes`。现有历史卡片仍只从 `board.nodes` 提取图片，因此所有卡片都退化为标题占位。
3. 现有摘要卡和聚合方框虽然能降低 DOM 数量，但改变了节点的视觉语言，不符合无感缩放要求。

## 设计原则

- 缩放只改变尺寸，不改变节点的外观结构、图片、颜色、边框和层级。
- LOD 只是内部渲染技术，不是可见的产品形态。
- 节点在屏幕上足够大时，必须使用完整 DOM；只有在超高密度、实际像素不可辨时，才能换为视觉等价的场景精灵。
- 数据安全优先：不修改旧节点载荷，不为测试写入正式画布。
- 图片资源优先读取已有缩略图，低缩放不直接加载原图。

## 渲染架构

### 1. 普通视口：始终使用完整节点

当视口候选节点不超过 800 个时，无论当前是 5%、11% 还是 500%，都挂载现有的完整节点 DOM。

- 禁止创建 `.canvas-node-virtual-summary`。
- 禁止渲染“图片区域”、“图集区域”或节点数量方框。
- 保留节点原有图片、标题、输入区、按钮、状态和连接点的视觉。
- 在屏幕尺寸过小时，节点内部控件保留外观，但事件命中限制为节点级选择和拖动；进入可操作的屏幕尺寸后再恢复内部控件交互。这不改变视觉。

### 2. 超高密度视口：视觉等价场景精灵

当候选节点超过 800 个时，DOM 仍保持 800 上限，其余节点由 Canvas/OffscreenCanvas 场景层绘制。这一层不绘制聚合卡，而是绘制与原节点一致的单节点精灵：

- 每个精灵使用节点原始几何尺寸、层级和类型样式。
- 图片节点使用缩略图纹理；缩略图未就绪时使用与原节点相同的背景和骨架，不显示新的类型标签。
- 文字和控件只在投影后仍有足够像素时绘制；小于可辨像素时自然消失，等价于完整 DOM 经 CSS transform 缩小后的结果。
- 屏幕空间完全重叠的节点依照 z-order 遮挡，只绘制实际可见的顶层精灵，不用区域计数代替。
- 场景层与 DOM 层使用相同的位置、尺寸、缩放和资源，通过双缓冲在同一帧完成原位交接，不出现闪烁、突跳或卡片变形。

表示层选择依据是候选数量、屏幕占用像素和遮挡关系，不再使用 65% 之类的可见外观阈值。

### 3. 交互与命中测试

场景精灵保留节点 ID 和屏幕命中区域。点击或开始拖动时，目标节点会在原位被提升为完整 DOM 并锁定，场景精灵在同一帧被替换。节点不会因为表示层切换而丢失选中、拖动、生成状态或未保存编辑。

## 画布历史缩略图

### 持久化预览索引

数据库新增轻量的画布预览候选索引，不再为了列表卡片返回整张画布的节点数据。

每个候选项保存：

- `board_pk`
- `node_id`
- 优先级最高的缩略图或预览地址
- 节点 z-order
- 更新时间

节点新增、更新或删除时增量维护该索引。画布列表接口一次查询每张画布最多 4 张预览，以 `previewImages` 返回。即使单画布包含 5 万节点，列表也不需要扫描或传输全部节点。

### 旧画布自动回填

启动数据库升级时，对缺少预览索引的旧画布执行一次性、幂等回填。回填只读取节点载荷并生成独立索引，不改写节点内容。

图片来源优先级为：

1. `thumbnailSrc` / `thumbnailUrl` / `previewUrl`
2. 已保存的画廊或图组缩略图
3. `savedUrl`
4. 原图地址，仅作为后台生成缩略图的输入

列表卡片优先使用 `board.previewImages`，仅对未迁移的内存旧数据保留 `board.nodes` 兼容回退。只有真正没有任何图片节点的画布才显示纯文字占位。

## 运行时一致性

- 画布视口响应增加引擎版本字段。
- 前端资源与数据库 Worker 版本不一致时，不继续渲染旧 LOD 结果，而是显示明确的本地服务重启提示。
- 本次上线完成后必须重启 3099 端口的项目 Node 进程，并通过实时接口确认 94 节点的“苹果”在 11% 不返回聚合方框。

## 错误和降级策略

- 单个缩略图加载失败时，节点仍保持原有结构与背景，不改成新的摘要卡。
- 场景精灵资源未就绪时，继续显示上一帧有效内容，新内容就绪后原子替换。
- 预览回填失败不阻止画布打开；错误可重试，且不修改原节点。
- 任何表示层替换失败时保留当前可见层，不先清空再加载。

## 性能边界

- 单画布 5 万混合节点和 10 万连接继续作为保证目标，逻辑上不设总节点硬上限。
- 完整 DOM 节点不超过 800。
- 场景层只绘制屏幕内实际可见精灵，使用遮挡剔除、纹理缓存和帧时间预算。
- 拖动、缩放和平移期间不加载原图；高清资源只在停止交互并进入可辨尺寸后加载。
- 保持已有性能验收约束：平移 P95 不高于 20ms，最长交互任务不高于 100ms，内存稳态增长不高于 15%。

## 验收标准

### 视觉连续性

- 对“苹果”、“画布 17”、NILLKIN 以及其他非空历史画布，在 5%、11%、25%、55%、64%、65%、74%、100% 和 160% 依次缩放。
- 候选节点不超过 800 时，DOM 中必须是完整节点，摘要节点数和聚合区域数必须为 0。
- 屏幕截图差异必须只体现缩放和位移，不出现新的标签、区域方框、空白节点或突然显示。
- 超过 800 候选节点时，场景层不得绘制“×个节点”聚合卡，而必须保持单节点几何和遮挡结果。

### 历史缩略图

- 所有含图片的画布列表元数据都包含 1–4 个 `previewImages`。
- “测试2”、“苹果”、“画布 17”、NILLKIN 和“画布 41”的选择卡均能显示实际图片预览，而不是标题占位。
- 不因列表打开而读取整张画布或请求原尺寸图片。

### 数据与回归

- 旧画布升级前后节点数、连接数、视口、未知字段和资源引用完全一致。
- 完成 5 万节点浏览器回归和 3 分钟耐久测试，测试画布在结束后自动删除。
- 重启实际 3099 服务后再次检查实时接口与真实画布 UI，不仅检查测试副本。

## 非目标

- 不重新设计节点视觉。
- 不为低缩放新增类型卡、状态卡或聚合计数卡。
- 不改变现有高缩放图片细节、编辑器和节点业务逻辑。
- 不删除或重置用户的旧画布。
