# 统一素材节点与混合素材合集设计

## 目标

把画布中的导入图片、导入视频、导入音频、图片结果图集和视频输出统一到一个「素材」入口与一套素材记录中。用户从菜单创建「素材」节点后，可以上传任意支持的图片、视频或音频；生成器产生的图片、视频和音频结果也能进入素材合集。合集按生成/导入时间倒序混排，每项显示媒体类型标识，并保留对应的预览、播放、下载和连接能力。

本次不删除或破坏旧节点。已保存的 `image`、`video`、`audio`、`gallery-container`、`video-output` 继续按原格式恢复；新入口和新结果使用统一素材节点。旧节点的结果不自动跨节点搬迁，避免用户现有连线和历史被悄悄改变。

## 交互与节点模型

### 统一入口

画布添加菜单的「添加卡片」区只显示一个「素材」按钮，替代三个导入按钮；「工具与输出」区用「素材合集」替代结果图集和视频输出。旧菜单数据值不再创建新节点，但保留连接菜单和历史恢复兼容。

「素材」节点支持两种呈现状态：

- 空状态：显示上传区域，可选择或拖入图片、视频、音频；文件类型由 MIME 类型识别，无法识别或不支持的文件明确提示。
- 有内容状态：显示单项预览和类型标签。上传第二个文件或接收生成结果时自动转为混排合集，不改变节点 ID 或已有连接。

「素材合集」节点与素材节点使用同一 `asset-collection` kind 和同一持久化结构。区别只在创建时的标题和是否等待输入；内容一律按 `createdAt` 倒序显示，时间相同按插入序号稳定排序。

每个素材成员结构为：

```js
{
  id: "stable-member-id",
  kind: "image" | "video" | "audio",
  name: "显示名称",
  src: "预览或播放地址",
  savedUrl: "下载地址",
  mimeType: "image/png",
  createdAt: "2026-09-23T00:00:00.000Z",
  duration: 0,
  source: "upload" | "generation" | "output",
  sourceNodeId: "optional-node-id",
  promptSummary: "optional-short-description"
}
```

图片使用缩略图和图片预览，视频使用静音视频缩略图并支持播放，音频显示音频图标、名称、时长和播放控件。所有成员显示类型徽标；没有有效地址的成员显示「等待素材」或失败原因，不伪造预览。

## 数据与兼容

新增 `asset-collection` 节点序列化字段：

```js
assetCollection: {
  title: "素材合集",
  mode: "single" | "collection",
  members: [],
  activeMemberId: ""
}
```

成员不复制媒体字节，只保存现有资源机制可访问的地址和元信息。现有 `gallery-container` 仍保持图片成员合同；新混排节点不得复用只接受图片的字段名作为视频或音频的隐式标识。

节点输出统一为 `type: "assets"`，携带 `assets` 数组；单项仍可通过 `kind` 识别。连接兼容性按成员类型判断：图片生成节点可接受图片素材，视频生成节点可接受图片/视频/音频参考，音频输入只连接到支持音频的节点。不能因为目标节点只支持一种媒体而静默丢弃其他成员。

新生成结果写入规则：

- 图片生成结果写入连接的 `asset-collection`；不存在时在生成节点右侧创建一个「素材合集」并连接。
- 视频生成结果写入连接的 `asset-collection`；不存在时创建同样的混排合集，不再创建新的 `video-output`。
- 以后接入音频生成结果沿用同一写入函数。
- 旧的 `video-output` 仍可显示和保存自己的视频历史，但不再作为新入口创建。

同一 `sourceNodeId + savedUrl/src` 不重复写入。成员按时间重排，但保持稳定 ID；选中成员仅影响预览，不改变生成节点结果。

## 代码边界

- 新建 `canvas-asset-collection-rules.js`：纯函数定义成员规范化、类型识别、去重、稳定排序和输出合同。
- 修改 `script.js`：菜单入口、素材文件选择、`asset-collection` 渲染、序列化/恢复、生成结果写入和连接输出。
- 修改 `styles.css`：素材单项、混排网格、类型徽标、视频/音频控件和空状态。
- 新建 `tools/check-canvas-asset-collection.js`：不依赖浏览器的规则与序列化检查。
- 在现有全量检查命令中加入该检查。

不在本次范围内：删除旧节点类型、自动迁移用户已有图集、重写已有视频历史、把所有普通图片节点强制替换成素材节点、改变模型参数或生成协议。

## 验收

- 菜单只显示「素材」和「素材合集」，不再显示三个导入项、结果图集和视频输出的新建入口。
- 上传 PNG、MP4、MP3 后均进入同一个素材节点，类型徽标、预览/播放和下载行为正确。
- 图片、视频结果写入同一个素材合集后按时间混排，刷新或关闭重开画布后顺序、类型和媒体地址不丢失。
- 相同结果重复回传不会产生重复成员；生成任务晚到仍只写入所属素材合集。
- 图片生成节点可以读取图片成员；视频生成节点可以读取图片、视频和音频成员；不支持的连接明确拒绝。
- 旧 `gallery-container` 和 `video-output` 数据仍能恢复；现有图片生成、视频生成、连接和保存流程没有回归。
