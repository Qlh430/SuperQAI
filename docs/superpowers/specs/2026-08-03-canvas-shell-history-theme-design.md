# 画布首屏与历史画布状态设计

## 目标

消除网站加载时在线生图界面的短暂闪现，区分“尚未打开画布”和“已进入画布”两种状态，并让历史画布面板在深色模式及所有配色主题下清晰、统一、可交互。

## 已确认原因

- `index.html` 将在线生图同时标记为活动导航和活动视图；画布脚本在文档末尾执行后才反向切换到画布，因此脚本下载或执行前会先绘制在线生图。
- 画布结构中的 `.canvas-origin` 始终可见，没有与 `canvasState.activeBoardId` 绑定，所以尚未新建或打开画布时也会显示“把图片和想法放到这里”。
- 从起始层打开历史画布前会先执行 `dismissCanvasStartGate()`；关闭历史面板只隐藏弹窗，不恢复之前的起始状态，于是用户看到一个没有活动画布却像新画布的界面。
- 历史画布面板仍使用 `#fff`、`#111827`、`#8a93a3` 等固定颜色以及文本/Emoji 图标，覆盖了全局主题变量，也没有完整的 hover 与 `:focus-visible` 反馈。

## 方案

采用方案 A：在现有原生 HTML、CSS、JavaScript 架构内增加明确的画布界面状态，不做大规模状态管理重构。

### 首屏状态

- 移除 HTML 中在线生图导航和视图的初始 `active` 标记，使浏览器首次绘制时不再显示错误工具。
- 画布脚本建立画布结构后同步激活画布；不依赖异步请求完成后再切换。
- 保留无 JavaScript 时的基础页面结构，不新增全屏加载动画。

### 画布进入状态

- 用一个集中函数根据 `canvasState.activeBoardId` 更新画布工作区状态。
- 默认落地页没有活动画布：不显示 `.canvas-origin`。
- 新建画布或打开历史画布后进入活动画布状态；空画布可以显示 `.canvas-origin`，有节点后继续由现有样式隐藏。
- 历史面板记录打开前是否处于起始落地页。点击关闭时只关闭面板并恢复此前状态，不创建、保存或自动选择任何画布。
- 从历史列表选择画布仍按现有逻辑恢复该画布并关闭面板。

### 历史画布视觉与交互

- 标题、说明、计数、搜索框、卡片、节点徽标、日期、边框和背景统一使用 `--panel`、`--field`、`--ink`、`--muted`、`--line-strong`、`--accent`、`--accent-soft`、`--accent-contrast` 等主题变量。
- 刷新、回收站、新建、关闭按钮改为 Lucide 图标加可访问标签；“新建画布”保留文字。
- 工具按钮具有一致的默认、hover、active 和 `:focus-visible` 状态；当前配色的 `--accent` 负责强调，不写死黄色或蓝色。
- 历史卡片在 hover 与键盘焦点时提升边框和背景对比；活动画布使用主题强调色，不使用固定深灰描边。
- 深色模式下文字对比度以 `--ink` 和 `--muted` 为准，卡片不再显示白底。

## 边界

- 不改变画布数据接口、保存格式、历史排序、搜索、回收站和删除语义。
- 不自动恢复最近画布，也不在关闭历史面板时新建画布。
- 不重构其他工具弹窗；首屏仅修正当前画布优先外壳的初始活动状态。
- 保留用户现有的无关工作区改动，不批量格式化文件。

## 验证

- 静态回归检查确认在线生图在 HTML 中不再初始激活，画布初始化仍同步激活画布。
- 静态回归检查确认 `.canvas-origin` 由活动画布状态控制，关闭历史面板不会调用新建画布路径。
- 静态回归检查确认历史工具按钮使用 Lucide 图标、可访问标签、主题变量和 hover/focus 状态。
- 浏览器验证刷新时不出现在线生图闪帧；默认落地页不显示 `.canvas-origin`；新建或打开画布后显示正确；关闭历史面板不产生新画布。
- 深色模式和至少两种配色主题下检查标题、卡片、日期、按钮、搜索框与回收站状态的可读性。
- 运行项目完整检查、JavaScript 语法检查和 `git diff --check`。
