# 固定前端开发工作台实施计划

目标：在不修改当前/稳定候选、不另起真实数据后端的前提下，复用已有 stage 与组件部署，实现构建后刷新验收。用户已批准前次评估中的最小方案。

最小架构：Vite 现有代理能力提供 127.0.0.1:33200 开发入口。有限前端资源从固定 stage 读取；其他请求（包括登录、API、媒体、WebSocket）转发原 AI OS 服务。浏览器顶层仍加载完整宿主页，保留同源 Neon iframe 与画布桥接。Electron 原生托盘/更新接口继续在原应用使用，不仿造原生接口。代理不加载服务端业务模块、不打开数据库。

实施范围：新增 workbench-frontend 组件白名单（构建 JS、CSS、host bridge）；固定开发路径及无链接保护；Vite 的独立 daily 模式；快捷入口和操作说明。既有组件部署与按变化文件备份继续复用，不复制完整运行时。原 Vite dev 模式保留。

- [x] 先写小型夹具测试，验证白名单含 CSS、缓存入口更新、硬链接/联接拒绝、固定路径保护、静态资源刷新和后端代理的会话/媒体/SSE行为。
- [x] 最小实现并通过专项及现有组件部署回归（19 项）。
- [x] build 后只通过 deploy.mjs 更新固定 stage；实际构建与 stage 已一致，changed=[]、backupDir=null；夹具验证变化更新及再次无变化不备份。
- [x] 启动仅前端的开发入口，完成 acceptance.cjs 四宽度模拟 API 验收和只读真实服务连接检查；不复制数据或运行第二套业务后端。
- [x] 核验当前/稳定候选、指针及原始入口未改；报告浏览器入口的原生功能边界，写清日常操作与 Git 检查点。

风险边界：浏览器与 Electron 的登录会话存储独立，需要在开发入口正常登录；账户仍由原后端验证。业务请求使用真实数据，用户验收前应保存正在编辑的内容，避免两个页面同时编辑同一画布。真实登录/生成由用户已有会话验收，不伪造通过。
